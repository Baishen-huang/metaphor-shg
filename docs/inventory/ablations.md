> 哪些结论是「条件化」而非「成立」，以及**每个失败背后的机制**是什么。

> **裁决四档**（严格区分）：
> - `成立`：预期方向与幅度均被实测支持；
> - `证伪`：预期被实测否定，且给出了否定机制；
> - `条件化`：只在特定口径/子集下成立，另一口径下不成立（**不等于证伪**）；
> - `中性`：实测无可测效应（效应在噪声内或结构性恒为 0），既未证实也未证伪；

### A1 / H1 —— 类型安全约束对字面误判率零贡献

- **假设**：超边 + 类型安全约束可使字面误判率降至 <15%（方案 §4.1.3 称之为「设计假设」，并设为 Go/No-Go）。
- **实测**：
  ```
  A1 完整系统（类型检查开）   召回 0.696  P1 0.092  精确 0.990  F1 0.818  | 本体非法框架 0
  A1 去掉全部类型检查        召回 0.696  P1 0.092  精确 0.990  F1 0.818  | 枚举拦 0 + 连贯性拦 24
  ```
  关闭的是**全部**类型检查：枚举约束 `type_valid` + 类型连贯性检查 `_type_coherent`（`ablation.py:136-152`）。
- **裁决**：**证伪**。约束的因果贡献恰为 0（P1 位移 0.000）。目标值 9.2% 本身达标，但达标来自 refine + 阈值，不来自约束。
- **机制（三层，逐层加深）**：
  1. **枚举约束拦 0 个**：本体在构建时已保证所有 `(source_type, mapping_type)` 合法；且 LLM 自举出的框架 **98.6%** 是 `GENERIC_VEHICLE → GENERIC_VEHICLE_MAP`（无条件合法）。约束面对的是一个**它永远无法拒绝的输入分布**。
  2. **连贯性检查拦下 24 个候选，但候选并未被丢弃**：`_type_coherent` 拒绝的是**绑定**（binding），被拒候选退化为临时框架 `F_LLM_*` 后**照样产出超边**。P1 的判据是 `pred = bool(edges)`（`evaluate_real.py:78`），所以边还在，P1 不动。
  3. **要让它影响 P1 就必须丢弃候选，而那等于关掉开放发现**（开放发现贡献 **+55.8pp** 召回）。**二难闭合，没有第三条路**——`exp/degrade` 随后专门检验了「不丢弃、改为软降权」这条中间路线，也被证伪（见 N4）。
  - 附带：为让约束真正有信息，曾做过两项改造——给自举框架推断真实 `source_type`（`GENERIC_VEHICLE` 占比 98.6% → 32.8%）+ 新增连贯性检查。**改造后 P1 依然纹丝不动**，这排除了「没接上」的解释。
- **代码位置**：`metaphor_graph/ablation.py:98-160`（`run_a1`）；复现 `python -m metaphor_graph.ablation`。独立复核：`.wt/degrade/experiments/eval_degraded.py` §2。
- **论文**：§7 第 1 行。结论表述为「约束管结构正确性（挂哪个框架），不管精度（要不要这条边）」。

### A2 / H2 —— 查表降本定性成立，但「~20 次/千边」从未被测量

- **假设**：每 1000 条 L1 超边的 LLM 调用从 ~200 次降至 ~20 次。
- **实测**（`ablation.run_a2`，只数「需聚类的框架占比」，不真调 LLM）：
  ```
  需聚类框架占比 34.0%；查表 363 个零调用，聚类需 187 次调用
  ```
- **裁决**：**成立（定性）**。「10×」量级差可复现（187 vs ~20）。但**分母不对**：「187」是**1100 句测试集上需聚类的框架数**，不是「每千边」；`~20` 从未被任何脚本测量。
- **机制**：
  - `builder.py:140-143` 的 `_llm_cluster_fallback` 前置条件是 `not e.frame_id`；**实测生产产出中无 `frame_id` 的边 = 0 条**（本次复核：110 文档 1097 条边中 0 条无 frame_id）→ **该函数是死代码**，它承诺的「~20 次/千边」实际由查表（零调用）完成。
  - 因此真实成本是 **0 次/千边（本体查表）+ 265/1097 = 24.2% 的边挂在未登记框架上但同样零调用**。成本主张成立，但机制描述与代码不符。
- **代码位置**：`metaphor_graph/ablation.py:163-191`；`metaphor_graph/builder.py:140-143`、`:245-247`。
- **论文**：§7 第 2 行。数字来源见 §6.2。

### A3 —— 三通道消融：refine 才是精度防线

### A6 —— 通用常识不可替代专属隐喻知识（但两处口径缺陷）

- **实测**：
  ```
  常识通路（AI 生成关联）  Recall@10=0.095  Hits@3=0.097  (n=652)
  隐喻通路（语义超图）     Recall@10=0.783（top_k=5）/ 1.000（top_k=20）
  ```
  本次复核（main，默认 `top_k=20`）复现 1.000；`--meta-top-k 5` 复现 0.829。
- **裁决**：**成立**，且**修正预算后结论加强**（8.2× → 10.5×）。
- **机制**：
  - 常识通路失败的真实原因不是「知识少」，而是**跨域映射不是常识关联**：常识邻居是**近义/相关**（「人生」→ 人生相关词），而隐喻通路沿 `EVENT_IS_PERFORMANCE` 级联命中「舞台/演员」。常识通路的入口受限（概念词命中 390/652 = 0.598）且邻居匹配是**字面匹配**，跨域天然失效。
  - **两处口径缺陷**（均已在论文修正块披露）：① 预算不对等（常识臂无上限 vs 隐喻臂 `top_k=5`，低估 17pp）；② 隐喻臂的 1.000 是**平凡饱和**（池 ≤10，Recall@10 对任何返回全候选的排序器恒为 1.0）。
  - **为什么饱和不影响结论**：A6 的证据结构是**相对比较**——两臂面对同一金标、同一查询集、同一池。饱和同时抬高两臂的上界，但常识臂的 0.095 是**真实低值**（受概念词命中率限制），故 10.5× 的差距仍然成立。
- **代码位置**：`metaphor_graph/evaluate_a6.py`（`--meta-top-k` 默认 20）；`experiments/A6预算对等修正.md`。
- **论文**：§7 第 6 行 + §6.4 修正块 + §4.1 表。

### A7 / H5 —— 「训练增益」的三次翻案与最终归因（见 §3 链条 C2）

- **实测（三个口径，三个答案）**：

  | fullcorpus（gen3 归因后） | 0.9948（`type`=0） | 0.9977 | **+0.29pp** | 增益≈0 |

- **裁决**：**条件化 → 最终证伪**（原「训练增益」是权重错配 + 锚定的产物）。
- **机制（这是全项目最完整的一条机制链）**：
  1. **自监督天花板**：训练正样本 = 「该 chunk 实际抽出的边」，评测金标 = 「该 chunk 产出的边被 LLM 判相关」——**同一个 chunk**。于是 `clue`（触发词命中）在训练集上 AUC ≈ **0.9985**，模型退化为只学 `clue`（权重 +1.2543，其余≈0）。这是**训练目标与评测目标重合**，不是泄漏检测能抓的。

### A8 / H6 —— 自适应阈值中性：且是**结构性恒等**

- **实测**：

- **裁决**：**中性**。
- **机制（本次复核新增，比原报告的「小语料测不出」更深一层）**：
  - `AdaptiveThreshold.select`（`context_budget.py:80-113`）只有两条生效路径：**降阈值**（当选中数 < `min_keep=50`）与**高密度截断**（当 `regime == "high"`）。

### A9 / H7 —— 角色特征零贡献

- **实测**：去 `same_frame`/`same_cascade`/`ground_jaccard` 后 MRR **完全不变**：诊疗集 0.906→0.906、fullcorpus 0.998→0.998、真实向量 0.999→0.999。

### N1–N3 / N14–N19 —— 查询侧可观测性：三代连续证伪（见 §3 链条 C3）

- **N1（Ω 无额外信息量）**：

### N7–N10 —— HGNN 源项 / 动力学

- **N7（源项不打破平局）**：18 个 (α,ε) 配置下 \|ΔAUC\| ≤ **0.0047**；95% CI 基本跨 0（2/18 轻微排除 0，方向偏 flat）；逐对 McNemar p 恒 **1.000**（α=1 时 flat 与 hgnn 判对模式**完全相同**，b=c=0）。
  - 裁决：**证伪**（原假设「平局是算子退化造成的」不成立）。
  - **两条独立证据**：
    1. **退化是渐近命题，H4 工作在 `layers=2`**：同分量余弦 layers=1 → **0.188**、layers=2 → **0.388**、layers=500 → **1.000000**；源信息保留 layers=2 时 **0.840**。逐层分量内 AUC：α=1.0 从 layers=2 的 **0.7075** 单调掉到 layers=500 的 **0.5413**（趋近纯指示器）——**退化是真的，但不在 H4 的工作点**。
    2. **完美同分量指示器达不到 0.950**（决定性）：该配对样本上正样本 20（全部同分量）、负样本 752（其中 150 同分量）→ **完美指示器准确率上限 = (20+602)/772 = 0.8057 < 0.950**。这一条单独就足以排除退化解释。

### B1–B11 —— 基准与口径类（详见各块）

- **B1（构造锚定）**：**机制**：`evaluate_llmgold` 的查询由金标边的触发词改写而来，金标由 LLM 在**同一伪文档的候选**上判定。LLM 的作用是**过滤**（剔掉 3.2% 不认可的），**不是去锚**。任务实质 = 「把产出这条边/这个 chunk 排到第一」。IR 文献对应 **pooling bias**。
  - **决定性证据**：MRR 分解显示训练增益 **+6.44pp 全部落在「产出 chunk」列**，非产出列 **−0.64pp**。
- **B2（候选池饱和）**：**机制**：池按伪文档切分（K=10 句）→ 池 = 该伪文档的**不同候选 chunk 数**。本次复核实测：**min=5 / median=8 / max=10，100% ≤10**（110 个伪文档）。于是 **Hits@10 对任何返回全候选的排序器恒为 1.0**；池=7 时随机排序的 MRR 期望即达 **0.37**（`H_7/7 = 0.3704`），指标量程被吃掉一半以上。IR 文献对应 **test collection 规模不足**。
- **B3（权重错配）**：**机制**：训练器在**标准化空间**工作，只有 `w/sd` 才是「每变动一个原始单位，logit 变动多少」，才与人工权重可比。实测错配：`struct` 0.250 vs 应为 0.005（**49×**）、`type` 0.200 vs 0.011（**19×**）、`ground_jaccard`/`same_frame`/`same_cascade` 人工 0 vs 应为 0.101/0.045/0.045。**注意 `struct` 比 `type` 错得更离谱，而前两代都把注意力放在 `type` 上。**
- **B4（A6 预算不对等）**：**机制**：常识通路是全池扫描（无上限），隐喻通路硬编码 `rank_mappings(..., top_k=5)`。修正为 `top_k=20` 后 0.8287 → **1.0000**（`top_k=20` 已与无上限等价）。**这是一类系统性问题的第三例**（前两例：§6.1 池饱和、§6.2 权重错配+锚定）。已新增机器检查 `metaphor_graph/audit_fairness.py`。
- **B5–B8（修复后基准）**：见 §1.5 表。
- **B9（P2 覆盖率注水）**：**机制**：报出的 100% 由两种不同性质的归属混合而成——本体正式登记框架 + 抽取器为未知喻体**临时建的回退框架**（靠 `builder._ensure_cascades` 按目标域事后补的 `C_ADHOC_*` 级联才够到 100%）。**两个口径度量不同的问题**：前者是「每条边是否都有层级归属」，后者是「层级归属是否来自本体」。实现见 `health.graph_health(ontology=...)`，**不传 `ontology` 时字段为 `None`，历史口径逐位不变**。
  - **归因修正**（gen2 更精确）：**100% 由兜底函数产生，不由本体级联保证**。关掉 `_ensure_cascades` → **0.767**；本体级联查表单独贡献 0.767，兜底贡献剩下的 0.233。成本主张不受影响（两者都是查表式、零 LLM 调用）。
  - **口径数字差异**：degrade 报 **77.6%**（1100 句 / 883 边），论文 §5.2 报 **82.4%**（120 句 / 108 边）。两者都是「本体登记框架」口径，**差在语料规模**——见 §6.5。
- **B10（三通路绝对数字下修）**：见 §6.6。
- **B11（静默回落陷阱）**：**机制**：`evaluate_real.build_llm_backend()` 在无 `LLM_API_KEY` 时回落到 `LocalHeuristicBackend`，而它**不实现 `discover_batch`/`batch_refine`** → 调用方传的 `--llm-cache` **根本不被消费**，却仍打印一份看似正常的指标。**这类「看起来跑通了」的错误比崩溃危险得多**，故已加显式告警（`evaluate_real.py:48-58`）。正确做法是用 `PrecomputedBackend` 重放（P1 = 0.092）。

### N23–N30 —— 组件级、生成层与工程负面结果

- **N23（HGNN 从检索路径移除）**：**决定性证据是代码审计而非指标**：检索评分路径 `_pair_features` → `extract_features(qe, mapping, self._centrality)`，其中 `centrality = 0.5·len(ground) + 0.5·[cascade_id 非空]`——**完全不依赖 HGNN**。全仓 hgnn 的引用只有三处：`__init__.py`（导出）、`evaluate_hgnn.py`（评测）、`evaluate_chain_quality.py`（可选 coherence 过滤，默认关闭）。**即 HGNN 从未参与检索打分**——这才是「flat ≡ HGNN」的最终解释。裁决：**从检索路径移除**（保留为可选分析工具）。
- **N24（弱监督修好病理但指标不动）**：用 refine 缓存里 **1172 条被 LLM 否决的候选**作负样本 → `clue` 平均 AUC **1.000 → 0.931**、leakage 标记 **136 → 23**，但 **MRR 0.998 不动**。**机制**：by-construction 基准本身已饱和（四种配置全在 0.995–0.998），它**测不出**排序增益。要证明弱监督排序器的价值必须先有非构造金标。
- **N25（自举触发词 train→test 泛化差）**：召回涨 **4.5 倍**（7.6% → 34.4%），误判同步涨 **4 倍**（7.9% → 32.9%）；收紧到 P1 达标时召回只剩 10~12%。**关键对照**：「自举本体但清空触发词」与基线**完全一致**（7.6% / 7.9%）⇒ **框架本身是中性的**，召回与误判全部来自触发词。**结论：自举的价值在结构（框架/级联 → 覆盖率），不在触发词。**
- **N26（LLM-as-judge 模型敏感性）**：同一查询集、同一生成模型、4 种打包变体：**deepseek judge 判纯向量对照 6:1 胜**，**glm judge 判当前打包最优**（26.50 vs 21.12，最优率 50%）——**结论随 judge 模型反转**。方法论结论：一切生成质量主张必须由真人评估仲裁。
  - 附带发现的缺陷：`evaluate_packing_ablation.py` 在写缓存时有 `NameError: name 'cache_file' is not defined`（`data/packing_ablation_glm47.log`），**跨模型复跑目前是崩溃的**。
- **N27（文本级/图结构级过滤信号无效）**：扩展链过滤的三方消融（同一候选集、同一 judge）：
  | 过滤信号 | 保留链 | 精度 |
  |---|---|---|
  | 无过滤（基线） | 52 | 16.7% |
  | 文本级：触发词跨段复现/喻底交集≥2 | 49 | **不变** |
  | 图结构：`metaphor_coherence` 阈值 0.5（L1-only 图） | 52（中位连贯度 **0.820**） | **不变** |
  | **LLM 语境级语义校验** | **11** | **63.6%** |
  - **机制**：候选链的域对本就通过自身框架相连，抽象域标签的图连贯度对「词化惯用语 vs 真隐喻」不敏感；文本级信号同样区分不了。**判别信息在语境级语义中**——这为「结构化管线中哪些环节必须引入语言模型」提供了一个可测量的判据实例。
- **N28（外部基准不适用）**：MiQA（AACL 2022）是**二选一推理任务**，ANALOGICAL（Findings of ACL 2023）是**长文本类比评测**——**两者都不是检索基准，不提供「查询→相关文档」的金标**。文献检索当初的「可借用查询来源」判断有误，此处更正。
- **N29（合并引入的 3 处回归）**：`score_conditions` 无条件加 legacy 臂 → `evaluate_fullcorpus` KeyError 崩溃（`.wt/repair/experiments/fullcorpus_after_repair.log` 有完整 traceback）；冲突解决遗漏 argparse 定义 → `evaluate_hgnn` AttributeError；多处 auto-merge 冲突标记未清 → 语法错误。**教训：222 项单测全绿不足以保证合并正确**——单测不覆盖 CLI 入口与 `evaluate_fullcorpus` 等脚本。
- **N30（`experiments/REPORT_exp-typefeat.md` 缺失）**：`experiments/REPORT.md` 索引指向该文件，但文件不存在（gen3 的 typefeat 报告未从分支复制到 main）。内容可从 `experiments/gen3/REPORT.md`（HEAD 段，行 1–633）获取。

## 3. 「证伪链条」——需要多次实验才settle的假设

> 项目里有若干负面结果不是一次实验定案的，而是「提出 → 部分证伪 → 翻案 → 再证伪」的多轮链条。
> 这些链条本身是本项目最有价值的方法论产出。

### 链条 C1 —— 「GRU 打平 HGNN」：从「算子退化」到「该层从未被调用」

| 轮次 | 假设 | 实测 | 裁决 |
|---|---|---|---|
| gen0（原报告） | HGNN 跨层传播与 flat/GRU 打平（0.950 vs 1.000） | 平局 | 「聚合方式次要」（诚实负面） |
| **gen1 `exp/dynamics`** | **我提出**：`M=½(I+S)` 无源项 → 迭代收敛到连通分量平稳分布 → `metaphor_coherence` 退化为同分量指示器 → 这才是平局的原因 | 退化只在**渐近**意义成立（500 层同分量余弦 1.000000），而 H4 工作在 **layers=2**（余弦仅 0.388）；**完美同分量指示器准确率上限 16/20 = 0.8000 < 实测 0.950** | ❌ **证伪**（退化解释不了 0.950） |
| gen1 追加 | 加源项应能打破平局 | 18 个 (α,ε) 配置 \|ΔAUC\| ≤ 0.0047，CI 跨 0；源项只在 layers ≥ 50 有意义 | ❌ **证伪**（源项不是原因） |
| gen2 `exp/cascade` | 也许是级联构造质量差 | H4 在 json/source/source_type 三规则下**逐位相同**（0.960/0.960） | ❌ 与级联无关 |
| **gen4 `exp/repair`（代码审计）** | — | **检索评分路径从不调用 HGNN**：`_pair_features` 只用 `centrality = 0.5·len(ground) + 0.5·[cascade_id 非空]` | ✅ **最终解释**：平局是因为**该层本就不提供检索所需的信息**（因为它根本没被调用） |

**教训**：连续三轮用「指标实验」试图解释一个平局，而答案是**代码审计**给出的。
「加源项 → 看指标」这条路径永远走不通，因为指标不经过该算子。

### 链条 C2 —— A7/H5「训练增益」的三次翻案

| 轮次 | 口径 | 结果 | 结论字符串 |
|---|---|---|---|
| gen0（诊疗集） | 2 文档 8 查询 | 训练 0.906 < 人工 **1.000**（−0.094） | 「H5 不成立❌」 |
| gen0（fullcorpus） | 池=7，n=861 | 训练 0.998 vs 人工 0.995（**+0.003**） | 「H5 不成立❌」（贴天花板） |
| gen0（llmgold） | 改写型查询 n=632 | 训练 0.547 vs 人工 0.502（**+4.5pp**） | 「H5 **条件化**成立」 |
| **gen1 `exp/source`** | 修 `type` 特征双路径不一致后重跑 fullcorpus | **+9.5pp** | 「H5 成立✅」（标记「需人工复核的重大结论变更」） |
| **gen3 `exp/typefeat`** | 拆解这 +9.5pp 的来源 | **+9.18pp 全部来自「人工加权硬编码 0.20」这一项**；训练侧去 `type` 的效应**恰为 +0.00pp**；真实增量 **+0.29pp** | 「翻转是真的，但**归因是错的**」 |
| gen3（零假设对照） | 人工权重按学到比例重配 | 人工 **0.5496 反超**训练后 0.5447；训练增益降为 **+0.49pp**（CI 覆盖 0）；**1 维 `sem` = 7 维训练后** | 「训练增益 ≈ 0」 |
| **gen4 `exp/repair`** | 全局池 + 去锚定 | anchored +0.005 → **deanchor −0.0119**；真实向量 deanchor **−0.126** | 「训练器学的是**复现构造锚点**」 |

**最终裁决**：原「训练增益 +4.5pp / +6.4pp / +9.5pp」**主要是人工权重错配 + 构造锚定的产物**；
去锚定后一致为负。**链条的每一环都改变了结论，且每一环都改变了下一环的提问方式。**

### 链条 C3 —— 查询侧可观测性：三代连续证伪

| 代 | 分支 | 假设 | 裁决 |
|---|---|---|---|
| gen1 | `exp/omega` | 实现 Ω，检验「低 Ω 预测级联通路 0.042 失效」 | ❌ Ω 退化为 1-bit 触发词指示器（ρ=0.9949）；且「Ω=0 ⟹ 通路空」是**定理** |
| gen2 | `exp/cascade` | 换级联构造使 Ω_N 复活（Ω_N 从 1.4% → 14.8%），Ω 应获得信息 | ❌ Ω 仍是 1-bit（ρ=0.9954，一致率 1.0000）。但**发现 `n_emergent` 分层 AUC 0.836** |

**量化了不变式的代价**（只读查询 0.65 vs 读图 1.0000）、并给出了本代唯一正面发现：
**查询侧激活结构确实与候选侧存在统计关联（targeting excess 1.73–1.78×），但该关联是多维分布式的，无法标量化。**

### 链条 C4 —— 「0.950 的 HGNN 判别信号来自哪里」

| 轮次 | 检验 | 结果 |
|---|---|---|
| gen0 | 原口径「HGNN→GRU → 抽取 F1 下降 >3pp」 | **无法成立**：HGNN 是检索/语义信号编码器，CCL2018 是逐句金标且**无逐边金标**，无法训练/评测逐边检测器 |
| gen0（改口径） | 分解判别信号来源 | HGNN 0.950 = flat 0.950 > raw **0.150**；GRU **1.000** |
| gen0（真实向量） | 换真实句向量 | HGNN 0.850 = flat 0.850；raw 0.650 |
| **gen1 `exp/dynamics`** | ① raw=0.150 是并列口径产物（AUC 实际 0.5500）；② n=20 功效不足（结论字符串会翻转） | 两条方法学修正 |
| gen2 `exp/cascade` | 换本体（种子 32 框架 → 生产 2209 框架） | GRU **1.000 → 0.880**、raw 0.150 → 0.120 —— **本体替换效应**，说明原 GRU 行只在 20 配对、种子本体下成立 |
| gen4 | 代码审计 | HGNN 从未参与检索打分 |

**最终结论**：「隐喻连贯度校验信号来自 n 元喻底共现，而非层级传播」**在两种向量器、四条级联规则、
两种本体下均成立**，是项目里**最稳健的负面结论**；但它同时暴露了一个脆弱性——
**该行的绝对数字（GRU=1.000）对本体规模敏感**，样本量极小（20–25 配对），应视为指示性而非结论性。
