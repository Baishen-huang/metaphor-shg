## 2. 常识通路的检索机制

代码位置：`metaphor_graph/evaluate_a6.py:196-238`（`main` 的 ① 段）。

### 2.1 精确流程（四步）

```
① 概念词命中（入口）
   hit_terms = [t for t in neighbors if len(t) >= 2 and t in q["question"]]
   · 遍历全部 987 个键；条件是「键作为子串出现在改写查询里」
   · 无分词、无归一化、无同义扩展 —— 纯字面子串
   · 守卫 len(t) >= 2 排除 54 个单字键
   · 命中则 term_hit += 1（仅用于统计入口命中率）

② 邻居池并集
   pool = set()
   for t in hit_terms: pool |= set(neighbors.get(t, []))
   · 多个命中词的邻居取并集（不去重语义，只做集合去重）

③ chunk 字面匹配打分
   for i, c in enumerate(chunk_texts):
       sc = sum(1 for n in pool if n and n in c)
       if sc: cand[f"{did}_c{i}"] += float(sc)
   · sc = 邻居池中**作为子串出现在该 chunk 里**的成员个数
   · sc == 0 的 chunk 不进入候选集（cand 里没有它）
   · **全池扫描：候选池 = 该文档全部 10 个 chunk，无 top_k 上限**

④ 排序
   cs_ranked = [c for c, _ in sorted(cand.items(), key=lambda x: -x[1])]
   · 按分数降序；Python sort 稳定 → **并列时按 chunk 序号（字典插入序）**
   · 取前 10 计 Recall@10，前 3 计 Hits@3
```

**打分公式**（原文，`evaluate_a6.py:210`）：

```python
sc = sum(1 for n in pool if n and n in c)
```

即「邻居池 × chunk」的**字面共现计数**，无 IDF、无长度归一、无关系类型权重。

### 2.2 对照的隐喻臂（② 段，`evaluate_a6.py:221-228`）

```python
eng = engines[did]
ranked, _dec = eng.rank_mappings(q["question"], top_k=args.meta_top_k, adaptive=False)
meta_ranked = []
for m in ranked:
    for s in m.chunk_spans:
        if s.chunk_id not in meta_ranked:
            meta_ranked.append(s.chunk_id)
```

`rank_mappings` 走 `metaphor_retriever_score`（`retrieval.py:314-331`），
对全部 live 边打分后取 top_k，再展开为 chunk 序列（去重保序）。
两臂**面对同一金标、同一查询集**（`questions` 列表同源）。

### 2.3 机制的关键性质（实测）

| 性质 | 实测值 | 含义 |
|---|---|---|
| 入口命中率 | **390/652 = 0.598** | 40.2% 的查询里**没有任何概念词**，通路连门都进不去 |
| 入口命中 → 有候选 | **119/390 = 0.305** | **69.5% 的入口命中查询候选集为空** |
| 全查询候选为空 | **533/652 = 81.7%** | 常识臂绝大多数查询返回空 |
| 每查询候选数 | 0→533、1→97、2→18、3→4（**max = 3**） | 候选数上限被文档 chunk 数（10）与字面重叠稀疏性双重压死 |
| 每文档 chunk 数 | **恒为 10**（110 个 fc 伪文档全部 10 chunk） | 常识臂的候选池上限 = 10 |
| 候选全并列的查询 | **113/119 = 95%** | 绝大多数有候选的查询里所有候选同分（sc=1） |
| 并列若能完美打破 | Recall@10 仍 = **0.0948** | **并列不是主因**——候选集本身就不含金标 |
| 条件 Recall@10（仅在 119 条有候选的查询上） | **0.5196** | 一旦产生候选，常识臂能拿回一半——**失败发生在桥接步，不在匹配步** |
| 金标在常识排序中的位次 | rank1: 58、rank2: 4、rank3: 1，**rank≥4: 0** | 常识臂命中的都排得极前，只是命中太少 |
| 金标大小 | 单元素 639/652 = 98.0%、双 12、三 1 | 金标极小 → 单次漏召回即掉大量 Recall |

**「候选池」的三种口径（本次实测，避免混淆）**：

| 定义 | min | median | max | mean |
|---|---|---|---|---|
| ① judge 判定过的候选**边**数 | 2 | 9 | 15 | 8.64 |
| ② live 边数 | 2 | 9 | 15 | 8.70 |
| ③ live 边**覆盖的 chunk** 数 = 可召回池 | **2** | **7** | **10** | 7.02 |
| ④ `rank_mappings(top_k=5)` 覆盖的 chunk 数 | 2 | **5** | 5 | 4.35 |
| ⑤ `rank_mappings(top_k=20)` 覆盖的 chunk 数 | 2 | 7 | 10 | 7.02 |

**③ 是「可召回池」的正确口径**（与 `exp_g3_3_metric.json` 的
`{"min":2,"med":7.0,"max":10,"mean":7.028}` 逐位一致）；
**④ 是 A6 旧口径下隐喻臂的实际搜索半径** —— median 5 < 池 median 7，
这就是 §6 公平性问题的物理根源。

## 3. 与隐喻通路的对照设计

### 3.1 为什么要做这个对照

项目的 RQ1 主张是「**隐喻理解所需的是超越基础常识的高阶认知，专属隐喻知识不可替代**」。
该主张的原始依据是**外部文献的间接证据**（方案 §1.3 引 MetaphorBoost 消融：
换通用常识图谱 ConceptNet 性能下降）。A6 的目的就是把这条间接证据
**在本项目的数据与口径上变成直接实测**（方案 §6.3 最后一项消融：
「换成 ConceptNet → 预期性能下降（已有实证支持）」）。

### 3.2 隔离的是什么变量

**被隔离的变量 = 知识类型（knowledge type）**。

| 被固定的量 | 如何固定 |
|---|---|
| 模型能力 | 常识邻居与隐喻结构由**同一厂商的同一模型**产出（`build_llm_backend()`，GLM/DeepSeek 系） |
| 语言风格 | 同上 |
| 查询集 | 两臂共用 `questions`（652 条 LLM 改写查询） |
| 金标 | 两臂共用 `gold`（LLM listwise 判定的相关 chunk 集合） |
| 语料与切分 | 两臂共用同一 `fc` 伪文档与 chunk 序列 |

**唯一变化的量 = 关系类型**：
「域内常识关联（共现 / 类属 / 功能 / 因果）」vs「跨域源→目标映射（隐喻级联）」。

`evaluate_a6.py:10-11` 明说这是**方法学优势**：
> 同一模型生成常识关联与抽取隐喻结构，把「知识类型」变量隔离
> （常识关联 vs 隐喻级联结构），模型能力/语言风格被固定。

### 3.3 为什么这个替代**可以作为隔离装置**，但**不能作为 ConceptNet 的替身**

**可以作为隔离装置**（成立的理由）：对照实验的有效性只要求「除被测变量外其余尽可能一致」。
同厂商同模型同时充当两臂的知识来源，恰好把「模型能力/风格」这一最强的混淆项
控制到了零。作为**变量隔离装置**，它是合格的。

**不能作为 ConceptNet 的忠实替身**（四条，逐条给出本项目的证据）：

| # | 差异 | 具体表现（实测/代码） |
|---|---|---|
| 1 | **无关系类型、无权重、无溯源** | 产物是 `{"词": ["概念", ...]}` 的**扁平列表**。ConceptNet 是 `(relation, start, end, weight, sources)` 的有标关系图（IsA / UsedFor / AtLocation / Causes…）。本替代把 4 类语义（共现/类属/功能/因果）**压成同一种无标边**，两臂的「关系表达力」差异被混入 |
| 2 | **覆盖边界继承自隐喻图本身** | 987 个键全部来自**隐喻图的 vocabulary**（`seeds = L1 边的源域∪目标域`）。这意味着替代源**无法扩宽覆盖边界**——它测不出「换一个更广的知识库会怎样」，只能测「把关系类型换掉会怎样」。ConceptNet 的 34M+ 边、百万级概念是**外部独立**的覆盖面 |
| 3 | **噪声特性不同** | LLM 关联**通顺但不可验证**，且**明确违反了自己的提示词约束**（见 §1.2）：键里混入 `人生漂泊又回到原点`、`制度障碍/政策实施/价值实现` 等描述性/多域拼接串。ConceptNet 的噪声是众包结构性的（漏边、过泛边），性质不同。另：60% 的邻居是只出现一次的长尾，而高频邻居全是 `成长/目标/健康/情绪` 这类**抽象泛词**，在 10-chunk 文档里几乎不携带定位信息 |
| 4 | **同族（in-family）** | 替代源与隐喻结构**同厂商同模型**。这既是隔离设计的优点，也是它的软肋：任何**共享的模型偏差**（例如都偏好某类抽象词）都**没有被控制**。真正的 ConceptNet 对照是一次**出族（out-of-family）**检验 |

### 4.2 失败机制：**桥接失败，不是排序失败**

这是本清单**最重要的实测结论**，也是任务要求「精确记录」的部分。

#### 4.2.1 决定性证据：常识邻居图里没有「查询词 → 隐喻源域」这条边

在 390 条入口命中的查询上，检查**邻居池是否含金标边的关键成分**：

| 邻居池含… | 命中数 | 占比 |
|---|---|---|
| 金标边的**源域** | **8 / 390** | **2.1%** |
| 金标边的**触发词** | 11 / 390 | 2.8% |
| 金标边的**喻底** | 6 / 390 | 1.5% |

即：**常识邻居图几乎从不把查询里的词连到隐喻的源域上去**。这是 0.095 的根因。

#### 4.2.2 上界实验：把入口换成「完美桥接」也只到 0.160

把常识臂的入口从「查询字面命中」换成**金标边的源域**（等于给常识臂一个
完美的、oracle 级别的桥接入口），实测：

| 入口方案 | 入口命中 | 有候选 | **Recall@10** |
|---|---|---|---|
| **A) 当前口径（查询字面命中概念词）** | 390 (0.598) | 119 | **0.0948** |
| B) 完美桥接（直接用金标边的**源域**） | 651 (0.998) | 179 | **0.1595** |
| C) 目标域入口 | 652 (1.000) | 175 | 0.0974 |
| D) 查询入口 ∪ 源域入口 | 652 (1.000) | 263 | 0.2329 |
| E) 用金标边的触发词作入口 | 223 (0.342) | 55 | 0.0429 |

**结论**：即使把「桥接」这一步做到 oracle（B/D），常识通路的 Recall@10 也只到
**0.160 / 0.233** —— 因为**字面邻居匹配本身也跨不了域**。
两个失败叠加：① 入口桥接不上（390→119）；② 即便桥接上了，字面匹配也够不着金标。

#### 4.2.3 逐例剖析（取自实测，非日志）

**例 1 —— `人生如戏`（真失败，与论文引用一致）**

```
改写查询: 人生如戏，每个人都在扮演自己的角色吗？   （原触发词: 舞台）
命中概念词: ['人生']
邻居池(12): ['事业','出生','命运','婚姻','幸福','成长','挫折','死亡','理想','经历','衰老','选择']
常识臂候选: [('fc0_c7', 1)]            ← 只有 1 个候选
隐喻臂 top3: ['fc0_c0', 'fc0_c8', 'fc0_c9']   ← 金标排第 1
金标 fc0_c0: 整个世界就是个舞台，男男女女，演员而已
误命中 fc0_c7: 我不愿意做一个温室里的弱苗，我要出去经历风雨。
```

机制：`人生` 的邻居里只有 `经历` 在文档中字面出现，而它出现在**另一句**
（`fc0_c7`「出去经历风雨」）。常识图把「人生」连到「经历」——一条**同语域**的
常识关联；而文档实际用的是 `舞台/演员` 这个**跨域映射**。
隐喻臂的胜出靠的是显式映射边（实测该查询的 top-2 边，两条都落在金标 `fc0_c0`）：

```
rank1  L1_e01d40b1  src=舞台  tgt=生活        cascade=C_LLM_aefcbfca  score=0.1833
       triggers=['舞台','演员']  ground=['就是','自己的']  spans=['fc0_c0']
rank2  L1_16897657  src=戏剧  tgt=人生/社会事件  cascade=C_EVENT_IS_PLAY  score=0.0844
       triggers=['舞台']  ground=['舞台','演员']  spans=['fc0_c0']
```

> **与论文表述的精确化**：论文 §6.4 写「隐喻通路沿 **EVENT_IS_PERFORMANCE** 级联命中
> 『舞台/演员』chunk」。实测 top-1 其实是**另一条 LLM 开放发现边**
> （`C_LLM_aefcbfca`，src=舞台 tgt=生活）；`C_EVENT_IS_PLAY` 那条排第 2。
> 两者都命中 `fc0_c0`，**结论不受影响**，但「沿 EVENT_IS_PERFORMANCE 级联」
> 的说法把一个「top-2 中有 1 条属于该框架」说成了唯一机制。
> 另：`EVENT_IS_PERFORMANCE` 是**框架 id**，`C_EVENT_IS_PLAY` 是**级联 id**
> （`ontology.py:266` / `:327`），论文用的是宽泛指称。

**例 2 —— `不愿做受保护的人`（候选集直接为空）**

```
命中概念词: ['保护', '受保护的人']
邻居池(21): ['保镖','儿童','动物','妇女','守护','安全','弱者','措施','权益','法律',
             '爱护','环境','病人','监护人','维护','老人','警察','责任','防御','隐私','难民']

```

机制：`保护` 的邻居全是「保护对象 / 保护措施」语域（保镖、监护人、法律、隐私…），
文档用的是 `温室/弱苗/风雨` 的**植物—天气**源域。**零字面重叠 → 候选集空 → Recall 0**。

**例 3 —— `愤怒时像什么一样充满野性难驯`（候选集为空）**

```
改写查询: 愤怒时像什么一样充满野性难驯？   （原触发词: 野兽）
命中概念词: ['愤怒']

常识臂候选: （空）

```

机制：`愤怒` 的邻居是**情绪行为**语域（发火、摔东西、脸红），

**例 4 —— 任务指定的标杆案例「推进不动 → 泥潭」（手工构造，`demo_llm.py` 同款语料）**

```
查询: 为什么我们的项目推进不动？
文档: 这个项目现在陷在泥潭里，每前进一步都要拔出腿来。

① 概念词命中: ['项目']
② 邻居池(12): ['计划','团队','进度','预算','目标','任务','负责人','方案','执行','验收','风险','总结']
   → 池里含「泥潭」吗？            False
   → 池里含「沼泽/陷入/挣扎/淤泥」吗？ 否
③ chunk 字面匹配:
   「这个项目现在陷在泥潭里」   重叠 =（无）
   「每前进一步都要拔出腿来。」 重叠 =（无）
→ 候选集为空 → Recall@10 = 0

对照：若查询**直接说出源域触发词**「泥潭」——
   概念词命中 ['泥潭']，邻居池 = ['危险','拔出','挣扎','救援','水草','沼泽','泥浆','淤泥','湿地','脚印','越陷越深','陷入']
   与文档重叠 = ['拔出']  ✅ 命中
```

**这是整个 A6 机制的最小完整说明**：常识图能连 `项目 → 进度/预算/团队`
（**全在 PROJECT 语域内**），但连不到 `泥潭`（TERRAIN 语域）。
只有当用户**自己说出** `泥潭` 时，常识图才「看起来能工作」——
而那已经是**把答案写进问题里**了。真实用户说的是「推进不动」，
而 `推进` / `推进不动` **在常识图里根本不是键**。

#### 4.2.4 机制总结

```
常识通路的失败发生在**两层**，且第一层就足以致命：

第 1 层（桥接） 查询词 --[常识关联]--> ?          ← 断在这里
   常识图是**语域封闭**的：它只能在同一语域内游走。
   实测：邻居池含金标源域仅 2.1%；390 条入口命中里 271 条（69.5%）候选集为空。
   即便给 oracle 桥接（B/D 方案），Recall@10 也只到 0.160 / 0.233。

第 2 层（匹配） ? --[字面共现]--> chunk            ← 即使桥接上了也弱
   常识邻居与文档的对齐靠**字面共现计数**，无 IDF、无长度归一。
   实测：条件 Recall@10（119 条有候选者）= 0.5196。
   候选数 max = 3（被 10-chunk 池 + 字面稀疏性压死）。

→ 而隐喻通路**不需要第 1 层**：跨域映射由 L1 超边**显式携带**
  （src=戏剧 tgt=人生/社会事件 ground=[舞台,演员] cascade=C_EVENT_IS_PLAY），
  查询沿语义超图打分直接落到映射边，再展开到 chunk。
```

| 维度 | 常识通路 | 隐喻通路 |
|---|---|---|
| **知识对象** | 987 概念词 × 12 无标邻居（`cs_neighbors.json`，11,844 边） | L1 映射超边（源域/目标域/**喻底集合**/触发词）+ L2 框架 + L3 级联 |
| **关系性质** | **域内**：共现 / 类属 / 功能 / 因果 | **跨域**：源域 → 目标域映射 |

| **搜索预算** | **无上限**（全池扫描 10 chunk） | `top_k`；原**硬编码 5** → 修正为 **20** |

| **Hits@3** | 0.097 | 0.670 |
| **候选集为空的比例** | **533/652 = 81.7%** | 0（任意 k≥1 均有返回） |
| **条件 Recall@10**（有候选时） | 0.5196（n=119） | — |
| **失败模式** | **桥接失败**：邻居池含金标源域仅 **2.1%**；oracle 桥接上界仅 **0.160** | **排序/预算失败**：`top_k=5` 时 chunk 覆盖 median 5 < 池 10（覆盖 <10 的查询占 100%） |

## 6. 「A6 公平性修正」

> 完整版见 `experiments/A6预算对等修正.md`；本节为清单口径的复述 + 本次独立复核。

### 6.1 缺陷：两臂搜索预算不对等

| 通路 | 原实现 | 搜索预算 |
|---|---|---|
| 常识通路 | 概念词 → 常识邻居 → chunk 字面匹配 | **无上限**（全池扫描） |
| 隐喻通路 | `rank_mappings(..., top_k=5)` | **硬编码 5** |

原实现中该行为 `ranked, _dec = eng.rank_mappings(q["question"], top_k=5, adaptive=False)`
（commit `b21b5e6` 的 diff 显示为纯字面量 `top_k=5`，无参数化入口）。
隐喻臂被人为截断，常识臂不受限 —— **两臂不对等**。

### 6.2 量化（本次独立复现的完整扫描，n=652）

| 隐喻臂预算 | Recall@10 | Hits@3 |
|---|---|---|
| `top_k=1` | 0.3259 | 0.3313 |
| `top_k=3` | 0.6378 | 0.6426 |
| **`top_k=5`（原实现）** | **0.8287** | 0.6702 |
| `top_k=10` | 0.9908 | 0.6702 |
| **`top_k=20`** | **1.0000** | 0.6702 |
| 无上限（`top_k=1000`） | 1.0000 | 0.6702 |

**`top_k=20` 已与无上限等价** → 原数字**低估隐喻通路 17.1pp**。

**根因（本次新增量化）**：隐喻臂的 chunk 覆盖被 `top_k` 直接封顶。

| 隐喻臂预算 | 覆盖的 chunk 数 min / median / max | 覆盖 <10 的查询占比 |
|---|---|---|
| `top_k=5` | 2 / **5** / 5 | **100%** |
| `top_k=20` | 2 / 7 / **10** | 部分 |

而常识臂的候选池是文档全部 10 个 chunk（无截断）。
**一个覆盖 median 5 个 chunk 的臂，去和一个覆盖 10 个 chunk 的臂比 Recall@10，必然吃亏。**

### 6.3 修正与幅度

| 项 | 修正前 | **修正后** |
|---|---|---|
| 常识通路 | 0.095 | 0.095（**不受影响**，本就无上限） |
| 隐喻通路 | 0.783（论文原表）/ 0.829（本地 `top_k=5`） | **1.000** |
| **两臂差距** | **8.2× ~ 8.7×** | **10.5×** |

### 7.3 理论分界：为什么「推进不动 → 泥潭」**不是**常识关联

#### 7.3.1 两种关系的定义差异

| | 常识关联 | 跨域隐喻映射 |
|---|---|---|
| 连接的两个概念 | **共享语域或范畴** | **不共享语域，但共享关系结构** |
| 关系类型 | 共现 / 类属 / 功能 / 因果 | 源域 → 目标域（结构同构） |
| 是否可凭语料统计获得 | ✅ 可以（共现即证据） | ❌ 不可以（两者从不共现） |
| 是否需要显式断言 | 否（隐含在用法里） | **是**（必须由映射边显式携带） |
| 典型例 | `项目 → 进度 / 预算 / 团队` | `项目困境 → 泥潭`（`DIFFICULTY_IS_TERRAIN`） |

#### 7.3.2 常识图的**语域封闭性**（本清单的核心理论结论）

常识图的性质是：**它只能在同一语域内游走**。

以「推进不动 → 泥潭」为例（实测）：

```
用户查询「项目推进不动」
   ↓ 概念词命中
「项目」
   ↓ 常识关联（实测 12 个邻居，全部）
计划 / 团队 / 进度 / 预算 / 目标 / 任务 / 负责人 / 方案 / 执行 / 验收 / 风险 / 总结
   ↓ 全部仍停留在 PROJECT 语域 —— 即用户**已经在的地方**
（无法抵达 TERRAIN 语域的「泥潭 / 沼泽 / 陷入 / 挣扎」）
```

- `推进`、`推进不动` **在常识图里根本不是键**（实测：`'推进' in cs → False`）。
- 文档实际使用的源域是 `泥潭`；`泥潭` 确实是键，但它的邻居是
  `沼泽 / 陷入 / 挣扎 / 淤泥 / 越陷越深 / 湿地 / 危险 / 拔出 / 水草 / 泥浆 / 脚印 / 救援`
  —— 这是一组**TERRAIN 语域内部**的词，**其中不含任何 PROJECT 语域的词**。
- 因此 `项目` 到不了 `泥潭`，`泥潭` 也回不到 `项目`。**两个方向都不通。**
- 唯一的「通路」是：用户**自己说出** `泥潭`（此时邻居 `拔出` 恰好与文档字面重叠）。
  但那已经不是常识通路在做跨域——是用户把答案写进了问题。

**这不是覆盖率问题，而是关系类型问题。** 即使把常识图从 987 键扩到 ConceptNet 的
百万级概念，只要它仍然只编码「共现/类属/功能/因果」四类**域内**关系，
`项目 → 泥潭` 这条边就**依然不存在**——因为**没有任何常识关系能 licensed 这次跨越**。
跨越只能由隐喻映射来 licensed。

#### 7.3.3 隐喻通路为什么能做成

因为**级联/超边显式携带了跨越**。实测该例的 L1 边：

```
L1_16897657  src=戏剧  tgt=人生/社会事件  cascade=C_EVENT_IS_PLAY
             triggers=['舞台']  ground=['舞台','演员']  spans=['fc0_c0']
```

> 该例隐喻臂的 top-2 边都落在 `fc0_c0`；命名（框架 id vs 级联 id）与论文表述的
> 精确化见 §4.2.3 例 1。

`src=戏剧` 与 `tgt=人生/社会事件` 是**两个不同语域**，这条边**断言**了它们的结构对应，
并给出喻底集合 `[舞台, 演员]` 作为对应关系的**证据词**。
查询沿语义超图打分直接落到这条边 → 展开到 `fc0_c0`（「整个世界就是个舞台，男男女女，演员而已」）。

**所以 A6 的结论可以精炼为一句话**：
> **常识图编码的是「A 与 B 同属一个语域」；隐喻图编码的是「A 与 B 分属两个语域但结构同构」。
> 前者永远推不出后者——这不是数据量问题，是关系类型问题。**

#### 7.3.4 与项目文献定位的一致性

- `知识隐喻分析任务方案.md:48`：「换成通用常识图谱 ConceptNet 性能也下降，
  说明**隐喻理解所需的是超越基础常识的高阶认知**，专属隐喻知识不可替代。」
- `知识隐喻分析任务方案.md:328`（§4.4.1 场景）：「向量检索永远找不到这种关系，
  因为『推进不动』和『泥潭』在向量空间里可能根本不近。」
  —— A6 把这句话从「向量检索」扩展到了「常识图检索」：**两者都找不到**，
  因为它们失败在同一个原因上（域内相似性 vs 跨域映射）。
- `evaluate_a6.py:15-16`（预期引据）：「MetaphorBoost 消融显示换通用常识图谱性能下降
  —— 常识关联覆盖近义/相关概念，但『推进不动→泥潭』这类跨域映射不是常识关联。」
