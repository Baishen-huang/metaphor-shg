## 2. 数据集

### 2.1 CCL2018 测试集（主抽取评测集）

| 项 | 值 | 来源 |
|---|---|---|

| 规模 | **1,100 句** | 实测 `load_ccl2018()` 返回 1,100 |
| 标签分布 | 0=中性(字面) **76** ／ 1=动词隐喻 **517** ／ 2=名词隐喻 **507** | 实测 `Counter(label_raw)` |

**为什么这样设计**：用第三方公开共享任务做 L1 抽取的**硬门槛**验证，

**已知缺陷/边界**：
- 仅 76 条中性句 → P1 的置信区间很宽（一个 FP 约 = 1.3pp）。
- 逐句二分类金标，**无逐边金标** → 无法训练/评测「逐边检测器」，
  这是 P4/HGNN 验收口径被迫改写的原因（见 §10.1）。
- 独立短句、无文档结构 → 扩展链天然稀疏（5 条 / 110 伪文档），
  这是引入 §2.3 连贯文档语料的动机。

### 2.4 伪文档分组（CCL2018 检索化，K=10）

| 项 | 值 | 来源 |
|---|---|---|
| 分组方式 | 按**连续 K=10 句**切伪文档，`did = fc{di}` | `evaluate_fullcorpus.py:190-200` |
| 伪文档数 | **110** | `ceil(1100/10)` |
| 产物 | L1 边 **856**、扩展边 **5**、平均密度 **Δ=1.071** | `experiments/logs/fixed_fullcorpus.log` |
| 候选池（旧口径） | 每查询 = 该伪文档内有边的 **distinct chunk**，**结构上 ≤ K = 10** | 见下 |

**为什么这样设计**：CCL2018 测试句无原生文档结构，需要**人造干扰池**才能测排序。
K=10 的取法给 L1.5 扩展链提供合并空间、给排序提供干扰项。

**已知缺陷/边界（致命）**：池规模**被 K 硬性上界**——K=10 ⇒ 池 ≤10 ⇒
`Hits@10` 对任何返回全候选的排序器恒为 1.0（§9.1）。这是「伪文档分组」
这一设计本身带来的**结构性饱和**，与排序器质量无关。
实测（本文件复算）：110 个伪文档的 distinct-chunk 池 **min=2 / median=7 / max=10**，
**≤10 占比 100%**，与 `exp_g3_3_metric.py` 的记载一致。
另：分组方式是**受控人造**，不是语料原生结构；跨框架 (frame, source_domain)
+ 喻底交集 + 间距<3 的合并判据仍是真实语言信号，不随分组方式改变。

## 3. 基准口径

### 3.1 anchored（锚定口径，现行但已知偏高）

| 项 | 定义 |
|---|---|
| 查询 | `q = "，".join(dict.fromkeys(e.triggers))`（**该边触发词拼接**） |
| 金标 | `gold = {s.chunk_id for s in e.chunk_spans}`（**产出该边的 chunk**） |
| 池 | 全局 1,100 chunk（`build_global_graph` 合并全部伪文档） |
| 规模 | 634 查询（去重后）；金标规模 **min=median=max=1** |
| 位置 | `evaluate_repaired.build_query_sets()` L198-250 |

**为什么这样设计**：这是「排序器能否在干扰池中复原抽取-建图时已建立的结构」的
**自监督口径**，零标注成本、完全确定性。它测的是组件（排序/阈值），
不是端到端召回。

**已知缺陷/边界**：**构造锚定**——查询含金标边触发词，`clue` 特征恒命中，
632/632 = **100%** 的金标都包含产出 chunk，619/632 = **97.9%** 只包含它。
这是 IR 文献的 **pooling bias**（Buckley 等 2007）。
anchored 数字里**约 74% 来自「把已知答案排到前面」**（§8.2 量化）。

### 3.2 deanchor（去锚定口径）

| 项 | 定义 |
|---|---|
| 查询 | 同 anchored（触发词拼接） |
| 金标 | **同框架的「其它」chunk**：`by_frame[e.frame_id] - own`；无同框架则退到同级联 `by_casc[e.cascade_id] - own`；仍无则**丢弃该查询** |
| 池 | 全局 1,100 chunk |
| 规模 | **385/634 = 60.7%** 可构造；金标规模 **min=1 / median=3 / max=37** |
| 位置 | `evaluate_repaired.build_query_sets()` L238-245 |

**为什么这样设计**：物理切断「复现锚点」这条捷径——金标天然不含产出 chunk，
故 `rank_all` 无需再排除。金标规模从恒定 1 变成 median 3 / max 37，**更接近真实检索任务**。

**已知缺陷/边界**：
- 金标由**图结构定义**（同框架），不是人工相关性判断 → 仍是内部检验。
- 385/634 = 61% 可用，其余 249 条因无同框架其它 chunk 被丢弃 → **非全量**。
- **文档描述与代码不一致（重要，本文件新发现）**：docstring、论文 §4.2、
  `REPORT_benchmark_repair.md` 均称「**把产出 chunk 从候选池中移除**」，
  但代码里 `_run(..., exclude_own=True)` 的 `exclude_own` 参数**从未被使用**
  （`evaluate_repaired.py:448`；AST 核对函数体：`exclude_own` **0 次**引用、
  `n_chunks` **0 次**、`chunk_texts` 亦 **0 次** —— **三个参数全是死参**）。
  实际行为是：产出 chunk **仍留在池中**，只是**不在金标里**。
  实测差异（本文件复跑，n=385，人工加权重标定臂）：

  | 实现 | MRR | Hits@3 | Hits@10 | Recall@10 |
  |---|---|---|---|---|
  | 产出 chunk 留在池中（**当前代码**） | 0.2336 | 0.3662 | 0.4597 | 0.3363 |
  | 产出 chunk 物理移出（**文档描述**） | **0.3620** | 0.3792 | 0.4623 | 0.3404 |

  即**当前实现比文档描述更严格**（产出 chunk 作为强干扰项占住 rank 1，
  压低金标名次，MRR 被吃掉 **0.128**）。方向上使已上报数字**偏保守**，
  结论不受影响，但**描述必须改写**为「产出 chunk 移出金标、保留为干扰项」。

### 3.3 重叠型查询（overlap-type）

| 项 | 定义 |
|---|---|
| 构造 | `query = "，".join(e.triggers)` —— **触发词直接出现在查询里** |
| 规模 | 634（去重后全量）；`--max-q 60` 子集用于三通路对照 |
| 位置 | `evaluate_repaired.build_query_sets()` |

**为什么这样设计**：这是 G1/G3 基准的原生形态，与旧口径可比。

**已知缺陷/边界**：字面通路天然占优（触发词就是查询的子串），
`clue` 特征恒命中 → **语义通路的 1.000 受锚定支配**（§9.2）。
实测复跑（n=60）：字面 0.8833 / 级联 0.2000 / 语义 **1.0000** —— 与
`experiments/three_pathway_four_families.log` 逐位一致。

### 3.4 改写型查询（paraphrase-type）

| 项 | 定义 |
|---|---|
| 构造 | LLM 把触发词查询改写成自然问题，**程序化红线**禁止出现原触发词 / 源域 / 目标域 |
| 规模 | **777**（anchored）/ **508**（deanchor）；缓存 782 键 |
| 缓存 | `data/llm_cache_paraphrase.json`（键 = `"<doc>|<原触发词查询>"`） |
| 位置 | `evaluate_repaired.build_paraphrased_sets()` L164-195 |
| 红线过滤 | `evaluate_llmgold.filter_violations()`：`banned = triggers + [src, tgt]`，命中即剔除 |
| 违规率 | 原始 861 查询 → 保留 **635**、违规剔除 **226**（**26.2%**）—— 模型总想偷用触发词 |

**为什么这样设计**：重叠型查询下字面与级联通路天然占优，测不出架构能力。
改写**程序化切断触发词**，才能把「语义/结构信号」与「字面线索」分离。
这是 §6.1 三通路分解的唯一有效查询族。

**已知缺陷/边界**：
- **改写型金标仍是构造性的**（继承触发词查询的金标），只换了查询文本 →
  测的是「改写后能否找回原金标」，不是「能否回答用户问题」。
- **架构能力高度依赖触发词命中**：重叠型语义 MRR 0.9200 vs 改写型 **0.1183**（7.8×）；
  Hits@10 1.0000 vs 0.1918（5.2×）。改写切断了触发词 → 查询侧结构无法激活 →
  7 维特征中 `same_frame`/`same_cascade`/`ground_jaccard` 全部失效
  （AUC 0.505–0.530），只剩 `sem`（AUC 0.62）→ **语义通路退化为纯语义相似度检索**。
- 改写与判定同源（同一模型族）→ 有自偏好风险，用「构造金标一致性 96.8%」交叉校验。

## 4. 指标

> 公式一律以**代码为准**（`metaphor_graph/*.py`）。凡「本文件复算」的数值均为本次编写时实跑得到。

### 4.1 Recall@k

| 项 | 内容 |
|---|---|
| 定义 | `|top_k ∩ gold| / |gold|`；`gold` 为空时返回 1.0 |
| 实现 | `evaluate_repaired.metrics()` L323；`evaluate_retrieval._recall_metrics()` L99 |
| 量程 | [0,1]；**受池规模支配**（池 ≤ k 时任何返回全候选的排序器恒 = 1.0） |
| 论文用途 | §5.1 抽取召回、§6.1 三通路、§6.4 A6、§6.6 L1.5 |
| 复现 | 见汇总表 E1/E6/E7/E8 |

**为什么这样设计**：跨域检索的「能找到多少相关证据」比「第一条对不对」更贴近 RAG 场景。

**已知缺陷/边界**：**这是本项目被误用最严重的指标**。池 ≤10 时恒为 1.0，
而池 ≤10 出现在 G1/G2 全部基准与 A6 全部基准上（§9.1、§9.2）。
池=1,100 时随机期望仅 **0.0091**（金标=1），量程才真正打开。

### 4.2 MRR@10（首个相关项的倒数排名）

| 项 | 内容 |
|---|---|
| 定义 | `1 / rank(第一个命中金标的候选)`；无命中 = 0.0 |
| 实现 | `evaluate_repaired.metrics()` L315-319；`evaluate_retrieval._mrr_hits()` L257 |
| 量程 | **[1/n_pool, 1]**；随机期望 = 随机基线的 `mrr` |
| 论文用途 | §6.1/§6.2/§6.7 全部排序表 |
| 复现 | E6/E7 |

**为什么这样设计**：RAG 的上下文预算有限，**第一条的位置**比召回总数更决定生成质量。

**已知缺陷/边界**：
- 旧池（=7）下随机期望 **0.3704** → 量程被吃掉 **37%**（可用区间只剩 0.63）。
  实测旧口径下四种排序器全在 0.995–0.998，「训练增益」在噪声内。
- 新池（=1,100）下随机期望 **0.0069** → 量程 **0.99**（§9.4）。
- **deanchor 下金标规模不是 1**（median 3 / max 37）→ 池=1,100 的
  「金标=1」随机基线 **不适用于 deanchor 表**。按金标规模加权的正确期望是
  **MRR 0.0291 / Hits@10 0.0589**（本文件复算），故论文中
  「deanchor 0.2330 = 随机的 34 倍」实际是 **8.0 倍**（若按尺寸匹配随机基线）。
  这不是造假，而是**基线选错**：34× 用的是金标=1 的基线。见 §9.4。

### 4.3 Hits@3 / Hits@10

| 项 | 内容 |
|---|---|
| 定义 | top-k 内**至少一个**金标 → 1，否则 0（per-query 后取均值） |
| 实现 | `evaluate_repaired.metrics()` L321-322 |
| 量程 | {0,1} 逐查询；均值 [0,1] |
| 饱和条件 | **池 ≤ k 时恒为 1.0** |

**为什么这样设计**：二值「有没有命中」对下游 RAG 更宽容（一条相关证据即可支撑回答）。

**已知缺陷/边界**：见 §9.1——Hits@10 在池 ≤10 的**全部**历史基准上平凡为 1.000，
被当作性能成就报告过；实际在池=1,100 上语义通路只有 **0.1918**（改写型）。

### 4.4 P1 字面误判率（硬门槛）

| 项 | 内容 |
|---|---|
| 定义 | **`FP / (FP + TN)`** —— 在「本应判字面」的中性句里，有多少被判成隐喻 |
| 实现 | `evaluate_real.eval_split()` L104；`extractor.literal_false_positive_rate()` L307 |
| 门槛 | **< 0.15**（方案 §6.5，Go/No-Go） |
| 论文实测 | **9.2%** ✅ |
| 复现 | E1（本文件实跑复现 0.092，TP=713 FP=7 TN=69 FN=311） |

**为什么这样设计**：隐喻抽取最大的工程风险是**字面误判泛滥**（把「红薯有药用价值」
判成隐喻），所以方案把它定为唯一的 Go/No-Go 硬门槛。

**已知缺陷/边界（本文件新发现，重要）**：
**P1 的效应上界恒等于 0**（`exp/degrade` 的决定性证据）。
判据是 `pred = bool(edges)` —— 只统计「这句话有没有产出任何边」。
任何**不丢弃候选**的机制（软折扣、可靠性降权、类型连贯性检查）
都不可能改变 `bool(edges)`，故对 P1 的效应**结构性为 0**。
实测：7/7 条字面误判句**全部**由本体正式框架支撑（0/7 来自降级边）。
→ 论文 §7 的 A1 结论（H1 证伪）根因在此，**不是「没接上」，是「不可能接上」**。

**为什么这样设计**：单一数字便于门槛判定。

**已知缺陷/边界**：P3 的 F1 在**精选诊疗集**上（2 文档 7 条金标链）测出 **1.000**，
语料是**按可检测隐喻刻意设计**的（`eval_corpus.py` docstring 自陈）。

### 4.7 全量负样本 AUC（判别力主指标）

| 项 | 内容 |
|---|---|
| 定义 | `AUC = P(score_pos > score_neg) + 0.5·P(score_pos == score_neg)`，用**全量正负对** |
| 实现 | `evaluate_hgnn._auc_full()` L316-328 |
| 规模 | 20 正 × 752 负 = **15,040 对** |
| 论文实测 | HGNN **0.915** / flat 0.910 / raw **0.550** / GRU 0.945 |
| 复现 | E9（本文件实跑逐位复现：0.915 / 0.910 / 0.550 / 0.945） |

**为什么这样设计**：原口径是 **n=20 的配对准确率**，分辨率仅 **0.05**，
18 个 (α,ε) 配置下 \|Δacc\| ≤ 0.05 全落在噪声内，且**结论字符串会随无关参数抖动翻转**
（实测 α=0.5 时打印「依赖跨层传播 ✅」）。
改用全量 AUC 后 \|ΔAUC\| ≤ 0.005，**方向稳定**。

**已知缺陷/边界**：
- **并列处理是决定性的**：raw 的配对准确率 = 0.150（**低于随机**），
  但 AUC = **0.550（≈无信息）**。差异源于默认哈希向量下抽象域标签几乎无共享
  n-gram，**全体并列率 94.6%**（正样本 85.0%、负样本 94.8% 余弦恰为 0），
  而配对准确率**把并列计为错误**。论文 §6.3 已修正表述为「无信息而非反向判别」。
- 正样本仅 20 条（2 文档诊疗集），AUC 的 CI 宽。

### 4.12 随机排序基线（解析期望）

| 项 | 内容 |
|---|---|
| 实现 | `evaluate_repaired.random_baseline(n_pool, n_gold, ks=(3,10))` L327-346 |
| 用途 | 给出各指标的**量程下界**，判断饱和程度 |

**三个解析公式（这是本节的核心）**：

**(1) MRR 期望** —— 金标中最早出现的那个的期望倒数排名：

```python
exp_mrr = 0.0
for r in range(1, n + 1):
    if r - 1 > n - g:          # 前 r-1 个位置放不下「全部非金标」
        break
    p = (comb(n - g, r - 1) / comb(n, r - 1)) * (g / (n - r + 1))
    exp_mrr += p / r
```

即：`p(第 r 位首次命中) = [C(n-g, r-1) / C(n, r-1)] × g/(n-r+1)`，
其中第一项 = 「前 r−1 位全非金标」的概率，第二项 = 「第 r 位是金标」的条件概率。

**(2) Hits@k 期望** —— 1 − 「top-k 全是非金标」：

```python
hits@k = 1 - C(n - g, k) / C(n, k)      # n-g < k 时取 0.0
```

**(3) Recall@k 期望** —— 超几何分布均值：

```python
recall@k = min(1.0, k * g / n) / max(1, g)
```

**关键数值（本文件实跑 `random_baseline()` 得到，可逐位复算）**：

| 池 n | 金标 g | MRR | Hits@3 | Hits@10 | Recall@10 |
|---|---|---|---|---|---|
| **5** | 1 | 0.4567 | 0.6000 | **1.0000**（饱和） | **1.0000**（饱和） |
| **7** | 1 | **0.3704** | 0.4286 | **1.0000**（饱和） | **1.0000**（饱和） |
| **8** | 1 | 0.3397 | 0.3750 | **1.0000**（饱和） | **1.0000**（饱和） |
| **10** | 1 | 0.2929 | 0.3000 | **1.0000**（饱和） | **1.0000**（饱和） |
| 20 | 1 | 0.1799 | 0.1500 | 0.5000 | 0.5000 |
| **1,100** | **1** | **0.0069** | **0.0027** | **0.0091** | **0.0091** |
| 720（**有效池**） | 1 | 0.0099 | 0.0042 | 0.0139 | 0.0139 |

**为什么 `Hits@10 = 1.0` 当池=7**：`C(6,10)` 在 `n-g < k` 时按 0 处理
→ `1 - 0 = 1`。这不是近似，是**数学恒等**。


**量程换算**：可用量程 = `1 − 随机期望`。
池=7 → MRR 量程 **0.63**；池=1,100 → **0.99**。

**已知缺陷/边界**：
- 公式假设**均匀随机排序**（无并列、无先验）。实际排序器输出有大量并列，
  故随机基线是**乐观下界**（并列会把随机期望抬高一点）。
- **只对 `n_gold = 1` 与 anchored 口径现成可用**。deanchor 的金标规模是分布
  （min=1/median=3/max=37），必须按查询加权（§9.4）。
- `evaluate_repaired.main()` 打印基线时**硬编码 `n_gold=1`**（L439），
  而 deanchor 表紧挨着打印 → 读者极易误用。

## 5. 评测协议

### 5.1 双段管线（候选生成 → 语义校验）

| 项 | 内容 |
|---|---|
| 第一段 | **宽松生成**：`ground1` 判据（同框架 + 同源域 + 间距<3 + 喻底交集≥1）→ 52 条候选 |
| 第二段 | **语义校验**：`llm_backend.verify_chains_batch()` —— LLM 逐链判定「跨段延续」→ 保留 **11/52 = 21.1%** |
| 失败纪律 | 校验缺失（批次失败）的链**按未校验剔除**，不得当作通过（`builder.py:73` 注释） |
| 效果 | 精度 16.7% → **63.6%**（约 4×） |
| 位置 | `evaluate_document_corpus.py:165-194`；`evaluate_chain_quality.py:175-187` |

**为什么这样设计**：与抽取侧**对称**——第一段保密度（宽松召回），
第二段保精度（严格过滤）。这是 HyperRAG 式「宽松生成 → 严格过滤」架构在
隐喻链上的移植。

**已知缺陷/边界**：
- **被消融证伪的两个替代信号**（同候选集、同 judge）：
  - 文本级判据 `vehicle_repeat`（触发词跨段复现 或 喻底交集≥2）：密度 52→49，
    **存活链不变**，精度仍 16.7% → **文本级信号无效**。
  - 图结构 `metaphor_coherence` 阈值 0.5（L1-only 图，避免自证）：保留 52/52
    （全体连贯度中位数 **0.820**），精度不变 → **图连贯度无效**。
  - 结论：判别信息在**语境级语义**中，词面信号与抽象域标签的图连贯度均不可见。
    这是「结构化管线中哪些环节必须引入语言模型」的一个可测量判据实例。
- 校验器与抽取器同模型族 → 保留集精度可能被高估。

### 5.2 LLM-as-judge（生成质量盲评）

| 项 | 内容 |
|---|---|
| 设计 | 答案匿名化（A/B 或 A–D 按固定种子随机排序），judge 按 4 维打 1–7 分 |
| 维度 | 正确性 / 引用精确度 / 框架一致性 / 可读性 |
| 评卷参考 | 向 judge 提供**金标 chunk 原文**（判正确性所需） |
| 脚本 | `evaluate_llmasjudge.py`（2 系统）、`evaluate_packing_ablation.py`（4 变体） |
| 种子 | `20260830` / `20260831`（确定性） |

**为什么这样设计**：方案 §6.4 设计了 7 分 Likert 人工评估（3 语言学 + 3 领域 +
5 普通用户），但凑齐评估者前先用 LLM 盲评拿一版**模拟数据**，尽早暴露生成质量问题。

**已知缺陷/边界（这是项目最有价值的方法论发现之一）**：
**结论随 judge 模型反转**。同一查询集、同一生成模型、4 种打包变体：

| judge | 结论 |
|---|---|
| **deepseek** | 判**纯向量对照 6:1 胜** |
| **glm-5.3-flash** | 判**当前 50/30/20 打包最优**（26.50 vs 21.12，最优率 50%） |

→ **一切生成质量主张必须由真人评估仲裁**；组件级检索结论（§6.1–6.4）不受影响。
这把「需要人工评估」从程序性要求变成了**实测结论**。
另：n=8 诊疗集查询；生成与评判同厂商（自偏好风险）。

### 5.3 跨模型二评（Cohen's κ）

| 项 | 内容 |
|---|---|
| 设计 | 抽 50 条查询，由**跨模型第二标注者**独立重判全部候选，逐边配对算 κ |
| 原金标 judge | glm-5.3-flash；**二评** glm-4.7-flash |
| κ 公式 | `κ = (pa − pe)/(1 − pe)`，`pe = yes_a·yes_b + (1−yes_a)(1−yes_b)` |
| 实测 | **13 查询 / 114 边对**，`pa = 0.991`、`pe = 0.752`、**κ = 0.965**（近乎完美），不一致 **1** 对 |
| 复现 | E12；本文件用 `data/gold_audit_cache.json` + `llm_cache_judge.json` 独立复算，得 κ=**0.9646**、114 对、1 处不一致 ✅ 一致 |

**为什么这样设计**：用跨模型一致性**替代人工抽查**（第二标注者免费配额受限），
量化金标的标注者间可靠性。

**已知缺陷/边界**：
- **模型-模型 κ 是人工 κ 的下界代理**（同厂商家族、无真实标注者间差异的完整性）。
- **实际只跑到 13/50 查询**（免费档 429 限流，`data/gold_audit.log` 满屏 429）→
  114 边对，CI 宽。论文称「13 查询/114 边对」是诚实的，但**计划是 50 查询**。
- κ 的参考档（≥0.8 几乎完美）继承 Landis & Koch，未做本项目标定。

### 5.4 同模型换序二评（引出稳健性）

| 项 | 内容 |
|---|---|
| 变体 | **候选逆序** + `temperature = 0.4`（原为默认温度） |
| 实测 | **50 查询 / 420 边对**，`pa = 0.976`、`pe = 0.728`、**κ = 0.912**；10 处不一致**全部为二评更宽**（二评更严 0） |
| 缓存 | `data/gold_audit_cache_reorder.json`（50 键，实测） |
| 复现 | `$PY -m metaphor_graph.evaluate_gold_audit --reorder --audit-cache-suffix _reorder` |

**为什么这样设计**：跨模型二评混了**两个变量**（模型更换 + 引出方式）。
换序二评**固定模型**只动引出顺序与温度，把「引出稳健性」单独隔离出来。

**已知缺陷/边界**：κ=0.912 是**同模型**一致性，**不能**当作标注者间可靠性；
论文并列报告两协议是正确做法。10 处不一致全为单向（二评更宽）值得注意——
可能是逆序导致的位置偏差（后出现的候选被更宽松地接受），未被进一步分析。

### 5.5 泄漏自检（clue AUC / trivial_separators）

| 项 | 内容 |
|---|---|
| `feature_auc(ds)` | 每个**单特征**的 AUC（并列计 0.5） |
| `leakage_report(ds, auc_threshold=0.98)` | 返回单特征 AUC ≥ 0.98 的特征名；**非空 = 该样本集不适合上报指标** |
| `trivial_separators(ds, threshold=1e-9)` | 检出「单特征即可**完美**分类」的构造缺陷（正样本最小值 > 负样本最大值） |
| 位置 | `training.py:195-241` |

**为什么这样设计**：自监督样本集有一个**结构性陷阱**——
正样本 = 「该 chunk 实际抽出的边」，负样本 = 随机抽的其它 chunk，
于是 `clue`（触发词命中）**按构造就是标签本身** → AUC ≈ 1.0 →
排序器退化成「复读抽取器」，训练增益是自我实现。

**实测与修复**：

| 训练信号 | clue 平均 AUC | leakage 标记 | MRR@10（旧池） |
|---|---|---|---|
| 自监督（随机负样本） | **≈1.000** | **136 处** | 0.998 |
| **LLM 弱监督**（refine 否决候选作负样本） | **0.931** | **23 处（−83%）** | 0.998 |

**为什么弱监督能修**：refine 缓存里躺着真金白银买来的标签——
`batch_refine` 把每个 (chunk, 源域, 目标域) 候选的 LLM 判断落了盘，
`is_metaphor=False` 的候选是「**同 chunk、同触发词、但被模型否决**」的天然困难负样本，
其 clue 特征与正样本几乎相同 → clue 不再完美可分。

**已知缺陷/边界**：
- 修好了**训练信号的病理**（clue AUC 1.0→0.931、leakage 136→23），
  但 **MRR 完全不动**（0.998 → 0.998）—— 因为旧池已饱和，**测不出排序增益**。
  弱监督排序器的检索价值**至今未被证实**（改写型基准上是 −0.013）。
- `leakage_report` 的 0.98 阈值抓不住 AUC=0.93 这种「实质已被单特征决定」的样本集
  （docstring 自陈）。
- 实测 `evaluate_fullcorpus` 打印「110 个训练集中 leakage_report 共标记 **136 处**」。

**已知缺陷**：
1. **judge 是 LLM**（跨模型降低但不消除同源偏差）；n ≤ 30 抽样；**分子分母都小**。
2. **两个替代信号被证伪**：文本级 `vehicle_repeat`（密度 52→49，存活链不变）、
   图连贯度 `--coherence-threshold 0.5`（保留 52/52，全体中位数 0.820）。
3. **judge 默认模型与抽取模型不同**（glm-4.7 vs glm-5.3），但**同厂商**。
4. **429 限流**：多次 run 有判定失败被跳过（日志满屏 `429 Too Many Requests`），

### 7.12 `evaluate_llmasjudge.py` — 生成层 LLM-as-judge 预演

| 项 | 内容 |
|---|---|
| **测什么** | 隐喻结构上下文（A）vs 纯向量对照（B）的生成质量：4 维 1–7 分 + 总分胜率 |
| **怎么跑** | `$PY -m metaphor_graph.evaluate_llmasjudge`（需 `LLM_API_KEY`；生成与判定均落盘缓存） |
| **依赖缓存** | `data/llm_cache_llmasjudge.json`（5.6 KB）+ `llm_cache_corpus.json` |
| **n** | **8 查询**（诊疗集 `GOLD_RETRIEVAL`）；2 系统 |
| **盲评** | A/B 顺序按种子 `20260830` 随机 |
| **实测** | 缓存存在（`gen|meta|*`、`gen|vec|*`、`judge|*` 键），但**日志未留档到 `data/*.log`**；脚本每次运行会打印胜率与 4 维均分 |

1. **n=8**；生成与评判**同用 LLM**（自偏好风险）。

## 8. 已发现并修复的评测缺陷（含幅度）

> **本项目的核心方法论贡献**。八处缺陷按「检测方式 / 幅度 / 修复」三项登记。
> 其中 §8.1–8.3 是**同类系统性缺陷**（两臂的搜索预算、候选池规模或金标口径不对等），
> 由 `audit_fairness.py` 统一检查。

### 8.1 缺陷 ①：候选池过小 → Hits@10 平凡饱和

| 项 | 内容 |
|---|---|
| **检测方式** | `exp/typefeat`（gen3 实验三 `exp_g3_3_metric.py`）逐查询统计候选池分布 |
| **幅度** | 池 **min=2 / median=7 / max=10，≤10 占比 100%** → **Hits@10 在 100% 的查询上恒为 1.000**；随机排序 MRR 期望 **0.3704** → **MRR 量程被吃掉 37%**（可用区间 0.63） |
| **后果** | 各通路/各配置**同样饱和**，相对结论仍成立，但「1.000」被当作性能成就报告；语义超图 Hits@10 被高估 **5.2×**（1.000 → 0.1918） |
| **IR 学名** | test collection 规模不足（Efficient construction of large test collections, SIGIR 1998） |
| **修复** | `evaluate_repaired.build_global_graph()`：110 个伪文档合并为**一张全局图**，池 = **1,100 chunk** → 随机 MRR 期望 **0.0069**、Hits@10 **0.0091**、MRR 量程 **0.99** |
| **修复后实测** | 语义超图通路（改写型，n=777）Hits@10 **0.1918**、Recall@10 **0.1918**、MRR **0.1183**；重叠型（n=60）仍为 1.0000（**真实但受锚定支配**） |
| **残留** | ① `evaluate_fullcorpus` / `evaluate_llmgold` / `evaluate_a6` **仍跑在旧池上**，其 Hits@10/Recall@10 不可用于判定质量；② 有效池只有 **720**（§9.4） |

### 8.2 缺陷 ②：构造锚定（pooling bias）

| 项 | 内容 |
|---|---|
| **检测方式** | `exp/typefeat`（gen3 实验三）：逐条检查 LLM 金标是否包含「产出该问题的 chunk」 |
| **幅度** | **632/632 = 100%** 的查询，金标都包含产出 chunk；**619/632 = 97.9%** **只包含它** |
| **后果** | 任务退化为「把产出 chunk 排第 1」→ 与 `clue`/触发词命中强耦合；论文 §4 原称的「**非构造金标**」标签**不成立**——LLM 只做**过滤**（筛掉不相关候选），**未解除锚定** |
| **量化（决定性的 MRR 来源分解）** | 人工加权：产出 chunk 列 **0.4728**（n=632） vs 非产出列 **0.6987**（n=13）；训练后：**0.5372** vs **0.6923**。训练增益 **+6.44pp 全部落在「把构造锚点排更前」这一列**，非产出列为 **−0.64pp** |
| **修复后量化（§4.2/§6.7）** | anchored 0.8956 vs deanchor 0.2330 → **锚定抬高 ≈ +0.6626 MRR**，即原报告数字里**约 74% 来自「把已知答案排到前面」** |
| **IR 学名** | pooling bias（Bias and the limits of pooling for large collections, 2007） |
| **修复** | ① `deanchor` 口径（金标改为同框架其它 chunk，产出 chunk 不进金标）；② 全局池；③ 报告随机基线作为对照 |
| **残留** | ① deanchor 金标仍由图结构定义，**不是独立金标**；② 可构造 deanchor 查询仅 **385/634 = 61%**；③ **论文 docstring 称「把产出 chunk 移出池」，实际代码未移出**（§3.2，本文件实测 MRR 差 0.128）；④ anchored 表（论文 §4.2/§6.7）**在当前 HEAD 上不可复现**（§8.6） |

### 8.3 缺陷 ③：两臂搜索预算不对等（A6）

| 项 | 内容 |
|---|---|
| **检测方式** | 逐节复核「两臂是否对等」时发现（**人工审查三次都漏掉了下一处**，故后改为机器检查） |
| **幅度** | 常识通路 **无上限**（全池扫描）vs 隐喻通路**硬编码 `top_k=5`**。同一查询集（n=652）：`top_k=5` → Recall@10 **0.8287**；`top_k=20` → **1.0000**（与无上限等价）→ **低估隐喻通路约 17pp** |
| **修复** | 改为 `--meta-top-k`（**默认 20**）；保留 `--meta-top-k 5` 可复现旧口径 |
| **修复后** | 隐喻通路 **1.000**（受池饱和限制，见 §9.2）vs 常识通路 **0.095** → 差距从 8.2× 扩大到 **10.5×**，**核心结论反而加强** |
| **配套** | 新增 `metaphor_graph/audit_fairness.py`（静态扫描 + 单测护栏 `test_no_hardcoded_budget_in_comparisons`） |

### 8.4 缺陷 ④：人工权重错配（本文件认定的最严重标定事故）

| 项 | 内容 |
|---|---|
| **检测方式** | `exp/typefeat` 对比「人工权重」与「110 个伪文档各训一个排序器后取均值的学到权重」 |
| **幅度** | 归一化后：`struct` 人工 0.25 vs 学到 +0.0195 → **过权 37 倍**；`type` 人工 0.20 vs +0.0487 → **12 倍**。原始空间有效权重（`w/sd`）口径下更严重：**49 倍 / 19 倍** |
| **后果** | **仅把人工权重按学到比例重标定（不训练任何模型）**：旧口径 MRR **0.4809 → 0.5496（+6.87pp，p=0.0000）**，**反超**训练后的 0.5447 → 原「训练增益 +6.4pp」降为 **+0.49pp [−0.89, +1.84]（CI 覆盖 0）**。即**训练增益主要是人工权重配错的产物** |
| **附带发现** | **1 维 `sem` 单信号 = 0.5474**，与训练后 7 维 0.5449 **无差异**（Δ=+0.0025，CI 覆盖 0）；真实句向量下纯 `sem` **显著更高**（+1.76pp，p=0.003） |

| **残留** | `HAND_WEIGHTS_LEGACY` 仍在代码里（`evaluate_retrieval.py` 的 `legacy_arm` 参数、`evaluate_repaired` 的 `hand_legacy` 臂）；误用会得到历史口径数字 |

### 8.5 缺陷 ⑤：type 特征双路径不一致（静默低估）

| 项 | 内容 |
|---|---|
| **检测方式** | `exp/source` 排查「两条打分路径是否给同一个值」 |

## 9. 指标可用量程（哪些饱和 / 受限 / 误用）

### 9.1 饱和指标一：Hits@10（池 ≤ 10 时恒为 1.0）

| 项 | 内容 |
|---|---|
| **饱和条件** | **池 ≤ k**。数学恒等：`1 − C(n−g, k)/C(n, k)`，`n−g < k` 时 `C=0` → 结果 1.0 |
| **实测** | 池=5/7/8/10 时随机 Hits@10 **全部 = 1.0000**（本文件复算） |
| **受影响的评测** | E4（诊疗集）、E5（全量伪文档）、E6b 的重叠型子集、E7（llmgold）、E8（A6）——**全部旧口径** |
| **后果** | 「Hits@10 = 1.000」在这些评测上**完全无信息**，既不能证明排序器好，也不能区分配置 |
| **新池下的真实值** | 池=1,100：语义超图通路（改写型，n=777）**0.1918**；重叠型（n=60）**1.0000**（真实值，但受锚定支配） |
| **可用性判定** | **仅在池 > k 时可用**。当前唯一合规的用法是 E6（全局池 1,100）。 |

### 9.2 饱和指标二：Recall@10 / Hits@10（池 ≤ 10 且排序器返回全候选）

| 项 | 内容 |
|---|---|
| **饱和条件** | 池 ≤ k **且**排序器返回全部候选 → Recall@10 恒 = 1.0 |
| **受影响的评测** | E8（A6 隐喻臂 **1.000**）、E7（llmgold 语义超图通路 **1.000**）、E4（P3 的 Recall 辅助列） |
| **性质** | **不是性能成就**。A6 的 1.000 与 §6.1 的 1.000 同源 |
| **为什么 A6 结论仍有效** | 证据结构是**相对比较**（两臂同一金标、同一查询集）；常识臂 0.095 是**真实低值**（受限于概念词命中率 390/652 = 0.598，邻居匹配是字面匹配、跨域失效）。修正预算后差距从 8.2× 扩大到 **10.5×** |
| **正确表述** | 「在池饱和条件下，隐喻通路的召回**上界**（1.000）显著高于常识通路（0.095）」，并注明前者绝对值受池规模限制、**不可外推为「能召回 100% 的相关证据」** |
| **可用性判定** | **仅可用于两臂相对比较**，不可作为绝对性能报告。 |

### 9.3 饱和指标三：MRR（旧池下量程被吃掉 37%）

| 项 | 内容 |
|---|---|
| **量程** | `[随机期望, 1]` |
| **旧池（=7）** | 随机期望 **0.3704** → 可用量程 **0.63**；实测四种排序器全在 **0.995–0.998** → **在噪声内**，任何「训练增益」都不可信 |
| **新池（=1,100）** | 随机期望 **0.0069** → 可用量程 **0.99** |
| **clue 天花板的叠加效应** | 旧池下 `clue` 单特征 AUC ≈ 1.0 → 训练器退化为「复读抽取器」，学到的权重 `clue=1.4243`（实跑打印），其余 ≈0 |
| **可用性判定** | 旧池 MRR **不可用于判定排序质量**；新池 MRR 可用，但**基线必须按金标规模匹配**（§9.4）。 |

### 9.4 **被误用的基线**：deanchor 表用了「金标=1」的随机基线（本文件新发现）

| 项 | 内容 |
|---|---|
| **现象** | 论文 §4.2/§6.7、README、DATA.md 均称「**deanchor MRR 0.2330 是随机基线 0.0069 的 34 倍**」 |
| **问题** | 0.0069 是 `random_baseline(1100, **n_gold=1**)` 的值，而 **deanchor 的金标规模是 min=1 / median=3 / max=37**（非 1）→ 基线选错 |
| **正确的尺寸匹配基线（本文件复算，按 385 条查询的金标规模加权）** | |

| 池 | 金标处理 | 随机 MRR | 随机 Hits@10 | 随机 Recall@10 |
|---|---|---|---|---|
| 1,100 | 固定 g=1（**论文所用**） | 0.0069 | 0.0091 | 0.0091 |
| 1,100 | **按金标规模加权** | **0.0291** | **0.0589** | **0.0091** |
| 720（**有效池**） | 固定 g=1 | 0.0099 | 0.0139 | 0.0139 |
| 720（**有效池**） | **按金标规模加权** | **0.0407** | **0.0870** | **0.0139** |

| 项 | 内容 |
|---|---|
| **修正后的倍数** | deanchor MRR 0.2330 ÷ **0.0291** = **8.0×**（而非 34×）；若同时修正有效池：0.2330 ÷ 0.0407 = **5.7×** |
| **影响判定** | **结论方向不变**（deanchor 仍显著高于随机，「架构具备真实跨域检索能力」成立），但**幅度从 34× 降到 5.7–8.0×** |
| **为什么 `random_baseline` 会这样** | `evaluate_repaired.main()` L439 硬编码 `random_baseline(gs["n_chunks"], 1)`，而它紧接在 deanchor 表之后打印 → 读者自然会把 0.0069 当作 deanchor 的基线 |
| **建议** | ① 把 deanchor 表的基线改为尺寸匹配值 0.0291；② 或明确标注「0.0069 是金标=1 的基线，deanchor 金标中位数 3，故实际随机水平更高」；③ `random_baseline` 增加「按查询加权」的封装 |

### 9.5 受限指标：池规模 ≠ 名义值（有效池 720）

| 项 | 内容 |
|---|---|
| **现象** | 全局池名义 **1,100 chunk**，但**有效池只有 720** —— 候选来自 `eng.live_edges()` 的「边 → chunk」映射，**没有任何边的 chunk 永远不可能被排到** |
| **实测** | `len(eng._chunk_text) = 1100`；`distinct chunks covered by edges = 720`；`live_edges = 861` |
| **影响** | 随机基线偏乐观：池=720 时 MRR 期望 **0.0099**（vs 池=1,100 的 0.0069），即**真实随机水平比报告的高 43%** |
| **性质** | 这**不是错误**（只有被抽取出隐喻的 chunk 才是合法候选），但**必须在论文里说明**——否则「池 1,100」会被理解为「1,100 个可排候选」 |
| **可用性判定** | 报告池规模时应同时报「名义池 / 有效池」。 |

### 9.6 受限指标：配对判别准确率（n=20，分辨率 0.05）

| 项 | 内容 |
|---|---|
| **分辨率** | `1/20 = 0.05` —— 一个样本的差异就是 5pp |
| **实测抖动** | 18 个 (α,ε) 配置下 \|Δacc\| ≤ 0.05（至多一个样本对之差），且**结论字符串会随无关参数翻转**（α=0.5 时打印「依赖跨层传播 ✅」） |
| **并列陷阱** | 并列计错 → raw 得 **0.150**（低于随机），而其真实 AUC = **0.550**（无信息）。原因：哈希向量下抽象域标签几乎无共享 n-gram，**全体并列率 94.6%** |
| **替代** | **全量负样本 AUC**（20 正 × 752 负 = 15,040 对），\|ΔAUC\| ≤ 0.005 |
| **可用性判定** | **仅作历史兼容**；主指标必须用全量 AUC。 |

### 9.7 受限指标：严格口径链精度（分子 7 / 分母 11）

| 项 | 内容 |
|---|---|
| **数字** | 63.6%（7/11）；跨模型配对子集 71.4%（10/14）；另一轮 75.0%（6/8） |
| **CI 宽度** | 7/11 的 95% CI 约 **[0.31, 0.89]** —— 「从 16.7% 提升到 63.6%」的**幅度不可靠** |
| **可靠的** | **方向**：三组独立 run 都是 16.7% → 63.6/66.7/75.0% |
| **可用性判定** | 可报告方向与「约 4 倍」的粗略幅度，**不可把 63.6% 当作精度点估计**。 |

## 10. 评测的已知边界

### 10.1 口径与金标

1. **没有任何人工标注的检索金标**。全部检索金标是构造性的
   （anchored：产出 chunk）或图结构定义的（deanchor：同框架其它 chunk）。
   项目自己指出下一步是「用外部基准替换查询来源」（MiQA / ANALOGICAL），
   **未做**。
2. **LLM 金标的「非构造」标签已被证伪**（§8.2）。LLM 的作用是过滤，不是独立标注。
3. **改写查询与相关性判定同源**（同一 deepseek 模型族）→ 自偏好风险；
   用「构造金标一致性 96.8%」交叉校验，但这**不是独立验证**。
4. **跨模型 κ 只跑到 13/50 查询**（限流），且是**模型-模型 κ**（人工 κ 的下界代理）。
5. **真人评估完全缺失**。方案 §6.4 设计的 7 分 Likert 人工评估
   （3 语言学 + 3 领域 + 5 普通用户）**从未执行**；LLM-as-judge 只是预演，
   且已被证明**结论随 judge 模型反转**（§5.2）。
6. **P4 验收口径被迫改写**：原写「抽取 F1 提升 >5pp」，但
   CCL2018 **无逐边金标**、单句图太稀疏无法驱动图卷积 →
   改为测「跨层语义信号对检索/检测的质量」。这是**口径不匹配**而非达标/不达标。

### 10.2 数据与规模

1. **CCL2018 中性句只有 76 条** → P1 的 CI 宽（一个 FP ≈ 1.3pp）。
2. **连贯文档语料 106 篇是自采**，规模远小于真实 RAG 场景；
   鲁迅部分（1920 年代白话）L1 基数低 → 跨语时代泛化是已知边界。
3. **伪文档分组（K=10）是人造结构**，且 K 直接决定旧池上界（≤10）→ 见 §8.1。
4. **诊疗集只有 2 文档 / 8 查询 / 7 条链**，且语料是**按可检测隐喻刻意设计**的
   → P3 F1 = 1.000 与 H3/A5 结论**不可外推**。
5. **单语言**：框架与本体为中文；英文资源（VUA / `ontology_bilingual.json`）
   是对齐标注，**非独立英文抽取本体**。VUA 评测路径存在（`--vua`）但**未跑过**。
6. **`train.xml` 不是合法 XML** → 任何 `ET.parse` 复现脚本会崩。

### 10.3 统计与复现

1. **绝大多数评测在全量上读数，无 tune/report 切分**（仅 `evaluate_llmgold` 有）。
   超参（npp=3、seed=42、epochs=50、lr=0.1、`llm_conf=0.85`）**从未扫描**。
2. **结论判定阈值全部拍定**（0.02 / 0.2 / 0.05 / 0.98），无敏感性分析；
   且同一阈值在池规模修复前后**含义不同**（§4.14）。
3. **多处 n 极小**：A8 的 n=6、P4-B 的 20 正、链精度 7/11、跨模型 κ 13/50、
   LLM-as-judge 8 查询。
4. **已上报数字与当前代码存在不可复现**（§8.6），根因是 `type` 特征编码变更。
5. **`make_figures.py` 的数字硬编码且基于旧口径** → 五张图与论文修复后表格口径不一致。
6. **429 限流导致多次 run 的 n 不同**（链精度 30/8/6/11/7），
   跨 run 的精度数字**不可直接比较**。

## 12. 一句话总结

这套评测方法学的**主要产出是「分数不可用的证明」**：
项目用四代实验、七个分支，自己诊断出**八处评测缺陷**（池 ≤10 使 Hits@10 平凡饱和、
构造锚定使 100% 金标含产出 chunk、两臂预算不对等、人工权重错配 37 倍、
type 特征双路径分歧 22%、静默回落产出假性指标、审计字段声明未实现、
已上报数字与当前代码不可复现），并把每处的**检测方式、幅度与修复**一并留档。

**修复后的可用结论**：在全局池（1,100 / 有效 720）上，去锚定 MRR **0.2330**
（尺寸匹配随机基线 **0.0291** → **8.0×**，若用名义池的 g=1 基线则 34×），
而 anchored 口径的 0.8956 里**约 74% 来自构造锚定**。

**必须同时报告的边界**：Hits@10 在旧池上恒为 1.0（不可用）；
P1 的效应上界恒为 0（结构性）；配对准确率 n=20 功效不足；
链精度 7/11 的幅度不可靠；真人评估从未执行。
