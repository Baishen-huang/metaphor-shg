# 多方向并行实验与演化协议

本目录记录以 **git worktree + 独立分支** 隔离的并行实验，以及代际演化规则。

## 为什么需要隔离

项目的历史实验都在单一工作树里串行推进，导致两个问题：

1. **结论无法归因**。多个改动混在同一份代码上，某指标变化无法定位到具体改动。
2. **失败方向无法保留**。被否定的假设往往在后续重构中被覆盖，负面结果丢失。

worktree 隔离后，每个方向有独立的代码、独立的提交历史、独立的结果目录，可并行
推进且互不污染。

## 数据共享（关键）

语料与缓存体积大（`data/` 52MB）且许可受限，不复制。每个 worktree 通过
**目录联接（junction）** 指向主仓的 `data/`：

```bash
git worktree add -b exp/<name> .wt/<name>
powershell -NoProfile -Command "New-Item -ItemType Junction -Path '<abs>\.wt\<name>\data' -Target '<abs>\data'"
```

已验证：离线评测**只读** `data/`，不写回（`evaluate_hgnn` 前后 mtime 无变化）。
因此多方向并行读取是安全的。**唯一约束：不得在 worktree 内写 `data/`。**
新结果一律写到各 worktree 的 `experiments/` 下。

## 第一代：四个方向

第一代的目标是**独立检验四条已有线索**，其中两条来自与本项目架构相似但基质不同
的外部系统的对照分析（见主仓 `效果对比.md`）。

| 分支 | 方向 | 检验的核心问题 | 状态 |
|---|---|---|---|
| `exp/dynamics` | 算子动力学 | 无源项的 `M=½(I+S)` 收敛到分量共识（分量内余弦=1.000），加源项后是否打破 flat/HGNN 平局？"信号来自 n 元性而非层级"的结论是否成立？ | 运行中 |
| `exp/source` | 特征口径一致性 | `training.py` 与 `retrieval.py` 对 `F_LLM_*` 降级边的 `type` 特征给出 1.0 vs 0.0。§6.2 的 +4.5pp 训练增益是否部分来自此口径差？ | 运行中 |
| `exp/omega` | 查询侧可观测泛函 | 实现 Ω（只读查询、不读候选），检验"低 Ω 预测级联通路的 0.042 失效" | 运行中 |
| `exp/degrade` | 降级来源可靠度通道 | 不丢弃 `F_LLM_*` 候选、但给其封顶可靠度，能否让类型约束终于影响 P1 而不损失召回？ | 运行中 |

### 方向来源说明

- `dynamics` 起于一个已验证的数学事实：现有 `_conv` 是**无源项扩散**，行和恰为
  1.0，迭代收敛到连通分量的平稳分布。实测 500 轮后分量内平均余弦 = 1.000000
  （即同分量节点向量恒等），使 `metaphor_coherence` 退化为连通性指示器。
- `source` 起于一处**已复现的代码不一致**（实测 `[...,1.0,...]` vs `[...,0.0,...]`）。
- `omega` / `degrade` 起于与外部系统的对照：前者借鉴"查询侧可观测标量统一授权
  结构证据排序权限"的机制，后者借鉴"降级来源给独立封顶可靠度通道而非丢弃候选"
  的机制。**只借机制，不借基质**——外部系统的守恒传输/双尺度场依赖 Tag 间传输率
  与"实际承载流量"观测量，本项目没有该变量，不引入。

## 演化规则（代际推进）

每个方向返回后，按下列规则决定是否进入下一代：

1. **结论必须有精确数字**，且给出可复现命令。无数字的方向不进入下一代。
2. **负面结果同样是一等产出**。被证伪的假设写入 `实验结论汇总.md`，不删除分支。
3. **存活判据**：改动必须在不破坏 116 项单测的前提下，移动至少一个被上报指标，
   或推翻/条件化一个已有结论。仅"代码更优雅"不足以进入下一代。
4. **交叉验证**：若两个方向的改动都触及同一函数（如 `type` 特征），下一代必须
   在合并后的基线上重测，避免各自单测时好看、合并后抵消。
5. **合并顺序**：先合并**修正已上报数字**的方向（`source` 类），再合并**新增机制**
   的方向（`omega`/`degrade` 类），最后合并**改变数学性质**的方向（`dynamics` 类），
   因为后者会改变前两者的基线。
