## 0. 结论先行（TL;DR）

| 待检命题 | 裁决 | 关键数字 |
|---|---|---|
| L3 级联构造缺陷真实存在 | ✅ **成立，精确复现** | 758 级联中 **752（99.2%）** 成员共享单一目标域；规模 median=**1**、mean=2.91、max=55；**412（54.4%）** 是单例 |
| 根因定位 | ✅ **三处同规则 + 一处运行时兜底** | `ontology_clean.py:145-153` / `llm_ontology.py:197-233`（按目标域打包）+ `builder.py:167-186`（按目标域补孤儿） |
| 缺陷影响检索指标 | ❌ **否，度量中性** | 换任意构造规则，语义超图通路 MRR 恒 **0.5025**（人工加权）/ **0.5463–0.5570**（训练后）；A6 恒 **0.783/0.095**；H4 配对判别恒 **0.960**（flat 亦 0.960） |
| 级联层对指标**完全**无影响 | ❌ **不是** —— 有一个非零通道 | 影响来自 `cascade_id` 的**存在性**（非空），不是分组质量：`struct = 0.5·len(ground) + 0.5·[cascade_id 非空]`（`retrieval.py:73`）。全消融后人工加权 MRR **0.5025 → 0.4681（−0.034）** |
| 级联的**分组质量**影响指标 | ❌ **确证中性** | 「本体级联」「source 级联」「全单例级联（唯一 id，结构上最退化）」三者 MRR **逐位相同 0.5025** |
| L2/L3 覆盖率 100% 归因 | ⚠️ **不是本体级联的功劳，是兜底函数的功劳** | 关掉 `_ensure_cascades` 后覆盖率 **1.000 → 0.767**（**跌破 >0.85 门槛**） |
| 替代规则能否保住覆盖率 | ✅ **能** | 任何「本体级联非空 + 兜底开启」组合都是 **1.000**；`source` 规则 + 兜底同样是 **1.000** |
| Ω_N 是否复活 | ✅ **复活（部分）** | Ω_N>0 占比 **1.4% → 14.8%**（source）/ **18.0%**（source_type）；Ω_N mean 0.0142 → 0.1480 |
| Ω 是否获得超出 1-bit 的信息 | ❌ **Ω 本身仍然没有**；但**原始涌现计数**有 | ρ(Ω, n_seed) 仍 **0.9949–0.9954**；「Ω>0 ⟺ n_seed≥1」一致率仍 **1.0000**。但 Ω>0 子集内 `n_emergent` 对「级联通路非空」的 AUC = **0.836 [0.759, 0.909]**（source）vs Ω 的 **0.654 [0.551, 0.750]** |
| 默认是否应改 | ⚠️ **不应改默认**（见 §8） | 改默认不带来任何指标收益，却要重跑全部已上报数字 + 重新沉淀本体；应把规则**保留为可选项**并把 §6.3 的表述收紧 |

**一句话**：缺陷是真的、根因是清晰的、修法是可用的；但**级联层对已上报指标是度量中性的** —— 唯一真实的因果通道是「`cascade_id` 是否为空」这一个二值条件，与级联怎么分组无关。这**证实并强化**了论文 §6.3 已有的表述（「层级价值应表述为检索组织与可解释性，而非检测/排序信号本身」），并且给出了一个此前没有的**量化边界**：级联层的贡献上界 = 人工加权 MRR +0.034（struct 特征），且这个贡献**不随级联质量变化**。同时发现一处**覆盖率的归因错误**：已上报的「L2/L3 覆盖率 100%」是 `builder._ensure_cascades` 的产物，不是级联本体的产物。

## 1. 缺陷的精确复现

### 1.1 测量口径

测量对象是**生产口径的本体**（`ontology_clean._build_variant` 组装，即 `evaluate_fullcorpus` / `evaluate_llmgold` / `exp1_omega` 实际用的那一个），不是裸 JSON：

- `ontology_default.json`：2177 框架 / 733 级联
- `+ build_metanet_ontology()`（25 个 MetaNet/手工种子框架）+ `build_bootstrap_ontology()` 底座
- 组装后：**2209 框架 / 758 级联**（与 `exp/omega` 的实验口径一致）

脚本：`experiments/gen2/exp_g2_1_defect.py` → `exp_g2_1_defect.json`

### 1.2 级联规模直方图（758 个级联）

| size | 级联数 | | size | 级联数 | | size | 级联数 |
|---:|---:|---|---:|---:|---|---:|---:|
| **1** | **412** | | 7 | 9 | | 22 | 2 |
| 2 | 134 | | 8 | 6 | | 24 | 2 |

- **median = 1**，mean = 2.91，max = 55
- **单例级联 412 / 758 = 54.4%**
- 规模 ≤2 的级联占 546 / 758 = **72.0%**

### 1.3 每级联 distinct target_domain 数

| 目标域数 | 级联数 | 占比 |
|---:|---:|---:|
| **1** | **752** | **99.2%** |
| 2 | 5 | 0.7% |
| 3 | 1 | 0.1% |

那 6 个跨目标域级联**全部**是手工种子（`C_ARG_WAR`、`C_TIME_MONEY`、`C_PROGRESS_JOURNEY`、`C_LIFE_MACHINE`、`C_ANGER_HEAT`、`C_MIND_CONTAINER`），最大者 3 个成员。733 个 `C_LLM_*` 级联中**没有一个是跨目标域的**（定义使然）。

### 1.4 L1 超边的级联归属（真实建图：CCL2018 1100 句 → 110 伪文档 → 856 条 L1 边）

| 归属 | 边数 | 占比 |
|---|---:|---:|
| 落在**单例**级联 | 135 | 15.8% |
| 落在多成员级联 | 533 | 62.3% |
| **无级联归属** | 188 | **22.0%** |

**关键机制发现**：那 188 条无归属的边，`builder._ensure_cascades` 会在 `shg.cascades` 里补出 188 个 `C_ADHOC_*` 级联（110 次 build 累计 distinct id = 399），**但这些级联不回写 `edge.cascade_id`** —— 实测 `edge.cascade_id` 以 `C_ADHOC_` 开头的边数 = **0**。所以：

- `graph_health.cascade_coverage` 看的是 `shg.cascades` → **1.000**
- 检索/训练特征看的 `edge.cascade_id` → **只有 78.0% 非空**

这是同一个词（「级联覆盖率」）在两个口径下的不同数字，此前未区分。

### 1.5 根因（file:line）

级联按**目标域**打包，在**三处独立实现**（同一规则，无单一实现来源），加**一处运行时兜底**（同规则）：

| 位置 | 内容 |
|---|---|
| `metaphor_graph/llm_ontology.py:197` | `by_target: Dict[str, List[str]] = defaultdict(list)` |
| `metaphor_graph/llm_ontology.py:223` | `by_target[t].append(fid)` |
| `metaphor_graph/llm_ontology.py:226-233` | `for t, fids in by_target.items(): cascades.append(CascadeSpec(id=_stable_id("C_LLM", t), ...))` |
| `metaphor_graph/ontology_clean.py:145-153` | `rebuild_cascades()`：「按目标域重建级联（与 llm_ontology.build_specs 同规则、同稳定 id）」 |
| `metaphor_graph/builder.py:167-170`（原 `HEAD`） | `for f in orphans: tgt = mem[0].target_domain ...; groups[tgt].append(f.id)` |
| `metaphor_graph/builder.py:173`（原 `HEAD`） | `cid = "C_ADHOC_" + hashlib.md5(tgt.encode("utf-8")).hexdigest()[:8]` |

**因果链**：按目标域分组 ⇒ 一个级联的所有成员框架共享 `target_domain` ⇒ `retrieval.py:130-139` 的级联扩展段

```python
for fid in cas.member_frames:
    fs = self.ont.get_frame(fid)
    if fs:
        targets.add(fs.target_domain)   # ← 永远等于 c.target_domain，集合不增长
        targets.add(fs.source_domain)
```

拿不到任何**新**目标域 ⇒ 级联退化成「框架别名」⇒ 涌现（emergence）恒为空集 ⇒ `observability.activated_structure` 的 `emergent = expanded - direct` 恒为 `∅` ⇒ Ω_N ≡ 0。

**直接量化**（`exp_g2_2_consumers.py`）：单条 L1 边经级联能多拿到的目标域数

| 新增目标域数 | 边数 |
|---:|---:|
| +0 | **827 / 856（96.6%）** |
| +1 | 26 |
| +2 | 3 |

mean = 0.037。**96.6% 的边经级联扩展一无所获。**

## 2. 级联层在检索期到底被谁消费？

`exp_g2_2_consumers.py` 的逐条审计（代码级，非推断）：

| 消费点 | 位置 | 读的是 | 对分组质量敏感？ |
|---|---|---|---|
| 跨域检索的目标域扩展 | `retrieval.py:130-139` | `ont.get_cascade_spec(cid).member_frames` | **是**（但只在跨目标域时才产生差异） |
| 语义回退粗筛 | `retrieval.py:150-166` | `ont.cascades` 的描述向量 | 是（仅 `semantic_fallback=True`，默认关闭） |
| `struct` 特征 | `retrieval.py:73`、`training.py:76/107/544/628` | `e.cascade_id` **是否为空** | **否**（只看二值） |
| `same_cascade` 特征 | `training.py:87-89/116` | `e.cascade_id` **相等性** | **是** |
| 训练正样本构造 | `training.py:333-338` | `e.cascade_id` 分组 | 是（`positive_mode="cascade"`，有泄漏，仅连通性用） |
| HGNN 跨层传播 | `hgnn.py:36-84` | `shg.cascades`（含 `C_ADHOC_*`） | 是 |
| Ω_N | `observability.py:143-161` | `ont.get_cascade` + `get_cascade_spec` | **是** |
| 图健康度覆盖率 | `health.py:123-130` | `shg.cascades` | 是（但被兜底恒置 1.0） |

**结论**：级联层的**分组质量**只通过两条路径可能影响指标 —— `same_cascade` 特征、HGNN 跨层传播。两条都在 §3 被实测为**不敏感**。

### 2.1 机制定位：影响来自「存在性」而非「结构」

`exp_g2_5_mechanism.py` 用四个人工构造的对照把因果链拆开（同一批 632 条改写查询）：

| 变体 | `cascade_id` 非空 | struct 均值 | same_cascade 配对命中 | 其中同框架占比 | 人工加权 MRR |
|---|---:|---:|---:|---:|---:|
| A 本体级联(json)+兜底 | 668/856 = 0.780 | 1.3966 | 29 | 0.517 | **0.5025** |
| B 本体级联(json)，兜底关 | 668/856 = 0.780 | 1.3966 | 29 | 0.517 | **0.5025** |
| C source 级联，兜底关 | 668/856 = 0.780 | 1.3966 | **76** | **0.197** | **0.5025** |
| E **全单例级联（唯一 id，结构最退化但非空）** | 668/856 = 0.780 | 1.3966 | 15 | **1.000** | **0.5025** |
| D 无级联 | 0/849 = 0.000 | **1.0094** | 0 | — | **0.4681** |

**读法**：
- A = B = C = E 的 MRR **逐位相同**。C 的 `same_cascade` 配对命中从 29 涨到 76（增量信息从 48.3% 涨到 80.3%），E 把它压到 15 且 100% 与 `same_frame` 重合 —— **指标一点没动**。
- 唯一变化的是 D（`cascade_id` 全空）：`struct` 均值掉 0.3872，MRR 掉 0.0344。
- 即：`same_cascade` 特征在这套排序器里**权重被训到 −0.013**（`evaluate_retrieval` 打印的权重），人工加权里它压根不在公式里（`evaluate_retrieval.py:186-187` 只用 `f[0..3]` = sem/struct/clue/type）。**`same_cascade` 从未参与任何已上报指标。**

这解释了论文 A9（去角色特征）为何无差异 —— 不只是「角色信息可被同质 DDE 替代」，而是**角色特征在现状下几乎不携带独立信息**（`same_cascade` 有 51.7% 与 `same_frame` 重合，且二者权重都 ≈0）。

## 3. 替代构造规则与结构对照表

新增模块 `metaphor_graph/cascade_rules.py`，7 条规则（`RULE_JSON` = 默认，原样载入 JSON 级联，**与改动前逐位一致**）：

| 规则 | 语义 | 语言学/工程依据 |
|---|---|---|
| `json` | 原样载入本体 JSON 级联 | **默认**（改动前行为） |
| `target` | 按 `target_domain` 打包 | 现状规则（从 frames 重算，用于自检） |
| `source` | 按 `source_domain` 打包 | MetaNet 中大量级联是「同一源域、多个目标域」（JOURNEY 覆盖 LIFE/LOVE/CAREER） |
| `ground` | 按喻底集合 Jaccard ≥0.34 贪心聚合 | 级联 = 「**共同出现**的基础/一般隐喻打包」，共现载体就是喻底集合；与 `extended.py` 喻底交集判据同源 |
| `metanet` | 保留非 `C_LLM_*` 的种子级联，其余按 `source` 重组 | 分离「语言学来源级联」与「工程打包级联」 |
| `source_type` | 按推断的 `source_type` 打包 | 最粗对照（16 个喻体大类） |
| `none` | 不建级联 | L3 消融 |

### 3.1 结构对照表（生产本体 2209 框架）

| 规则 | 级联数 | size median | size mean | size max | **跨目标域率** | **单例率** | 跨源域级联数 | 框架覆盖 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `json`（默认/基线） | 758 | **1.0** | 2.91 | 55 | **0.008** | **0.544** | 343 | 1.000 |
| `target` | 748 | 1.0 | 2.95 | 55 | **0.000** | 0.539 | 344 | 1.000 |
| `source` | 543 | **2.0** | 4.07 | 75 | **0.516** | 0.484 | 0 | 1.000 |
| `ground` | 1663 | 1.0 | 1.33 | 14 | 0.174 | **0.818** | 218 | 1.000 |
| `metanet` | 560 | 2.0 | 3.94 | 75 | 0.507 | 0.493 | 3 | 1.000 |
| `source_type` | 16 | 81.0 | 138.06 | 794 | **0.938** | 0.062 | 15 | 1.000 |

**`source` 规则把跨目标域率从 0.8% 提到 51.6%**（64 倍），中位规模 1 → 2，同时保持框架覆盖 100%。`ground` 规则反而更碎（单例率 0.818），因为喻底词表太稀疏（2367 个不同喻底词，只有 543 个出现在 ≥2 个框架里）—— 这是一个**负面结果**，值得记录：喻底共现在当前本体规模下不足以支撑聚合。

## 5. L2/L3 覆盖率归因（关键发现）

`exp_g2_6_coverage.py`：本体级联规则 × 孤儿打包规则的完整矩阵（110 伪文档，取 min/mean）。

|---|---|---:|---:|:---:|---:|---:|---:|---:|
| `json` | `target`（**生产现状**） | **1.0000** | 1.0000 | ✅ | 188 | 1 | 1 | 0 |
| `json` | `source` | 1.0000 | 1.0000 | ✅ | 188 | 1 | 1 | 0 |
| `json` | `ground` | 1.0000 | 1.0000 | ✅ | 188 | 1 | 1 | 0 |
| `json` | `source_type` | 1.0000 | 1.0000 | ✅ | 89 | **2** | **6** | **152** |
| `json` | **`none`** | **0.3333** | **0.7672** | **❌** | 0 | — | — | 0 |
| `source` | `target` | 1.0000 | 1.0000 | ✅ | 188 | 1 | 1 | 0 |
| `source` | `none` | 0.3333 | 0.7672 | ❌ | 0 | — | — | 0 |
| `source_type` | `source_type` | 1.0000 | 1.0000 | ✅ | 89 | 2 | 6 | 152 |

**三个结论**：

1. **覆盖率 100% 由 `_ensure_cascades` 保证，不由本体级联保证。** 关掉它 → **0.767，跌破 >0.85 门槛**。这意味着论文摘要(2) 与 §5.2 的「cascade 查表构建将 L2/L3 覆盖率提升至 100%」（`论文初稿.md:23`、`:189`、`:399`）在归因上**不准确**：本体级联查表单独贡献 **0.767**，`builder._ensure_cascades` 的**目标域兜底打包**贡献剩下的 **0.233**。二者都是「查表式」的（零 LLM 调用），所以**成本主张（H2，~20 次/千边 vs ~187 次）不受影响**，但**覆盖率主张的归属需要修正**。

2. **换任何替代本体规则都不会让覆盖率崩掉** —— 因为兜底函数会把缺口全部补上。所以「改构造规则会不会击穿 >0.85」这个担心的答案是**不会**（前提是兜底开启）。

3. **`source_type` 是唯一让补出来的 ad-hoc 级联有真实规模的规则**（median 2、max 6、152 条边落进 size≥2 的 ad-hoc 级联）。若要让 L3 层在**运行时**（`shg.cascades`）也具备组织力，这是最省的改法（改一行 `orphan_cascade_rule=`）。

## 6. Ω_N 是否复活，Ω 是否获得信息

`exp_g2_7_omega.py` / `exp_g2_8_omega_attrib.py` / `exp_g2_9_conditional.py`，同一批 635 条改写查询（红线过滤后）。

### 6.1 Ω_N 复活判定

| 规则 | Ω_N>0 占比 | Ω_N mean | ρ(Ω, n_seed) | 「Ω>0 ⟺ n_seed≥1」一致率 | AUC(Ω→通路非空) 全样本 | 去 Ω=0 后 |
|---|---:|---:|---:|---:|---:|---:|
| `json`（上一轮口径） | **0.014** | 0.0142 | 0.9950 | **1.0000** | 0.9543 | 0.5933 |
| `source` | **0.148** | 0.1480 | 0.9954 | **1.0000** | 0.9719 | 0.6539 |
| `metanet` | 0.135 | 0.1354 | 0.9949 | 1.0000 | 0.9648 | 0.6248 |
| `ground` | 0.036 | 0.0339 | 0.9945 | 1.0000 | 0.9420 | 0.5688 |
| `source_type` | **0.180** | 0.1795 | 0.9954 | 1.0000 | 0.9982 | **0.8387** |
| `none` | 0.000 | 0.0000 | 0.9953 | 1.0000 | 0.9437 | 0.5952 |

- **Ω_N 复活（部分）**：1.4% → 14.8%（`source`）/ 18.0%（`source_type`）。复现了 `exp/omega` 的 0.0142（精确一致）。
- **但 Ω 本身仍是 1-bit 指示器**：ρ(Ω, n_seed) 稳定在 **0.9945–0.9954**（上一轮 0.9949），「Ω>0 ⟺ n_seed≥1」逐条一致率仍 **100%**。
- 门控漏检：Ω 门控 0 条 / n_seed 判据 0 条（全部规则）—— **门控等价性不变**。

**为什么 Ω_N 复活了 Ω 却没变？** Ω = (Ω_E·Ω_N·Ω_F)^(1/3) × 完备度。Ω_N 从 0 涨到 0.148 时，几何平均的三次根把它的影响压到约 5 倍稀释：`(Ω_E·0.148·Ω_F)^(1/3)` 相对 `(Ω_E·1e-3·Ω_F)^(1/3)` 只涨 5.3 倍，而 ε 下界 1e-3 本来就在托底。实测 Ω mean 从 0.0027（`target`）→ 0.0231（`source`），**涨了 8.6 倍**，但相对「触发词命中数」的秩相关几乎不动 —— 因为 Ω 的**序**仍由「有没有命中触发词」的 0/非 0 分界主导（82.0% 的样本 Ω=0，全部规则一致）。

### 6.2 但「原始涌现计数」确实携带信息（新发现）

`exp_g2_9` 在 **n_seed 固定的层内**检验（避免 n_seed 代理效应），bootstrap 95% CI（2000 次重采样）：

| 规则 | 层内加权 AUC(n_emergent) | 层内加权 AUC(n_frames) | 层内加权 AUC(Ω) | ρ(n_emergent, n_seed) |
|---|---:|---:|---:|---:|
| `json` | 0.487 | 0.596 | 0.592 | 0.117 (p=0.215) |
| `source` | **0.833** | 0.495 | 0.643 | 0.103 (p=0.275) |
| `metanet` | 0.792 | 0.527 | 0.613 | 0.113 (p=0.232) |
| `source_type` | **0.874** | 0.583 | 0.819 | 0.221 (p=0.018) |

合并（不分层）AUC，`source` 规则，n=114：

```
n_emergent  0.8357 [0.7585, 0.9090]
Ω           0.6539 [0.5510, 0.7502]     ← CI 不重叠
n_frames    0.4950                        ← 反向，无信息
```

**这是与上一轮不同的结论**：上一轮 Ω_N 恒为 0，无从谈起；现在**涌现目标域的原始计数 `n_emergent`** 在 Ω>0 子集内对「级联通路是否非空」有 AUC **0.836 [0.759, 0.909]**，显著高于 Ω 的 0.654 [0.551, 0.750]（CI 不重叠），且与 n_seed 的秩相关仅 0.103（p=0.275，不显著）—— **它不是 n_seed 的代理**。同时 `n_frames`（点亮的框架数）在同一子集内 AUC 仅 0.495（无信息），说明这个信号确实来自**跨域扩展**，不是「点亮了多少结构」。

**但必须诚实标注三条边界**：
1. 这是 **Ω>0 子集（n=114）** 内的结论，样本小、CI 宽（[0.759, 0.909]）。
2. 它衡量的是「预测级联通路非空」这个**中间量**，不是端到端检索质量。§4 已证级联通路的 Recall@10 只有 0.042–0.131，所以「更好地预测一个弱通路是否非空」的工程价值有限。
3. Ω 的**合成方式**（几何平均 + ε 下界 + 完备度因子）把 Ω_N 的信息稀释掉了 —— 这是 Ω 的设计问题，不是级联层的问题。若要利用这个信号，应把 Ω_N 作为**独立可观测量**暴露，而不是塞进 Ω 的几何平均。

## 8. 诚实裁决

### 8.1 级联层是度量中性还是度量相关？

**分级裁决**：

| 问题 | 裁决 |
|---|---|
| 级联的**分组质量**影响任何已上报指标吗？ | **不影响。确证中性。** 人工加权 MRR 在「本体级联 / source 级联 / 全单例级联（结构上最退化）」下**逐位相同 0.5025**；A6 逐位相同 0.783/0.095；H4 逐位相同；A7/A9/A5/H3 逐字不变。 |
| 级联层**存在**影响指标吗？ | **影响，但很小且有明确上界。** 全消融（`cascade_id` 全空）→ 人工加权 MRR **0.5025 → 0.4681（−0.034）**，来源是 `struct` 特征里的 `+0.5 if e.cascade_id` 这一项。**这就是级联层对检索指标的全部贡献上界。** |
| 级联层影响什么？ | ① **触发词级联通路的 Recall**（0.042 → 0.076/0.131，论文 §6.1 的核心数字之一）；② **Ω_N**（0 → 0.148/0.180）；③ **`n_emergent` 的判别力**（AUC 0.49 → 0.83/0.87）；④ **检索组织与可解释性**（论文 §6.3 已表述）。 |
| 论文 §6.3 的表述需要改吗？ | **不需要改，但可以收紧。** 原文「层级（L2/L3）的价值应表述为**检索组织与可解释性**（级联粗筛、框架一致性约束），而非检测/排序信号本身」—— 本报告**证实**了它，并补上量化边界：级联层对排序/检测指标的最大贡献是 **struct 特征 +0.034 MRR**（且与分组质量无关），而「级联粗筛」这条在**当前本体下几乎不成立**（96.6% 的边经级联扩展取不到新目标域），换成 `source` 规则后才部分成立（通路 Recall 0.042 → 0.076）。 |
| 论文摘要(2)/§5.2 的「覆盖率 100%」需要改吗？ | **需要。** 归因错误：100% 由 `builder._ensure_cascades` 的**目标域兜底打包**保证，本体级联查表单独只贡献 **0.767**（`论文初稿.md:23/189/399`）。成本主张（查表 ~20 次/千边 vs 聚类 ~187 次）**不受影响**（兜底也是查表式、零 LLM 调用），但「cascade 查表构建将 L2/L3 覆盖率提升至 100%」应改为「**级联查表 + 目标域兜底打包**将 L2/L3 覆盖率提升至 100%（查表单独贡献 76.7%）」。 |

### 8.2 默认是否应该改？

**裁决：不应改默认，应保留为可选项。** 理由：

1. **没有指标收益。** 语义超图通路（论文的主要通路，Recall 1.000）对级联规则完全免疫；A6/H4/A7/A9 全部不变。唯一变动的是触发词级联通路的 Recall（0.042 → 0.076/0.131），但该通路在论文里是**被论证为失效的对照**，不是贡献点 —— 把它从 0.042 提到 0.131 **不改变任何结论**，反而需要重跑全部已上报数字并重新沉淀本体。
2. **成本高。** 改本体级联规则 = 重新生成 `ontology_default.json`（733 个 `C_LLM_*` 级联的 id 全部变化）→ 影响所有依赖稳定 id 的缓存键、导出（`export_shg.json/cypher`）、Neo4j 约束、双语资源对齐。
3. **`source` 规则本身有代价。** 它把 543 个级联的组织粒度从「748 个目标域」改成「543 个源域」，跨源域级联数降为 **0** —— 即彻底放弃「同一目标域下的多个源域打包」这一语言学结构（如「时间」目标域下 TIME_IS_MONEY / TIME_IS_RESOURCE）。这与 cascade 理论并不完全一致，是**用一类结构换另一类**，不是纯粹的改进。
4. **真正该改的是运行时兜底规则。** `orphan_cascade_rule="source_type"` 是**一行改动、零风险、不触碰本体**，却让补出来的 ad-hoc 级联从「size 恒为 1」（188 个、0 条边落入 size≥2 级联）变成「median 2 / max 6 / 152 条边落入 size≥2 级联」，覆盖率仍为 1.000。若要让 L3 层在**运行时**（`shg.cascades`、HGNN 跨层传播）具备真实组织力，这是最优改法。**但仍不建议改默认** —— 因为 HGNN 跨层传播的指标（P4-A/H4）对级联质量实测不敏感，改了也不动数字，只会增加一次全量重跑。

**建议**：把默认保持 `json`/`target`（已上报口径），把 `cascade_rules` 作为**可复现的对照工具**留在代码里（已实现），并在论文里把 §6.1 的覆盖率归因与 §6.3 的量化边界补上。若后续要做「L3 组织力」的正面论证，应走 `orphan_cascade_rule="source_type"` 这条**不动本体**的路径。

### 8.3 本报告没有证明什么

- **没有证明**「修好级联构造能提升端到端检索」。级联通路的 Recall 上限（`source_type`，最粗的规则）只有 0.131，而语义超图通路是 1.000 —— 级联通路的问题不止是分组，还有触发词覆盖（82.0% 的改写查询 Ω=0，即一个触发词都没命中，与级联规则无关）。
- **没有证明** `n_emergent` 的 AUC 0.836 能转化为工程收益。它预测的是一个弱通路是否非空，n=114、CI [0.759, 0.909]，且未做多重比较校正（4 条规则 × 6 个指标）。
- **没有证明** `ground` 规则的语言学正当性。它在本体上更碎（单例率 0.818），说明当前喻底词表（2367 个词，仅 543 个出现在 ≥2 个框架）不足以支撑「共现喻底」判据 —— 这是负面结果。
