## 1. 前人结论的复现（全部逐位命中）

### 1.1 gen1：`type` 的三元不一致

`experiments/gen3/exp_g3_1_audit.py`，110 个伪文档各训一个排序器后取均值：

| 量 | gen1 报告 | gen3 实测 | 一致？ |
|---|---|---|---|
| `type` 单特征 AUC | 0.4973 | **0.4973** | ✅ 逐位 |
| `type` 学到权重 | +0.0487 | **+0.0487** | ✅ 逐位 |
| `type` 人工硬编码权重 | 0.20 | **0.20** | ✅ |
| `sem` AUC / 权重 | 0.9329 / +0.6911 | **0.9329 / +0.6911** | ✅ 逐位 |
| `clue` AUC / 权重 | 0.9985 / +1.2543 | **0.9985 / +1.2543** | ✅ 逐位 |
| `struct` AUC / 权重 | 0.5036 / +0.0195 | **0.5036 / +0.0195** | ✅ 逐位 |
| `same_frame` AUC / 权重 | 0.5975 / +0.1953 | **0.5975 / +0.1953** | ✅ 逐位 |
| `same_cascade` AUC / 权重 | 0.5975 / +0.1958 | **0.5975 / +0.1958** | ✅ 逐位 |
| `ground_jaccard` AUC / 权重 | 0.7437 / +0.4965 | **0.7437 / +0.4965** | ✅ 逐位 |

**但这里有一个必须纠正的口径问题（本代的关键发现之一）**：

> gen1 的 `0.4973` 来自 `probe_learned_type_weight.py`，它调用的是
> `feature_auc(ds)`，其中 `ds` 是 **`build_training_set` 造出的自监督训练集**
> （正样本 = chunk 实际产出的边），**不是评测候选对上的 AUC**。
>
> 在**评测**候选对上（632 条 LLM 改写查询 × 全部候选，n=5485 对），
> `type` 的配对 AUC 是 **0.5249 [0.5092, 0.5401]** —— CI **不覆盖 0.5**。
>
> 所以准确的表述是：**「`type` 在自监督训练集上与标签无关（AUC 0.497），但在评测金标上是显著弱正向的（AUC 0.525）」**。
> 这两个数字不矛盾（训练集的正样本是「chunk 产出的边」，评测金标是「LLM 判定相关的 chunk」），
> 但把它们混为一谈会得出「`type` 是死维」这个**过强的结论**。
> gen1 报告 §4 的诚实标注已经说对了方向（「`type` 与金标弱正相关但 AUC 仅 0.497」），
> 只是那个 0.497 不是它以为的那个 AUC。

### 1.2 gen2：`same_cascade` / `same_frame` 冗余

`exp_g2_5_mechanism.py` 的口径是「L1 边两两配对中 `same_cascade` 命中者，同框架的比例」：

```
L1 边数 856 ｜ 有 cascade_id 668 = 78.0%
same_cascade 配对命中 29 ｜ 其中同框架 15
→ same_cascade ⇒ same_frame 比例 = 51.7%          （gen2 报告 0.517）✅ 逐位
```

另一口径（**评测候选对上**，本代新增）：
```
same_frame 命中 16 ｜ same_cascade 命中 25 ｜ 同时命中 16
→ same_cascade 命中中同框架比例 = 64.0% ｜ Jaccard = 0.640
```
两个口径都报，因为前者是「图的属性」，后者是「排序器实际看到的东西」。

### 2.1 表 1 —— 单特征 AUC（两种口径）

### 2.5 表 5 —— 裁决（规则预先声明，不事后调参）

裁决规则：
- `dead`：配对 AUC 的 95% CI 覆盖 0.5 **且** |配对 AUC − 0.5| < 0.02
- `harmful`：配对 AUC < 0.5 **且** CI 上界 < 0.5
- `useful`：CI 下界 > 0.5 **且** |配对 AUC − 0.5| ≥ 0.02（显著且非平凡）
- `weak`：CI 下界 > 0.5 **但** |配对 AUC − 0.5| < 0.02（显著但幅度小）
- `redundant`：与某一维的秩相关 ≥ 0.8 或二值重叠 Jaccard ≥ 0.8

| 特征 | 配对 AUC | 裁决 | 说明 |
|---|---:|---|---|
| `sem` | 0.6277 | **useful** | 唯一有实质判别力的维（幅度 +0.128） |
| `ground_jaccard` | 0.5300 | **useful（幅度小）** | 幅度 +0.030；与角色三维高度共线 |
| `type` | 0.5249 | **useful（幅度小）+ redundant(struct)** | **不是死维**；与 `struct` 二值重叠 1.000 |
| `struct` | 0.5197 | **weak + redundant(type)** | 幅度 +0.020；85.1% 饱和为常数 1.0 |
| `clue` | 0.5087 | **weak + redundant(same_frame/same_cascade/ground_jaccard)** | 评测集上 99.4% 为 0（改写查询已切断捷径） |
| `same_cascade` | 0.5070 | **weak + redundant(clue/same_frame/ground_jaccard)** | 文本锚点上 AUC = 0.5011（纯随机） |
| `same_frame` | 0.5053 | **weak + redundant(clue/same_cascade/ground_jaccard)** | 文本锚点上 AUC = 0.5000（纯随机） |

**没有任何一维被判为 `dead` 或 `harmful`。** 这是与 gen1 叙述不同的地方，且是可复算的。

> 诚实标注：`useful` / `weak` 的分界（幅度 0.02）是**本报告预先选定的**，不是行业标准。
> 若把门槛降到 0.01，则 7 维全部为 `useful`；升到 0.03 则只剩 `sem` 与 `ground_jaccard`。
> 真正稳健的结论只有两条：**① 只有 `sem` 的幅度值得一提（0.628）；
> ② 其余 6 维的 CI 都不含 0.5，但幅度都在 0.02 上下，实务价值有限。**

## 4. 指标批判：金标构造混杂的量化

### 4.1 三个缺陷（全部可复现）

**缺陷 1 —— 候选池太小，Hits@10 平凡饱和**

```
候选 chunk 池：min=2  median=7  max=10  mean=7.03
池 ≤ 10 的查询占比 = 100.0%   → Hits@10 在 100% 的查询上平凡为 1.000
池 ≤ 3 的查询占比 = 2.2%
随机排序（均匀）的期望 MRR@10 = 0.2622   ← 指标的**真实地板**，不是 0
完美排序 MRR = 1.0，可用动态范围只有 0.738
```

已上报的「Hits@10 = 1.000」不是排序完美的证据，是**池只有 7 个 chunk** 的算术必然。

**缺陷 2 —— 「LLM 非构造金标」仍然 100% 锚定在产出 chunk 上**

```
LLM 认可产出边相关        : 612/632 = 96.8%
产出 chunk ∈ LLM 金标     : 632/632 = 100.0%   ← 锚点没有被移除
LLM 金标恰好 == {产出 chunk}: 619/632 = 97.9%   ← 97.9% 只有唯一正确答案
LLM 金标 chunk 数         : median=1  max=3  mean=1.02
```

`evaluate_llmgold.py` 的文档字符串称 LLM 金标是「与抽取构造无关的独立金标」。
**实测不成立**：LLM 判定的作用是**过滤**（剔掉 3.2% 不认可的），不是**去锚**。
任务实质 = 「把产出这条边/这个 chunk 排到第一」。

**缺陷 3 —— 训练与评测同源**

自监督训练集的正样本是「该 chunk 实际抽出的边」（`_build_from_chunks`），
评测金标是「该 chunk 产出的边被 LLM 判为相关」。二者是**同一个 chunk**。
所以 `clue`（触发词命中）与 `sem` 在训练集上 AUC 高达 0.9985 / 0.9329 —— 这不是泄漏检测能抓的，
它是**训练目标与评测目标重合**。

### 4.2 三个协议的对照（构造锚点被逐步移除）

| 协议 | 说明 | M0 人工 | T7 训练后 | 训练增益 | n |
|---|---|---:|---:|---:|---:|
| **P1 已上报** | 金标含产出 chunk，池含产出 chunk | 0.4809 | 0.5447 | **+6.38pp** | 632 |
| **P2 去锚点** | 金标与池**双双剔除**产出 chunk | 0.6987 | 0.6923 | **−0.64pp** | **13** |
| P3 排除型金标 | 只保留「LLM 金标 ≠ {产出 chunk}」的查询 | 0.6987 | 0.6923 | −0.64pp [−0.0192,0.0000] p=0.72 | **13** |

**P2/P3 的 n = 13（占 632 的 2.1%）。样本量过小，不能作为「训练无增益」的证据 ——
但它足以证明「训练增益在无锚点条件下不再出现」。**

### 4.3 MRR 来源分解（决定性）

| 配置 | MRR(产出 chunk) | n | MRR(非产出金标 chunk) | n |
|---|---:|---:|---:|---:|
| M0 人工 | 0.4728 | 632 | 0.6987 | 13 |
| T7 训练后 | **0.5372** | 632 | 0.6923 | 13 |
| **Δ** | **+0.0644** | | **−0.0064** | |

**训练增益 +6.44pp 全部落在「产出 chunk」列；「非产出」列反而 −0.64pp。**
结合 §3.3（训练后 7 维 = 1 维 `sem`），完整因果链是：

> 训练器学到的是「把产出 chunk 排更前」。
> 而产出 chunk 就是产生该查询的 chunk —— 复读它靠的是 `sem`（查询改写后与原句的语义相似度），
> 不需要任何隐喻结构特征。
> **所谓「训练增益」= 一个正确的 `sem` 权重 × 一个锚在产出 chunk 上的金标。**

## 6. 诚实裁决

### 6.1 `type` 应该删除、替换还是保留？

**裁决：既不该「因为死维而删除」，也不该「因为有用而保留」——它对指标的影响不可测，删除是安全的、但收益也是不可证的。**

依据：
1. **`type` 不是死维。** 配对 AUC 0.5249 [0.5092,0.5401]，CI 不含 0.5。gen1 的 0.497 是训练集口径的误读（§1.1）。
2. **删掉 `type` 的效应不可测。** 自监督 +0.0028（CI 覆盖 0）、弱监督 +0.0102、真实句向量 +0.0065（p=0.077）。
   方向一致为正，但**没有一项显著**。
3. **换任何信号都没用。** 6 个候选替代信号（frame_support / frame_tier / cascade_size / n_emergent / frame_registered / ground_len）的 CI **全部覆盖 0**。
   其中 `n_emergent`（gen2 发现的对「级联通路口非空」AUC 0.836 的信号）在端到端排序上是 **−0.0013**。
   这印证了 gen2 自己的边界声明：「预测一个弱通路是否非空」的工程价值有限。
4. **`type` 与 `struct` 重叠 1.000**（二值），是同一个「有归属」事实的两种编码。

**建议**：
- **保留 `type` 维度**，但把人工加权里的 0.20 **改掉**（见 6.3）。
- 若要精简：**删 `type` 或删 `same_cascade` 都是安全的**（都不显著），但**不要声称因此获得了增益**。
- 论文中「新增 type 维度防污染」的主张应下调为：**「`type` 是弱正向信号（配对 AUC 0.525），但在本基准上与 `struct` 共线，且对排序指标的边际贡献不可测」**。

### 6.2 `same_cascade` 应该删除吗？

**裁决：可以删（无指标代价），但「冗余」这个理由是**部分**成立的。**

- 删掉后 Δ=+0.0017（CI 覆盖 0），真实句向量 +0.0028（p=0.13）—— **无代价**。
- 但 gen2 的 51.7% 是 **L1 边两两配对**口径；在**评测候选对**上是 **64.0%**，Jaccard 0.640。
  两个口径都不足以说「完全冗余」——`same_cascade` 确实携带 36–48% 的增量配对信息。
- 真正让它无用的是：**它在 97.6% 的查询（文本锚点）上 AUC = 0.5011，精确的随机**。
  与 `same_frame` 一样，只在 15 条边锚点查询上有效。
- 训练器给它的权重 +0.1958 与 `same_frame` 的 +0.1953 **几乎相等**，且两者在评测口径上秩相关 +0.993。

**建议**：保留（删除无收益），但把论文 A9 的表述从「角色信息可被同质 DDE 替代」收紧为
**「角色特征（`same_frame`/`same_cascade`）在 97.6% 的文本锚点查询上不携带排序信息（AUC 0.500/0.501），
其可测作用仅限 2.4% 的边锚点查询」**。

### 6.3 人工加权是错配的吗？

**✅ 是，而且这是本代最大的可操作发现。**

| 事实 | 数字 |
|---|---|
| 已上报人工加权 MRR@10 | 0.4809 |
| 人工权重改成与学到权重同比例 | **0.5496（+6.87pp，p=0.0000）** |
| 训练后 7 维 | 0.5447 |
| **人工（配对的权重）− 训练后** | **+0.0049 [−0.0089,+0.0184]，CI 覆盖 0** |

**错配清单**（人工权重 vs 原始空间有效权重 `w/sd` 归一）：

| 特征 | 人工 | 应为（学到的比例） | 错配 |
|---|---:|---:|---|
| `struct` | **0.250** | **0.005** | **高估 49×** ← 最大 |
| `type` | **0.200** | **0.011** | 高估 19× |
| `ground_jaccard` | 0.000 | 0.101 | 忽略 |
| `same_frame` | 0.000 | 0.045 | 忽略 |
| `same_cascade` | 0.000 | 0.045 | 忽略 |
| `sem` | 0.350 | 0.503 | 低估 1.4× |
| `clue` | 0.200 | 0.291 | 低估 1.5× |

**两个后果**：

1. **已上报的人工加权基线（0.4809）不是「合理的无训练基线」，是一个被配错权重的基线。**
   论文 §6.2 的「训练增益 +6.4pp」应改写为：**「训练增益主要来自权重校准：把人工权重
   按学到比例重配后，人工加权达到 0.5496，与训练后 0.5447 无显著差异（+0.49pp，CI 覆盖 0）。」**
2. **`struct` 比 `type` 错得更离谱，而前两代都把注意力放在 `type` 上。**
   建议论文与代码注释把「人工加权 0.35/0.25/0.20/0.20 是历史遗留的未校准超参」写明。

### 6.4 训练增益是真的吗？

**裁决：在 LLM 金标上是「≈0」（哈希口径）/「显著为负」（真实句向量口径）；在 fullcorpus by-construction 金标上是「+0.29pp」。三处都不是原来报告的 +6.4pp / +9.5pp。**

四条独立证据：
1. 人工权重调对后，训练增益 +0.49pp，CI 覆盖 0（§3.3）。
2. **1 维 `sem` = 训练后 7 维**（哈希口径 Δ=+0.0025，CI 覆盖 0）（§3.3）。
3. **真实句向量口径下，1 维 `sem` 显著优于训练后 7 维**（Δ=+1.76pp，p=0.003）（§3.4）。
4. MRR 来源分解：训练增益 +6.44pp 全部落在「产出 chunk」列，非产出列 −0.64pp（§4.3）。

**这不否定「可训练排序器」这个组件的工程价值**（它至少能自动校准权重，替代手工调参）。
它否定的是**「训练学到了隐喻结构信号」这个解释**。

### 6.5 本报告没有证明什么

  「人工配对的权重 = 训练后」本身不依赖最优性，只依赖「错配的幅度」）。

## 2. 诊断：Ω 的信号到底在哪一步丢的

这是本轮的科学核心。**核心假设（失败来自合成方式）被证伪**，
真正的元凶在**分量定义层**。

### 2.1 先否证「合成层」假说：2⁴ 开关全因子

`query_signal.compose()` 把 Ω 的四个合成设计选择做成**正交开关**：
`normalize`（分量除以 n_seed）、`floor`（ε 下界 vs 结构化丢弃）、
`use_completeness`（乘观测完备度）、`outer_zero`（无激活时严格为 0）。
16 种组合在 4 条级联规则上全跑（`exp_g3_1`）：

| 规则 | 16 种合成组合的 AUC 区间 | 极差 | Ω 实际值 |
|---|---|---:|---:|
| `json` | [0.5369, 0.6229] | 0.0860 | 0.5933 |
| `source` | [0.5289, 0.6546] | **0.1256** | 0.6539 |
| `metanet` | [0.5415, 0.6267] | 0.0852 | 0.6248 |
| `source_type` | [0.5185, 0.8387] | 0.3202 | 0.8387 |

**结论**：无论怎么拨这四个开关，AUC 都**到不了** `n_emergent` 本身的 0.836
（`source` 规则下最高 0.655）。**合成层不是元凶** —— 它最多能解释 0.126 的差异，
而待解释的差异是 0.836 − 0.654 = 0.182。特别是 `floor=False`（结构化丢弃，
即核心假设建议的修法）在 `source` 上**反而更差**（0.571 vs 0.654）。

### 2.2 定位元凶：分量定义层的 `min(1, ·)`

把「分量定义」与「合成算子」分成两层做完整因子分解（`exp_g3_2`）：
分量定义 4 档（`clip+div` = Ω 原口径 / `noclip+div` / `clip+nodiv` / `noclip+nodiv`）
× 合成算子 4 档（geo / arith / max / sum）× ε 下界 2 档 × 完备度 2 档 = **64 个变体**。

**效应分解（AUC 在 n_seed≥1 子集）**：

| 规则 | 64 组合总区间 | 固定 Ω 合成、只换**分量定义** | 固定 Ω 分量、只换**合成设置** |
|---|---|---|---|
| `json` | [0.5000, 0.6188] | [0.5933, 0.6087] 极差 0.0155 | [0.5000, 0.6149] 极差 0.1149 |
| `source` | [0.5000, **0.8483**] | [0.6539, **0.8176**] 极差 **0.1637** | [0.5000, 0.6539] 极差 0.1539 |

- 分量定义换成 `noclip+div` 后，**任意**合成算子都落在高区间
  （`source` 16 种全部在 **0.8061–0.8483**）—— 信号被完整找回；
- 合成设置无论怎么拨，**都留在 0.50–0.655** —— 信号找不回。

| clipE | clipN | divE | divN | AUC 子集 |
|---|---|---|---|---|
| 1 | **1** | 1 | 1 | **0.6539**（= Ω 原口径） |
| 1 | **1** | 0 | 0 | 0.6539 |
| **0** | 1 | 1 | 1 | 0.6544 |
| 1 | **0** | 1 | 1 | **0.8243** |
| **0** | **0** | 1 | 1 | 0.8176 |
| **0** | **0** | 0 | 0 | 0.8061 |

**唯一有实质影响的变量是 `clipN`**（Ω_N 的 `min(1,·)`）：clipN=1 → 0.6539；
clipN=0 → 0.806–0.824。`clipE`（Ω_E 的截断）与两个 `div` 的影响都在 ±0.005 内。

### 2.3 机制为什么是截断：档位塌陷的直接证据

`Ω_N = min(1, n_emergent / n_seed)`。当 `n_emergent ≥ n_seed` 时该式**恒为 1.0**
（算术恒等式，非经验发现）。实测（`exp_g3_2` 的 `per_layer_cardinality`）：

| 规则 | n_seed 层 | n | `n_emergent` 取值数 | **`Ω_N` 取值数** | 顶到 1.0 的条数 |
|---|---|---:|---:|---:|---:|
| `json` | 1 | 102 | 3 | **2** | 7 |
| `source` | 1 | 102 | **23** | **2** | **82** |
| `source` | 2 | 11 | 9 | **1** | 11 |
| `source_type` | 1 | 102 | 23 | 2 | 96 |

`source` 规则下 `n_seed=1` 层：**23 档取值 → 2 档**，102 条里 82 条被压到同一个
饱和值。这就是 0.836 → 0.654 的全部来源。生产本体（`json` 规则）下情况更极端 ——
`n_emergent` 全样本只有 **3 个不同取值**、Ω_N 只有 **2 个**，因此
`n_emergent` 在该规则下本来就没有信号（AUC 0.483），Ω 的 0.593 反而略高。
**这也解释了为什么 gen2 的 0.836 只在 `source` 规则下出现**：`json` 的级联按目标域
打包，成员共享目标域，涌现目标域恒空（gen2 §1.5），`n_emergent` 无变异可言。

### 2.4 ε 下界与完备度的角色（比核心假设说的**小**）

**ε 下界的实际行为**（`exp_g3_1` 的 `eps_floor_constant_identity`）：
`Ω_N=0` 时 `Ω_geo == (Ω_E · ε · Ω_F)^(1/3)` 在 `json` 上成立 95/105（0.905）、
在 `source` 上成立 **20/20（1.000）**。即 ε 下界**完全按设计工作** —— 它把
「Ω_N 缺失」变成一个固定的 10^(1/3)≈2.15 倍台阶，而不是把 Ω 钉死为 0。
核心假设担心的「ε 下界注入常数导致坍缩」在这层**不成立**：真正的坍缩
发生在**分量内部**（Ω_N 自己只有 2 档），ε 下界只是把一个 0/1 台阶变成
一个 ε^(1/3) 台阶，两者携带的信息量相同（都是 1 bit）。

**完备度**确实是 n_seed 的单调函数（ρ(comp, n_seed) = **0.9954**，
`exp_g3_1`），因此它把 Ω 进一步推向 1-bit 指示器。但它不是主因：
去掉完备度后 AUC 只从 0.6539 → 0.6148（更差），因为完备度在 Ω>0 子集内
本身携带一点弱信号（AUC 0.552）。

**层内秩序归因**（`exp_g3_1` 的 `layers`，`source`，n_seed=1 层 n=102）：
Ω 与各分量的层内 Spearman ρ 为
ρ(Ω, n_emergent)=**0.433**、ρ(Ω, Ω_N)=**0.689**、ρ(Ω, Ω_E)=**nan**（该层 Ω_E 恒为 1，无变异）、
ρ(Ω, Ω_F)=0.263、ρ(Ω, comp)=**0.600**。
即层内 Ω 的序**主要由 Ω_N 与完备度共同决定**，而 Ω_N 只有 2 档 —— 这就是
「序被 1 bit 主导」的微观证据。注意 Ω_E 在 n_seed=1 层**恒为常数**
（102 条全部 Ω_E=1.0），它对 Ω 的层内序贡献为零，是另一个死分量。

## 4. 最强候选 `S_query` 与它的下游检验

### 4.1 `S_query` 的定义（Ω 的单点修改）

```
Ω       = (Ω_E · min(1, n_emergent/n_seed) · Ω_F)^(1/3) × 完备度
S_query = (Ω_E ·     (n_emergent/n_seed)  · Ω_F)^(1/3) × 完备度
                      ↑ 唯一差别：去掉 min(1, ·) 截断
```

实现：`metaphor_graph/query_signal.py::_s_query`（常量 `SIG_S_QUERY`）。
**与 Ω 逐字相同**（同一 ε 下界、同一几何平均、同一完备度因子、同一外层特判），
只改一处。已用测试钉住：`test_s_query_removes_only_the_clip`。
已交叉校验：模块实现与实验脚本里的独立复写在 200 条样本上**逐位相同**。

### 4.2 下游目标的选择：per-query MRR

gen1/gen2 的弱点是「只预测了一个弱中间量」。gen3 选**语义超图通路**
（项目主通路，`evaluate_retrieval.score_conditions` 的 chunk 排序）对 LLM 金标的
**per-query MRR@10** 作为非平凡目标：

```
n = 632（有 LLM 金标 chunk 的查询）
MRR@10 人工加权 = 0.5025 [0.4747, 0.5296]
MRR@10 自监督训练 = 0.5463 [0.5180, 0.5725]
排名分布：第 1 名 186 条、第 2 名 103、…、第 10 名 1 条   ← 有真实余量，非饱和
```

这个目标**有真实余量**（不像构造金标饱和在 0.995），且与查询侧信号在
设计上应当相关（「查询激活的结构是否指向金标所在的域」）。

### 4.3 结果：查询侧标量**不能**预测 MRR

全样本 Spearman ρ 与**文档内** ρ（控制文档难度）对照（`exp_g3_7`，`source`）：

| 标量 | ρ 全样本(hand) | ρ 全样本(tr) | **ρ 文档内(hand)** | 文档内置换 p | ρ 文档内(tr) | p |
|---|---:|---:|---:|---:|---:|---:|
| `n_gold`（**非查询侧**，上界参考） | +0.0966 | +0.0738 | **+0.4981** | **0.0020** | **+0.3818** | **0.0242** |
| `cascade_nonempty` | +0.1429 | +0.1154 | **+0.2442** | **0.0010** | **+0.1959** | **0.0080** |
| `cascade_nhit` | +0.1395 | +0.1124 | **+0.2389** | **0.0010** | +0.1883 | 0.0107 |
| `n_emergent` | +0.0707 | +0.0720 | +0.1378 | 0.0332 | +0.0905 | 0.169 |
| `n_reach` | +0.0809 | +0.0724 | +0.1274 | 0.0357 | +0.0783 | 0.213 |
| `omega` | +0.0802 | +0.0690 | +0.1150 | 0.0597 | +0.0718 | 0.253 |
| **`S_query`** | +0.0814 | +0.0704 | **+0.1116** | **0.0665** | +0.0666 | 0.289 |

**三条结论**：

1. **没有任何查询侧标量能预测 per-query MRR。** 全样本 ρ 都在 +0.077~+0.082
   （所有查询侧标量**互相几乎相同**，因为它们的共同成分就是「有没有命中触发词」）；
   文档内 ρ 最大者 `S_query` = +0.1116，置换 p = **0.0665**，不显著。
2. **全样本的 ρ≈0.08 主要是文档难度混杂**：难文档里所有查询的 MRR 都低，
   且都更容易没命中触发词。文档内检验把这一层剥掉后，ρ 只从 0.0814 微涨到 0.1116，
   而 p 从 0.045 变到 0.067 —— 即「全样本显著」是伪的。
3. **`n_gold` 是唯一强相关（+0.498，p=0.002）**，但它**不是查询侧量**（由 LLM 对候选
   的判定产生），正是「只读查询」这条约束**结构性排除**的信息。这给出了不变式
   代价的直接量化：**下游目标的可用信号确实存在（+0.50），但全部在候选侧。**

### 4.4 `S_query` 在弱目标上的提升是真的，但目标本身是定理

**先说好消息**：`S_query` 在四条规则上都是**非图查询侧标量里 AUC 最高的**
（`source` 0.8243、`metanet` 0.7796、`source_type` 0.9290），且取值数从 Ω 的 40
提升到 **82**（不再坍缩成粗分档）。

**再说不好的消息（本轮最重要的诚实性控制）**：

**(a) 目标本身是集合相交的定理。** `exp_g3_4` 逐条核验：

```
cascade_nonempty = 1  ⟺  reachable_domains ∩ live_domains(doc) ≠ ∅
    json 635/635 · source 635/635 · metanet 635/635 · source_type 635/635   （一致率 1.0000）
```

`cross_domain_retrieve` 的 `agg` 非空 ⟺ 某个候选框架的 `targets` 集合与某条
live 超边的域相交。因此这个「目标」不是检索质量，而是**「查询可达的域集合是否
与图中现有边的域集合相交」这个集合成员判定**。

**(b) 用「集合大小」就能拿到几乎全部判别力。** 大小匹配的**随机集合**
（身份随机、大小相同，200 次重采样，`exp_g3_4`）：

| 规则 | 真实非空率 | 同大小随机集合非空率 | 真实/随机 |
|---|---:|---:|---:|
| `json` | 0.0756 | 0.0434 | 1.74× |
| `source` | 0.1071 | 0.0606 | 1.77× |
| `metanet` | 0.0945 | 0.0529 | 1.79× |
| `source_type` | 0.1701 | 0.1621 | **1.05×** |

`source` 逐档（`exp_g3_4` 的 `per_k`）：|reach|=2 时真实 0.2941 vs 随机 0.0424
（7.7×，这是唯一强 targeting 的档）；但 |reach|≥54 后真实 0.75–1.00 vs
随机 0.63–0.80（**1.2–1.3×**）—— 大集合几乎必然相交，与「买到了对的域」无关。
**决定性对照**（`exp_g3_4` 的 `auc_size_predicts_*`）：用**同一个「可达集合大小」
标量**，分别去预测「真实非空」与「同大小随机集合非空」（200 次重采样）：

| 规则 | 预测**真实**非空（全样本） | 预测**随机**非空（全样本） | 预测**真实**（n_seed≥1） | 预测**随机**（n_seed≥1） |
|---|---:|---|---:|---|
| `json` | 0.9640 | **0.9739** [0.9559, 0.9879] | 0.6799 | 0.5856 [0.2357, 0.8717] |

| `source_type` | 0.9988 | **0.9978** [0.9940, 0.9999] | 0.8943 | 0.5035 [0.4219, 0.5636] |

**全样本上「大小」预测随机标签的效果与预测真实标签完全相同**
（`json` 0.9739 vs 0.9640、`source` 0.9798 vs 0.9871、`metanet` 0.9806 vs 0.9803、
`source_type` 0.9978 vs 0.9988）—— 这就是「AUC 0.96–0.99 全样本」的真实成分：
**集合越大越可能与任何东西相交，与「买到了对的域」无关**。
在 n_seed≥1 子集内随机对照降到 0.50–0.59（真实 0.68–0.89），
说明子集内**确实还有一点**真实 targeting —— 但其幅度只有 1.7×（见 (c)），
且控制大小后归零（见 (d)）。

（查询侧的激活结构并非均匀分布）；但幅度只有 1.7× 左右
（`source_type` 几乎为 0），远不足以支撑「买到了对的域」这种机制性解释。
**这个 1.73× 是本轮唯一的正面发现**（与草稿一致，此处扩展为四条规则）。

**(d) 控制集合大小后判别力消失。** 用**对级加权**的条件 AUC
（w = n_pos·n_neg，等价于只在同大小对上数一致对；这是比 gen2 的
`min(n_pos, n_neg)` 更保守、更正确的估计量 —— 后者在「多数层只有 1 正或 1 负」时
退化成「若干 2–4 样本 AUC 的平均」，噪声极大）+ **分层内置换检验**（4000 次，
`exp_g3_5`）：

| 标量（`source`） | 条件 AUC(\|reach\|) [95% CI] | 分层置换 p | 再加 `doc_id` 后 |
|---|---:|---:|---:|
| `completeness` | 0.6562 [0.452, 0.824] | 0.0432 | **n/a**（无有效层） |
| `omega` | 0.6528 [0.443, 0.825] | 0.0467 | **n/a** |
| `S_query` | 0.6493 [0.439, 0.823] | 0.0500 | **n/a** |
| `n_seed` | 0.5174 [0.462, 0.594] | 0.3144 | n/a |
| `n_emergent` | 0.4861 [0.393, 0.573] | 0.7171 | n/a |
| `n_reach` | 0.5000 [0.500, 0.500] | 1.0000 | n/a |

**`n_emergent` 的条件 AUC = 0.486**（比 0.5 还低）—— gen2 的 0.836 **在控制集合
大小后完全消失**。`S_query`/`omega`/`completeness` 略高于 0.5（0.65~0.66），
分层置换 p ≈ 0.043~0.050，处于边缘；一旦再加一层 `doc_id`，
**所有标量都失去有效层**（`n/a`）—— 即这点边缘信号完全来自**文档间**差异。

**(e) 那个边缘信号是「文档难度」的投影。** `exp_g3_6` 在 `json` 规则上
`doc_id + |reach|` 分层后只剩 **2 个有效层、对权 2**（等于 2 个样本的 AUC），
AUC 显示 1.0000 —— 这是**样本量耗尽**，不是发现。`source`/`metanet`/
`source_type` 三规则下有效层数为 **0**。结论：**没有标量在控制「集合大小 + 文档」
后还有判别力。**

## 5. 多重比较校正与读图上界

### 5.1 Holm-Bonferroni 校正

`exp_g3_3` 测了 **25 个候选标量 × 4 条规则 = 100 个置换检验**。
Holm-Bonferroni 校正（`exp_g3_5` 的 `holm`）后，`source` 规则下
`S_query`/`omega`/`omega_nounclipN`/`n_emergent`/`n_reach`/`n_members`/
`n_expanded_td`/`S_log` 等的 p 都被校正到 **0.025–0.05**，`completeness` 到 **1.000**；
`json` 规则下 `S_query`/`omega` 被校正到 **0.629**、`n_emergent` 到 **1.000**。

**但这里必须说明一件事**：Holm 校正的是 `exp_g3_3` 的**无分层置换 p**
（打乱全样本标签），而那个零分布对**条件 AUC** 是错的（它把层间差异也算进了
「显著」）。因此在「控制集合大小后是否还有判别力」这个问题上，
**正确的判据是 `exp_g3_5` 的「分层内置换 p」，不是 Holm p**。两者并排：

| 标量（`source`） | 无分层 perm_p | Holm p | **分层内 perm_p** | 条件 AUC |
|---|---:|---:|---:|---:|
| `n_reach` | 0.001 | 0.025 | **1.0000** | 0.500 |
| `n_emergent` | 0.001 | 0.025 | **0.7171** | 0.486 |
| `n_members` | 0.001 | 0.025 | **0.3514** | 0.510 |
| `S_log` | 0.001 | 0.025 | 0.1925 | 0.528 |
| `omega` | 0.005 | 0.050 | 0.0467 | 0.653 |
| `S_query` | 0.001 | 0.025 | **0.0500** | 0.649 |

即：**「集合大小类」标量在 Holm 下「显著」纯粹是因为无分层检验的零分布错误** ——
它们的分层内置换 p 是 0.35–1.00、条件 AUC 是 0.49–0.53。
`omega`/`S_query` 是唯一分层内 p 触及 0.05 的（0.0467/0.0500），
但它们在 Holm 校正下是 0.025–0.050 的边缘，且**加 `doc_id` 后无有效层**（§4.4e）。

### 5.2 读图上界（不变式的代价）

如果允许读图（`|reachable ∩ live(doc)|`，即 gen1 的 Ω_G 那一支）：

| 标量 | AUC 全样本 | AUC 子集 | **条件 AUC(\|reach\|)** |
|---|---:|---:|---:|
| `S_graph`（读图，连续） | **1.0000** | **1.0000** | **1.0000** |
| `S_graph_bin`（读图，二值） | **1.0000** | **1.0000** | **1.0000** |

**读图后 AUC = 1.0000，连控制集合大小后也是 1.0000**（`exp_g3_6`）。
这不是「更好的模型」，而是**恒等式**（目标本身由集合相交定义）。
它说明：查询侧标量在**任何**情况下都无法达到这个数，因为缺的是**图可达性**
这一层信息。这就是「只读查询」不变式的**量化代价** —— 用 1.0000 换 0.65。

与 Ω 同一纪律，`measure_signal(query, ontology)` 的签名里**没有** `shg` /

- `test_query_signal_invariant_to_candidate_pool` —— 3 个随机种子 × 打乱/半量截断

- `test_measure_signal_signature_has_no_candidate_argument` —— 反射检查签名里
  不得出现 `shg/edges/candidates/retriever/chunks/ranked/result/scorer`。

另外三条口径/机制护栏：

- `test_reachable_domains_match_retrieval_target_set` —— `reachable_domains` 必须与
  `cross_domain_retrieve` 实际构造的 `targets` 集合**逐元素相同**（这是「通路非空」
  可被预测的前提）；
- `test_new_domains_excludes_direct` / `test_emergent_targets_only_target_domains`
  —— 两个「可达域」口径（gen2 的仅 `target_domain` vs 检索的 `target∪source`）
  必须区分，不能混用；
- `test_clip_collapses_levels_theorem` / `test_s_query_removes_only_the_clip`
  —— 把「`min(1,·)` 截断导致档位塌陷」这条机制钉成回归护栏。

## 7. 诚实裁决

### 7.1 三个问题的分级回答

| 问题 | 裁决 |
|---|---|
| Ω 的失败**来自它的合成**（几何平均 + ε 下界 + 完备度）吗？ | ❌ **不是**。2⁴ 开关全因子的 AUC 极差只有 0.126，且**任何组合**都到不了 `n_emergent` 的 0.836。ε 下界**完全按设计工作**（恒等式在 `source` 上 20/20 成立），完备度是共线但非主因。**真凶是分量内部的 `min(1, ·)` 截断**：`source` 规则下 `n_seed=1` 层 23 档取值塌成 2 档、102 条中 82 条顶到上限。 |
| 能不能造出一个「更好的」查询侧标量？ | ⚠️ **技术上是**：`S_query`（Ω 去掉截断）在四条规则上都是非图标量里 AUC 最高（0.593/0.824/0.780/0.929），取值数从 40 → 82。**但它更好的原因是它预测的目标是定理**。 |
| 那它有用吗？ | ❌ **没有**。目标 `cascade_nonempty` 是集合相交的同义反复（635/635）；同大小随机集合拿到 0.79–0.88 的 AUC；targeting excess 仅 1.73–1.78×；控制集合大小后条件 AUC ≈ 0.5（`n_emergent` 0.486）；对 per-query MRR 文档内 ρ=+0.11（p=0.067，不显著）。 |

### 7.2 「触发词命中数」是查询侧的天花板吗？

**是。** 证据链：

1. **所有查询侧标量在控制集合大小后条件 AUC ≈ 0.5**（`source`：`n_emergent` 0.486、
   `n_reach` 0.500、`n_members` 0.508、`n_seed` 0.517），唯一例外 `S_query`/`omega`
   0.649 但分层内置换 p=0.050（边缘）且加 `doc_id` 后**无有效层**。
2. **所有查询侧标量对 per-query MRR 的文档内 ρ 都在 +0.10 附近且不显著**
   （0.10–0.13，p=0.03–0.09），彼此差异在噪声内。
3. **唯一强预测因子（`n_gold`，ρ=+0.498，p=0.002）不是查询侧量。**
4. **读图上界是 1.0000**，且控制大小后仍是 1.0000 —— 缺的是图可达性，不是
   「更好的合成」。

因此：**`n_seed > 0`（有没有命中触发词）已经携带了查询侧的全部可用信息；
Ω 及其一切改版（包括 gen3 的 `S_query`）都在这个 1 bit 之上没有增加对下游有用的信息。**
这**证实并强化**了 gen1 的裁决，并补上了它缺的那一环 —— gen1 说「Ω 塌缩成 1 bit」，
gen3 说**「1 bit 就是查询侧的上限」**，且给出了机制（Ω_N 截断）与边界（读图上界）。

### 7.3 本报告没有证明什么

- **没有证明** `S_query` 在**工程上**有用。它在弱目标上 AUC 更高，但那个目标是定理；
  在下游目标上无预测力。`S_query` 的价值是**诊断性的**（暴露了 Ω 的实现缺陷），
  不是**功能性**的。
- **没有证明** 级联构造规则该改。本轮只把规则当作「让 Ω_N 有变异」的工具；
  改默认的裁决见 gen2 §8.2（**不应改**），本轮不改变该结论。
- **没有证明** `n_gold` 的 +0.498 可被利用。它是 LLM 判定的产物，用它做特征就是
  候选侧泄漏。
- **`source_type` 规则的 targeting excess 只有 1.05×** —— 它的高 AUC
  （`S_query` 0.929）**几乎全是尺寸效应**。这是最强的一条反面证据：
  同一条「信号」在一条规则下看起来很强（`source` 0.836），在另一条规则下被
  证明是纯机械效应。
- **样本量**：所有条件/下游结论都在 n=114（子集）或 n=632（MRR）上，
  条件 AUC 的有效对权只有 144–290。CI 宽是真实的，不是保守。
- **未做**：跨语料（只 CCL2018）、跨语言、真实用户查询的验证。
  gen1 报告的「774 触发词长尾覆盖不足」这一外推边界**依然成立**。

### 7.4 如果要把「查询侧标量」做对：本轮的修法清单

| 问题 | 修法 | 本轮是否验证 |
|---|---|---|
| Ω_N 的 `min(1,·)` 截断毁掉 23 档取值 | 去掉截断（= `S_query`） | ✅ 已验证：AUC 0.654 → 0.824 |
| Ω_E 在 n_seed=1 层恒为常数（死分量） | 分母不该是「种子触发词数」（触发词有同义冗余）；或该层直接不参与 | ✅ 已量化（该层 Ω_E 取值数 = 1） |
| 完备度是 n_seed 的单调函数（ρ=0.9954） | 应作为**独立诊断**而非乘性因子 | ✅ 已量化（去掉后 AUC 更差，但它不解释坍缩） |
| 几何平均是「与门」 | **不是主因**（16 种合成设置极差 0.126）——核心假设的这条归因应撤回 | ✅ 已否证 |
| ε 下界注入常数 | **不成立**：ε 下界按设计工作（恒等式 20/20）。真正的问题在分量定义层 | ✅ 已否证 |
| 「级联通路非空」这个目标 | **应停止使用** —— 它是集合相交的定理，不是检索质量 | ✅ 已证（635/635） |
| 要提升下游 | 必须读图（条件 AUC 1.0000）或读候选（`n_gold` ρ=0.498），两者都放弃不变式 | ✅ 已量化代价 |
