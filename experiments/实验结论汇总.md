## exp/dynamics：源项 / 谱性质（已复核）

**假设（我提出）**：`hgnn.py` 的 `M=½(I+S)` 无源项，迭代收敛到连通分量平稳分布，
使 `metaphor_coherence` 退化为同分量指示器；这解释了 §6.3 中 GRU 与 HGNN 打平
（1.000 vs 0.950），即"聚合方式次要"可能是算子退化的产物。

**裁决：假设证伪。** 两条独立证据：

### 证据一：退化只在渐近意义成立，H4 工作在 layers=2

我原始测量取 **500 轮**（收敛值），而 H4 实际工作在 `layers=2`。逐层实测
（doc_project，无源项）：

| layers | 同分量 cos | 跨分量 cos | 与 X0 余弦（源保留） |
|---|---|---|---|
| 1 | 0.188 | 0.046 | 0.961 |
| **2（H4 工作点）** | **0.388** | **0.076** | **0.840** |
| 5 | 0.660 | 0.124 | 0.547 |
| 50 | 0.964 | 0.129 | 0.331 |
| 500 | **1.000** | 0.133 | 0.314 |

`layers=2` 时同分量余弦仅 0.388，距 1.0 很远，源信息保留 0.840。**"退化"不能
用来解释 layers=2 的 H4 数字。**

### 证据二：完美同分量指示器达不到 0.950（决定性）

实测该配对样本上：正样本 20（全部同分量）、负样本 752（其中 150 同分量）。
**完美同分量指示器的准确率上限 = (20 + 602) / 772 = 0.8057**，**低于** H4 实测的
0.950。这一条单独就足以排除退化解释。

### 结论稳健性

在 α ∈ {0.1…1.0} × ε ∈ {0, 0.1, 0.2} 共 18 个配置下，`|acc_flat − acc_hgnn| ≤ 0.05`
（至多一个样本对之差）。换成高功效口径（20 正 / 752 负穷举，ROC-AUC）后
**|ΔAUC| ≤ 0.005，95% CI 跨 0**，方向甚至轻微偏向 flat。

**"信号来自 L1 n 元共现、而非层级"的结论保持不变。** 源项没有打破平局。

### 新增负面结果（2 项）

1. **`raw = 0.150` 是口径产物，不是"反向判别"。** 默认哈希编码器下抽象域标签
   几乎无共享 n-gram，实测**全体并列率 94.6%**（正样本 85.0%、负样本 94.8% 余弦
   恰为 0），而配对准确率把并列计为错误。raw 的真实 ROC-AUC = **0.5500**，
   即**无信息**，而非有害。原表述应修正。
2. **n=20 的 H4 配对准确率统计功效不足。** 其"结论字符串"会随 α 抖动翻转
   （α=0.5 时打印"依赖跨层传播 ✅"），而同期 AUC 完全稳定。**建议把 H4 主指标
   换成全量负样本 AUC。**

### 已实现（保持向后兼容）

`hgnn.py` 新增 `alpha`（源项系数，默认 1.0）与 `leak`（阻尼 ε，默认 0.0）；
`α=1.0, ε=0.0` 与历史实现**逐位相同**（`maxdiff = 0.000e+00`，4/4 组合）。
新增 `propagation_matrix()` 供谱分析。`evaluate_hgnn.py` 增加 `--alpha/--leak`
与两行新条目。测试 **116 → 129 全绿**。

源项的真实价值：让**深层迭代**（layers ≥ 50）不再坍缩，而非改善 layers=2。

## exp/omega：查询侧可观测泛函 Ω（已复核）

**假设（我提出）**：实现查询侧 Ω，检验"低 Ω 预测触发词级联通路的 0.042 失效"。

**裁决：分离现象真实，但 Ω 无额外信息量。** 逐条：

| 命题 | 裁决 | 关键数字 |
|---|---|---|
| Ω 只读查询（对候选池不变） | ✅ 成立 | 632 查询 × 4 种候选池扰动 → **0/632** 变化 |
| 改写型 Ω 系统性低于重叠型 | ⚠️ 成立但效应中等 | AUC=0.349、Cliff's δ=−0.301、Cohen's d=−0.502 |
| 低 Ω 预测级联通路失败 | ❌ **近乎同义反复** | 全样本 AUC=0.941；**去掉 Ω=0 的 518 条后 AUC=0.589（CI 含 0.5，p=0.163）→ 无区分力** |
| Ω 比"触发词命中数"更有信息 | ❌ 否 | Spearman **ρ(Ω, n_seed)=0.9949**；Ω>0 ⟺ n_seed≥1 **632/632 一致** |
| Ω 门控优于现有判据 | ❌ 严格更弱 | 漏掉 66 条"有触发词但通路仍空"的查询 |
| Ω 三分量都有用 | ❌ **Ω_N 是死分量** | 见下 |

### 根因：级联构造使 Ω_N 结构性恒空（已独立复核）

生产本体 758 个级联中，**752 个（99.2%）成员框架共享同一目标域**（实测确认）。
原因是 `builder._ensure_cascades` 按**目标域**打包孤儿框架——按目标域分组，
自然不会有"沿级联涌现出新的目标域"。**级联规模中位数 = 1**。

后果：Ω_N 恒为空集，几何平均下 Ω 被迫由 ε 下界决定，于是 Ω 退化成
"查询有没有命中任何触发词"的 1-bit 指示器。而该指示器与"级联通路是否为空"
在代码结构上是**定理等价**。

### 这条负面结果的正面价值

它**定位了一个真实缺陷**：级联是检索组织层（论文 §6.3 结论"层级的价值应表述为
检索组织与可解释性"），但当前构造下 **99.2% 的级联没有跨目标域的横向组织能力**，
中位规模为 1，实际退化为"框架别名"。这比"Ω 不好用"更重要——它指向
**级联本体构造规则需要修订**（见第二代候选）。

### 一句话

Ω **可以被计算**（"能测"成立），其低值与级联通路失败**确实共现**；但在本基底上
Ω 相对"有没有命中触发词"这个 1-bit 指示器**几乎没有额外信息量**。分离现象是
"本体触发词词表覆盖不足"的投影，**不是**"改写破坏了隐喻连贯性"的度量。

## exp/degrade：降级来源封顶可靠度通道（已复核）

**假设（我提出）**：不丢弃 `F_LLM_*` 降级候选，但给其封顶可靠度，能否让类型/结构
约束终于影响 P1 而不损失召回？

**裁决：假设不成立，且是结构性不可能——但揭露了一个更重要的指标问题。**

### 假设为何不可能成立（机制性）

**P1 是句级布尔指标**（`pred = bool(edges)`），而软可靠度通道只作用于打分/排序，
不改变任何句子的产出与否。**数学上界就是 0**，不是调参问题。

**更关键的是：误判根本不来自降级边。** 实测全部 **7/7 条 FP（字面误判）句都由
本体正式登记的框架支撑，0/7 是仅由降级框架支撑**。句级判别 AUC = **0.3913**
（即反相关：字面句 100% 可靠度 1.0，而 21.7% 的真隐喻句可靠度 0.5）。因此任何
折扣档位（floor 1.0/0.9/0.75/0.5）都不优于基线。**"惩罚降级来源"与"过滤字面误判"
在这批数据上完全不相交。**

实测：召回 0.696 → 0.696（逐位不变，通道实现正确、召回完全保住）；但排序被**损害**：
人工加权 MRR@10 **0.9948 → 0.8922（−0.1025）**，原因是 by-construction 金标与通道
前提直接冲突（26.6% 的金标 chunk 含降级边，降权即惩罚金标自身）。训练路径
+0.0000（clue AUC=0.999，金标已在 99.5% 查询中排第一，指标饱和），
**人工金标检索集（唯一不与通道前提冲突的尺子）效应恰为 ±0.0000**。
floor 全档位扫描无一档优于基线。**净增益为零。**

**张力未被解决。** 参考系统的封顶可靠性模式在本项目**不适用**，因为本项目 P1 不是
排序指标而是**存在性布尔指标**——这是与参考系统场景的关键结构差异，也是本实验最有
价值的发现。

### 但揭露了 P2 覆盖率的注水（已独立复核）

| 口径 | 值 |
|---|---|
| 现报 `hierarchy_coverage` | **1.000** |
| **诚实口径：本体登记框架 + 本体登记级联** | **0.776** |
| 退化边占比 | 22.4% |
| 级联总数 / 其中 `C_ADHOC_` 事后补的 | 408 / **184（45.1%）** |

独立复核（重跑 `probe_provenance2.py`）：超边 883 条，报出覆盖率 1.000，
**框架在本体中登记的边 = 685/883 = 0.776**，级联 408 其中 C_ADHOC 184。数字吻合。

**含义**：现报的 100% 覆盖率有 22.4pp 由"抽取器临时回退框架 + `_ensure_cascades`
按目标域事后补的 `C_ADHOC_*` 级联"撑起。排除后**本体正式归属仅 77.6%，低于 P2
的 85% 门槛**。论文附录 B 的 P2 状态需从 ✅ 改为**条件性达标**（现报口径 100%、
诚实口径 77.6%），并在限制章节说明两个口径。

### 实现过程中的一个关键坑（值得记录）

**判据必须是"本体有无条目"，不是 `F_LLM_` 前缀。** `llm_ontology.py:201` 用
`_stable_id("F_LLM", s, t)` 给**自举沉淀的正式框架**命名，于是生产本体的框架
**2177/2209 = 98.6% 以 `F_LLM_` 开头**（已独立验证：抽查的 `F_LLM_*` 均
`get_frame() is not None`）。**按前缀判定会把整个生产本体误判为"退化"**，
通道退化成"惩罚一切"。正确判据只有 `ontology.get_frame(frame_id) is not None`。
测试 `test_judgement_is_registration_not_prefix` 把这个坑钉死。

### 已实现（保持向后兼容）

新增 `metaphor_graph/provenance.py`（可靠性派生、分级标签、有下界乘性折扣）；
`models.py` 增加 `provenance_reliability: float = 1.0`（默认值保证旧数据不受影响）；
`extended.py` 扩展边取链上 `min(...)`（**退化边不得借合并洗白**）；
`retrieval.py` 两条打分路径都乘折扣。设计选择"**有下界的乘性折扣**"而非加性 bonus
（不改变相对次序）或硬过滤（丢候选、召回崩），有论证。

`health.py` 新增诚实覆盖率接口：**不传 `ontology` 时字段为 `None`，历史口径逐位不变。**

### 一个口径陷阱（已在报告中记录）

直接跑 `evaluate_real.py --use-llm` 在无 API key 时会回落到 `LocalHeuristicBackend`，
而它不实现 `discover_batch`/`batch_refine`，于是 `--llm-cache` **根本没被消费**，
产出**假性 P1 = 0.434**。正确做法是用 `PrecomputedBackend` 喂真实缓存重放
（P1 = 0.092，与 README 记录一致）。这与 README §7.1 记录的是同一类陷阱。

## exp/source：type 特征口径一致性（已复核）

**假设（我提出）**：`training.py` 与 `retrieval.py` 对 `F_LLM_*` 降级边的 `type`
特征给出 1.0 vs 0.0，§6.2 的 +4.5pp 训练增益可能部分来自此口径差。

**裁决：bug 真实存在，但我的因果链推断错了。§6.2 未被污染，增益反而增大。**

### bug 确认（比我原先描述的更精确）

两条路径确实不一致，但**分歧面比我原先说的窄得多**：

| 路径 | 表达式 |
|---|---|
| `training.py:81/113` | `type_ok = 1.0 if cand.frame_id else 0.0` |
| `retrieval.py:250-252` | `get_frame()` 对未注册 `F_LLM_*` 返回 `None` → `mtype` 退化为原始 id → `type_valid` = False → **0.0** |

关键修正：`F_LLM_` 前缀被**两个互不相交的 id 空间**共用——

- `extractor.py:113`：`md5("src|tgt")`
- `llm_ontology.py:201`：`_stable_id` 用 `md5("src||tgt")`（**双竖线**）

实测（856 条 L1 边）：**90.5% 的边以 `F_LLM_` 开头，但只有 188 条（22.0%）真正分歧**
——587 条回退边其实**已注册**（两条路径都给 1.0），只有 188 条未注册的才分歧。

### 我的因果链错在哪

**§6.2 的 "manual weighting" 根本不调用 `metaphor_retriever_score`。** 它走
`evaluate_retrieval.score_conditions`，用**共享的 7 维特征**，其中 `hand_weighted`
= `0.35·sem + 0.25·struct + 0.20·clue + 0.20·type`。而该候选池中
**`type` 恒为 1.0（已独立复核：25/25 边都有 frame_id）**——是**死维度**，
被偏置吸收。因此 §6.2 两侧 `type` 都是 1.0，**从未受口径差影响**。

> 教训：我依据「两处表达式不同」直接推断「已上报数字被污染」，未先确认
> **被上报的那条路径实际调用的是哪段代码**。这是本代实验里我自己犯的推理错误。

### 修复

新增 `ontology.type_reliability` / `type_reliability_of` 作为**唯一真源**：
**1.0** 已注册 / **0.5** 未注册回退（**封顶而非丢弃**，保住 +55.8pp 召回）/
**0.0** 无框架或已注册但非法。三处调用点统一，本体实例贯穿 `_pair_features` 与 `_add`。

### §6.2 重测：增益增大而非消失

| 配置 | 修改前 | 修改后 |
|---|---|---|
| 人工加权 | 0.502 | **0.481** |
| 自监督 | 0.547 | **0.545** |
| 弱监督 | 0.536 | **0.526** |
| **训练增益** | **+4.5pp** | **+6.4pp** |

真实句向量行逐位复现（0.707/0.759/0.756 vs 报告 0.707/0.758/0.755，缓存命中 100%），
修复后为 0.673/0.751/0.734，增益 **+5.2pp → +7.8pp**。

**机制**：`type` 的单特征 AUC ≈ 0.497（接近噪声）；训练器学到的权重 **+0.049 ≈ 0**，
而人工加权**硬编码 0.20**。修复把一个"无害常数"变成了"有害噪声"，因此
**人工加权受损更重**，训练的相对优势反而扩大。

### 结论翻转（需人工复核）

`evaluate_fullcorpus` 的 **A7/H5 从"+0.3pp，H5 证伪"翻转为"+9.5pp，H5 成立"**。
这一条影响 §6.2 与 §7 的结论表述，**建议人工复核后再采纳**。

### A1/H1 不变

日志逐字节相同：P1 0.092 → 0.092，枚举拦 0 + 连贯性拦 24。修复**有意不触碰**此处
——封顶到 0.5 而非 0.0，正是保住召回的原因。

### 其他口径分歧（已排查）

`same_frame` 0.0%、`same_cascade` 0.08%（max 聚合残差）、`struct` 0.0% —— 均一致。
`ground_jaccard` **4.76% 因定义不同**（包含比 vs 真 Jaccard）—— 已标注，未改动。
`sem` 的 clamp 不一致为潜在问题（此数据上余弦非负，未触发）。

### 诚实裁决

**报告的 +4.5pp 不是假象**——§6.2 两条路径本就一致，修复后增益反而增大到 +6.4pp。
真正发现的问题是：`type` 是死维度；且 `retrieval.py:250` 使 **A6 被低估 1.8pp**
（旧训练编码下 0.783 vs 0.801）。

四个方向全部返回，**四个假设全部证伪或需修正**（其中两个是我提出的，且我的

- Ω 无额外信息量（ρ=0.9949，退化为 1-bit 触发词指示器）

- H4 主指标应换成全量负样本 AUC（n=20 功效不足）

**加强的既有结论（1 条）**：
- "信号来自 L1 n 元共现、层级非必要"在高功效口径下依然成立（|ΔAUC| ≤ 0.005）

## 第二代方向（定稿）
