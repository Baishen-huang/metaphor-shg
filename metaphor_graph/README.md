# 隐喻超超图 / 元图（MetaphorSHG / MetaphorMG）

> 把认知语言学的隐喻层级结构（cascade 理论）翻译为超超图/元图的数学结构，
> 并验证其在检索增强生成（RAG）中的有效性——让系统「理解隐喻」而非仅匹配字面。

本仓库是 [`知识隐喻分析任务方案.md`](..\知识隐喻分析任务方案.md) 的可运行实现，
包含**方案 A（隐喻超超图 MetaphorSHG）** 与 **方案 B（隐喻元图 MetaphorMG）** 两条路线，
以及共享的跨域检索、多线索汇聚、超图版 KEG 检测器、HL-index 可达性索引与 Neo4j 存储层。

### 0.3 关键难点与已付出的代价

1. **静默失败差点毁掉整轮结论**：账户欠费 402 被"优雅降级"吞掉 → 域归并 100% 恒等 → 本体碎片化成 2656 框架，流程却一路报成功。已加 `LLMFatalError`（401/402/403 抛异常）+ `_canonicalize` 归并率自检。
2. **验收口径错配，必须重写结论**：P4 原定「抽取 F1+5pp」，但 HGNN 是检索/语义信号编码器，CCL2018 是逐句二分类无逐边金标——该口径**根本无法成立**。已改为测真实贡献（P4-B 第三道校验），并建议论文改述。
3. **密集的负面结论（诚实但刺眼）**：H1（类型约束压 P1）不成立、H5（训练排序器有增益）不成立、H7（角色特征不可被替代）不成立。每一条都"试过且证伪"，根因已挖清（开放发现使类型约束无法管精度；自监督 clue AUC≈1.0 天花板；角色特征权重≈0）。这类结果必须写进论文，否则读者会以为没试过。
4. **召回 vs P1 的帕累托天花板**：规则侧在 P1<15% 下召回天花板约 **9.7%**，裸名词能到 ~50% 但 P1 爆到 60%+。突破只能靠真实 LLM——且离线后端在新喻体上触到规则极限（字面身份判断无廉价可判别特征）。
5. **环境坑（已记 memory，永不再犯）**：sandbox 子进程前缀 `env -u LLM_API_KEY` 会让 stdout 整段丢失（exit 0 无输出），曾误判为"进程被杀/环境退化"浪费大量排查。**离线任务绝不用 `env -u` 前缀**。
6. **小样本评测的诚实边界（部分已收口）**：P3（2 文档 7 金标）为精选诊疗集；A7/A8/A9 已在
   全量建图基准（110 文档 861 查询）复验——A9 精确复现、A7 双方贴天花板、A8 仍无差异（§7.3）。
   但 **P3 的 F1=1.000 不能外推**：全量语料（CCL2018 独立短句）上扩展链天然稀疏（仅 5 条/110 文档），
   L1.5 的价值域是**连贯文档**（真实 RAG 场景），不是独立句集合。

## 1. 核心思想

隐喻不是 `(源域, 类似, 目标域)` 的三元组，而是一条同时承载
**源域、目标域、喻底集合、触发词、情感、语境** 的 *n 元关系*；隐喻的层级组织
（基础隐喻 → 一般隐喻 → 隐喻级联）又天然构成**超顶点嵌套**结构。

| 层级 | 隐喻结构 | 本框架表示 |
|---|---|---|
| L0 | 触发词（"失血""泥潭""发条"） | 语言形式节点 |
| L1 | 隐喻映射（源域, 目标域, 喻底集合, 触发词） | **超边** `MetaphorHyperedge` |
| L2 | 一般隐喻（框架） | **超顶点** `MetaphorFrame` |
| L3 | 隐喻级联（cascade） | **超超顶点** `MetaphorCascade` |

关键设计取舍：
- **类型安全约束**（§4.1.3）：用结构化规则过滤字面误判，不依赖 LLM 判断。
- **cascade 查表替代 LLM 聚类**（§4.1.4）：L2/L3 构建成本降低一个数量级。
- **跨 chunk 扩展隐喻超边**（§4.2）：填补向量检索在延伸隐喻上的结构性盲区。

## 4. 核心流水线（§4.6）

```
[原始文档] → [分块] → [L1 抽取：MIPVU + 双阶段过滤 + 类型安全]
  → [L1.5 扩展隐喻链接] → [L2 框架归属：cascade 查表]
  → [L3 级联归属：cascade 查表] → [存储：Neo4j / JSON]
  → [检索：字面通路 + 隐喻通路(RRF 融合)]
```

最小用法：

```python
from metaphor_graph import MetaphorSHGBuilder, RetrievalEngine

chunks = ["我们的项目现在陷在泥潭里，每前进一步都要拔出腿来。"]
shg = MetaphorSHGBuilder().build(chunks, doc_id="doc0")
eng = RetrievalEngine(shg, chunks, doc_id="doc0")
res = eng.cross_domain_retrieve("为什么我们的项目推进不动？")
print(res.chunk_ids, res.trace)
```

## 5. 检索能力

| 能力 | 入口 | 说明 |
|---|---|---|
| 跨域检索 | `RetrievalEngine.cross_domain_retrieve` | 触发词→级联→跨域目标概念（"推进不动"→"泥潭"） |
| 多线索汇聚 | `RetrievalEngine.multi_clue_retrieval` | ≥2 个触发词共同支持的映射优先 |
| 隐喻版 HyperRetriever | `RetrievalEngine.metaphor_retriever_score` | 在结构/语义/线索外新增 `type_score` 防污染 |
| RRF 融合 | `RetrievalEngine.rrf_fusion` | 字面通路 + 隐喻通路融合 |
| U-Retrieval | `MetaphorURetrieval.retrieve` | 方案 B：自顶向下匹配级联→逐层下钻→自底向上约束 |
| 可达性索引 | `HLIndex.reachable_targets` | 触发词→可达目标域，O(1) 查表 |

## 6. 如何扩展

### 6.1 接入真实 LLM 抽取（替换启发式）→ 详见 §6.6
`MetaphorExtractor(llm_fn=...)` 接受一个 `llm_fn(text, frame) -> Optional[dict]`，
返回 `{"confidence": float, "ground": List[str]}` 或 `None`（判为非隐喻）。
这是**旧接口**，只做「细化已命中的候选」，无法发现触发词表之外的隐喻。

需要真正的召回突破，请用 §6.6 的 `llm_backend=` 接口（含 `discover` 开放发现）。
旧接口予以保留，且与新接口可共存（`llm_backend` 优先）。

### 6.2 接入真实句向量（接口已就绪）
`embeddings.set_embedder(fn)` **一处注入，全链路生效**（HGNN / HyperRetriever /
训练特征 / 元图 / 语义通道 incongruity_score 自动共享同一向量源）：

```python
from metaphor_graph import embeddings
from metaphor_graph.embeddings import OpenAICompatibleEmbedder

embeddings.set_embedder(OpenAICompatibleEmbedder(
    base_url="https://open.bigmodel.cn/api/paas/v4",   # 或 OpenAI /v1、本地 vLLM
    model="embedding-3", api_key="...",
    cache_path="data/embed_cache.json"))               # 磁盘缓存，重跑零请求
```

- `OpenAICompatibleEmbedder`：标准库 `urllib` 直连 OpenAI 兼容 `/embeddings`
  端点，**零额外依赖**；批量接口 `embed_batch` 摊薄请求开销。
- **失败纪律与 llm_backend 一致**（§7.2）：401/402/403 → `EmbedderFatalError`
  （绝不静默降级成哈希向量——那是产出全错结果的坑）；其它错误 →
  `EmbedderError` 由调用方决定降级。
- HTTP 通路 / 缓存 / 批量 / 致命错误由本地 mock server 单测覆盖
  （`TestEmbedderLayer`，无需真实密钥）。
- 注入的 embedder 抛错**原样上抛**，`embed()` 不做静默回退。
- **实测（2026-08-30，智谱 embedding-3 @512 维，n=632 改写查询）**：sem 信号换真实
  句向量后，LLM 金标基准上全部排序器 **+21pp MRR**（人工加权 0.502→0.707、
  自监督 0.547→**0.758**），Hits@3 0.604→0.815；且训练增益在真实向量上依然成立
  （+5.1pp）。从最初基线起总迭代 **+25.6pp**（0.502→0.758，详见 §7.5/《效果对比.md》§6）。
  P4-A 亦翻案（见 §7.4）。

在 `ontology.py` 中按 `FrameSpec` / `CascadeSpec` 增列条目即可；

### 6.4 自举触发词（方案 §9.1 第一刀）
用 CCL2018 训练集（`train.xml`，自带 Label 0/1/2）把高频**喻体名词**挖出来回填触发词表，
是接入 LLM 之前成本最低、且能立刻拉升召回的自举手段。

方法要点（`bootstrap_triggers.py`）：
- **等比结构挖喻体**：中文名词隐喻多为「X是Y / X像Y / X如Y」结构，
  用 jieba 在标记词前/后抽取名词短语，得到**模式串触发词**（如 `是舞台`、`像棉花糖`、`若太阳`、`花般`）。
  之所以用「标记+喻体」模式而非裸名词，是因为字面句「我在舞台上」不含「是舞台」——
  模式串天然规避了裸名词的字面误触，是压住 P1 的关键。
- **字面软过滤**：按 lift（隐喻主导度）= P(词|隐喻)/P(词|字面) 保留高 lift 喻体；
  动词喻体无等比标记、裸词字面风险高，默认关闭。
- 落盘 `bootstrap_triggers.json`，`build_bootstrap_ontology()` 把词灌进
  `GENERIC_VEHICLE` 通道的新 cascade（已在 `TYPE_CONSTRAINTS` 注册，保证 `type_valid` 通过）。

运行与验证：
```bash
python -m metaphor_graph.bootstrap_triggers              # 挖词 + 落盘 + 自检
python -m metaphor_graph.evaluate_real --use-bootstrap   # 自举本体评估
python -m metaphor_graph.evaluate_real --use-metanet --use-bootstrap  # 最佳组合
```

**实证结果（CCL2018 测试集 1100 句，n=1100，中性 76 句）**——这恰好验证了方案 §4.1.3/§6.5 的核心论断：

| 配置 | 召回 | P1 字面误判率 | 达标 |
|---|---|---|---|
| 默认本体（7 级联/14 框架） | 3.1% | 1.3% | ✅ |
| MetaNet 迁移本体 | 4.8% | 6.6% | ✅ |
| **自举模式串（P1-safe）** | **6.0%** | **2.6%** | ✅ |
| **MetaNet + 自举模式串（推荐）** | **7.6%** | **7.9%** | ✅ |
| 裸名词喻体（激进，无标记） | 49.5% | 61.8% | ❌ |
| 模式串 + 具体裸名词 | 30.3% | 43.4% | ❌ |

> **关键发现**：在 P1<15% 硬门槛下，纯触发词自举的召回存在**天花板（约 6–8%）**。
> 裸名词能拉到 ~50% 召回，但 P1 直接爆到 60%+，撞穿硬门槛。这说明——
> **要真正突破召回，必须接入真实 LLM 后端（§6.1），而非堆触发词。** 自举的价值在于
> 「零成本、合规地翻倍基线召回」，以及为 LLM 提供高质量的初始候选。

### 6.5 MIPVU + Wmatrix 轻量语义通道（突破触发词天花板的第一刀）

§6.4 证明纯触发词自举的召回被 P1 门槛钉死在 ~6–8%。要再往上走，需要一条
**不依赖触发词表**的候选通道——这正是 MIPVU（基本义≠语境义）与 Wmatrix（USAS 语义域
+ keyness 失谐）的思路。本仓库以**轻量、不引外部英文工具**的方式实现：

- **中文语义域词表**（`semfield.py`，USAS 风格）：为 6 个新接入的级联域
  （THEATRE/NATURE/BUILDING/VALUE/SUBSTANCE/ORGANISM）建词表；`tag_token` 给每个
  内容词打语义域，`discourse_field` 统计 chunk 主导域作为「语篇预期域」。
  语义域与级联本体的 `source_domain` 同源——级联本体的 `ground` 词表本就是语义场种子。
- **MIPVU-lite 候选通道**（`mipvu.py`）：① 等比标记邻近（是/像/如/似/若 及其复合词
  *基于分词 token 匹配*，避免「如」误中「栩栩如生」、「像」误中「好像」）；
  ② 语义失谐（词域 ≠ 语篇预期域 且 该域词稀有）→ Wmatrix 式 keyness。
  再加**域内字面护栏**（同域词 ≥2 且即主导域 → 喻体落在源域内，非跨域，跳过）。
  域经 `FIELD_TO_CASCADE / FIELD_TO_FRAME` 桥接进级联框架，候选统一过类型安全护栏。
- **接入点**：`MetaphorExtractor(use_semfield=True)`，在「触发词通道」之外并行跑该通道，
  两路候选都汇入 §4.1.3 的类型安全约束（P1 护栏）。

运行与验证：
```bash
python -m metaphor_graph.evaluate_real --use-semfield                 # 语义通道单独
python -m metaphor_graph.evaluate_real --use-metanet --use-bootstrap --use-semfield  # 综合最佳
```

**实证结果（CCL2018 测试集，n=1100）**——语义通道把「触发词天花板」往上抬了一截，
且 P1 始终 < 15%：

| 配置 | 召回 | P1 字面误判率 | 达标 |
|---|---|---|---|
| 默认本体（仅触发词） | 3.1% | 1.3% | ✅ |
| 默认本体 + 语义域失谐 | 5.4% | 1.3% | ✅ |
| MetaNet + 自举 + 语义域（综合） | **9.7%** | **7.9%** | ✅ |

> 语义通道召回仍受限于**词表覆盖**（FIELDS 仅 ~150 词）。要再突破——即把 P1 压住的同时
> 召回拉到可用区间——需要把 `embeddings.py` 换成真实句向量（§6.2），让 `incongruity_score`
> 用语义相似度而非词表匹配；或接真实 LLM 后端（§6.6）。`semfield.set_embedder(fn)` 已为此预留接口。

### 6.6 接入 LLM 后端（方案 §8 路线图已完成项）

§6.4/§6.5 已实证：规则侧（触发词自举 + 语义域失谐）在 P1<15% 下的召回天花板约 **9.7%**。
要再往上，必须让模型来做「这到底是不是隐喻」的语义判断。本仓库用**统一后端接口**接入，
含三通道中的**通道三：LLM 开放发现**。

**接口**（`llm_backend.py`，结构化 Protocol，鸭子类型即可，无需继承）：

| 方法 | 作用 |
|---|---|
| `discover(chunk) -> List[LLMCandidate]` | **开放发现**：直接从自由文本找隐喻候选，**不看触发词表/词表**，召回突破的关键 |
| `refine(chunk, frame) -> Optional[LLMRefine]` | 细化：确认/否认通道一、二已命中的候选，给出置信度与喻底 |
| `cluster(edges) -> Optional[dict]` | 构建期回退：对未匹配本体的 L1 超边做 L2/L3 命名（少量调用） |

**三种实现**：

| 实现 | 用途 | 依赖 |
|---|---|---|
| `OpenAIBackend` | **真实大模型**。OpenAI 兼容端点（OpenAI / DeepSeek / 通义 / 本地 vLLM / Ollama），标准库 `urllib` 直连，**零额外依赖** | 需 `LLM_API_KEY` |
| `LocalHeuristicBackend` | 离线确定性近似（jieba 等比结构挖掘 + 本体/语义域绑定）。无密钥也能跑通全链路 | 需 jieba |
| `MockBackend` | 单测用，返回预置结果 | 无 |

**接入方式**（抽取器与构建器都吃同一个后端）：

```python
from metaphor_graph import MetaphorExtractor, MetaphorSHGBuilder, OpenAIBackend

backend = OpenAIBackend()                      # 读环境变量 LLM_API_KEY/LLM_BASE_URL/LLM_MODEL
# 或：OpenAIBackend(api_key="sk-...", base_url="https://api.deepseek.com/v1", model="deepseek-chat")

ex   = MetaphorExtractor(llm_backend=backend, use_semfield=True)
shg  = MetaphorSHGBuilder(llm_backend=backend).build(chunks, doc_id="d")
edges = ex.extract("这起事件让公司声誉陷入了舆论的漩涡。")   # 触发词表里没有"漩涡"
```

**三通道如何协同**：候选统一汇入 §4.1.3 的类型安全约束。LLM 给出的源域/目标域
**能绑定到已知框架时复用该框架**（类型护栏继续生效）；绑不上的全新喻体走 `GENERIC_VEHICLE`
通道（已在 `TYPE_CONSTRAINTS` 注册），并由**更严的 `llm_conf_threshold`（默认 0.5，
高于基础阈值 0.35）**单独把关。触发词无法在原文中定位的「悬空候选」直接丢弃。
跨通道重复召回由 `_dedup` 按 (框架, 跨度) 去重。

**稳健性**：网络/超时/解析/字段缺失一律**优雅降级**（`discover`→`[]`，`refine`→`None`），
流水线不会因 LLM 不可用而崩溃；`_parse_json_blob` 容错解析 ```json 包裹与前后废话。

**验证与运行**：
```bash
python -m metaphor_graph.demo_llm                # 离线模式（无密钥可跑）
python -m metaphor_graph.demo_llm --mock-server  # 本地假端点，验证真实 HTTP 通路（无需密钥）
python -m metaphor_graph.evaluate_real --use-llm # 有 LLM_API_KEY 走真实端点，否则走离线后端
```

**实证结果（CCL2018 测试集，n=1100；离线 LocalHeuristicBackend）**：

| 配置 | 召回 | P1 字面误判率 | 达标 |
|---|---|---|---|
| 基线（关 LLM，默认本体） | 3.1% | 1.3% | ✅ |
| **LLM 离线（保守，默认）** | **4.0%** | **1.3%** | ✅ |
| LLM 离线（放开新喻体 `allow_generic=True`） | 23.1% | 14.5% | ⚠️ 勉强 |
| LLM 离线（放开新喻体，未加专有名词护栏） | 26.6% | 17.1% | ❌ |

> **关键发现（重要）**：离线近似放开「新喻体」能把召回拉到 23%，但**全部字面误判都来自
> 这类绑不上的 GENERIC 候选**——离线后端拿不到 `target_domain`，于是把
> 「父母/奥斯曼帝国/待机时间/夫人」这类**字面身份判断句**的名词也当成了喻体。
> 我们做了两道护栏：① 专有名词作等比谓语视为身份判断（"苏利曼是苏丹"）；
> ② 域内字面护栏（同域词 ≥2 且即主导域）。加完后 P1 从 17.1% 降到 14.5%。
> 但这已到**离线规则的极限**——实测真隐喻与字面误判的词性分布几乎一致，
> 不存在廉价的可判别特征。**这正是真实 LLM 的价值所在**：它能同时给出 `target_domain`
> 并判断跨域映射是否成立（见 §6.5 结尾同样的论断）。
>
> 因此默认取**保守档**（P1 1.3%，留足安全边际）；想观察新喻体的潜在收益可置
> `LocalHeuristicBackend(allow_generic=True)`。

### 6.7 真实大模型实测（deepseek-v4-flash 全量跑通）

**接入即可用**：`deepseek-v4-flash` 把召回从规则侧的 **7.6% 拉到 66.3%（+58.7pp）**，
而 **P1 完全不变（7.9%）**，全量 1100 句只花约 **¥0.6–1.2**。

| 配置（CCL2018 测试集 n=1100，中性 76） | 召回 | P1 误判率 | 精确率 | F1 | 达标 |
|---|---|---|---|---|---|
| 规则侧（MetaNet+自举+语义域，**无 LLM**） | 7.6% | 7.9% | 0.929 | 0.141 | ✅ |
| **+ LLM 开放发现（`--llm-conf 0.85`）** | **66.3%** | **7.9%** | **0.991** | **0.795** | ✅ |
| + LLM（阈值放宽到 0.5，不设防） | 89.6% | 32.9% | 0.977 | 0.929 | ❌ 超门槛 |

> **结论：召回 +58.7pp，P1 一个点都没涨。** 这是本次接入最有价值的结论——
> 此前所有规则侧优化都在「召回换 P1」的帕累托前沿上挤，LLM 直接把前沿整体外推了。

**两道防线缺一不可**（拆开实测过）：
1. **`--llm-conf` 阈值**：候选只取一次，之后扫阈值**不再调 LLM**（零额外成本）。
   真隐喻置信普遍 0.9+，误判多在 0.6–0.85，抬高阈值能精准切掉误判。
   0.85 是实测的达标拐点（单独用阈值时 P1 14.5%）。
2. **`refine` 校验阶段**：`PrecomputedBackend(table, backend)` 带 fallback 时，
   触发词/语义域通道的候选会再过一次 LLM 判断。**这一道把 P1 从 14.5% 压到 7.9%**，
   代价是召回从 69.1% 略降到 66.3% —— 非常划算。

> 注：剩余 6 个"误判"里有多条其实**标注存疑**（部分为明喻而非隐喻，
> 另有若干如"淋湿了老张的心"明显是隐喻），真实 P1 可能更低。

**真实用量与费用**（`--llm-batch 20`，一次全量）：
调用 55 次｜输入 37,464 tok｜输出 57,351 tok
→ 高峰价（9–12、14–18 点）**≈ ¥0.63**，空闲时段半价 **≈ ¥0.31**。
（DeepSeek 2026-08-17 起峰谷定价：V4-Flash 高峰 输入未命中 ¥3/百万、输出 ¥9/百万；空闲减半。）

**MIPVU 判据必须写进提示词**（`_MIPVU_RULE`）：不加时模型会把固化成语（"七上八下"）、
描写性美称（"琼玉世界"）、拟人（"钟塔告诫学子"）全判成隐喻，P1 直接飙到 28.9%。
加上"基本义 ≠ 语境义 + 三类排除项"后，前两类误判已消除；输出字段里带 `basic_meaning`
是刻意设计——逼模型先把 MIPVU 判据走一遍再下结论。

### 6.8 成本估算与接入 GLM（跨厂商对比）

**实测输入量**（CCL2018 测试集 1100 句，句长中位数仅 15 字）：

| 模式 | 请求数 | 输入字符 | 说明 |
|---|---|---|---|
| 逐句调用（默认） | 1100 | ~387,000 | **其中 91% 是固定提示样板** |
| **批量 20 句/批** | **55** | **~55,000** | 省 ~86% 输入 token |

> 样板开销这么高，是因为提示模板有 321 字，而句子中位数才 15 字。
> 因此 `evaluate_real.py` 提供了 `--llm-batch N`，并新增 `discover_batch()` /
> `batch_discover()` / `PrecomputedBackend`：先把整批语料一次性问完，再让抽取器
> 消费缓存结果 —— **抽取器接口不变，成本与延迟各降一个量级**。

**token 换算**（中文按 0.5–0.8 token/字估算，取中位 0.65）：
- 逐句：输入 ≈ **0.19–0.31M**，输出 ≈ 0.17–0.33M（GLM-5.3-Flash 的 thinking 不可关闭，
  回复自带推理过程，输出比表面数字更高）→ 全量一遍 ≈ **0.4–0.6M tokens**
- 批量：全量一遍 ≈ **0.07–0.1M tokens**

**GLM-5.3-Flash 价格**（2026-08-26 发布，国内 bigmodel.cn）：
输入 ¥0.8/百万、输出 ¥2.8/百万、缓存命中 ¥0.23/百万；**上线前两周半价** ¥0.4 / ¥1.4。

**结论：跑一遍完整 CCL2018（1100 句）约 ¥0.1–1 元**，批量模式基本可以按「不要钱」算。
（免费替代：`GLM-4.7-Flash` 永久免费，但限 1 并发 / 约 1 req/s，1100 句需 ~18 分钟。）

**接入配置**（标准 OpenAI 兼容，注意 base_url 是 `/api/paas/v4` 不是 `/v1`）：


**三个坑（都是实测踩出来的）**：
1. **base_url 路径因厂商而异**：DeepSeek 是 `https://api.deepseek.com`（无 `/v1`），
   智谱是 `https://open.bigmodel.cn/api/paas/v4`（是 `/api/paas/v4` 不是 `/v1`）。
   本框架在 base 后自动拼 `/chat/completions`。
2. **思考模式默认开启，且会吃掉绝大部分预算**：
   V4 系列默认 `thinking=high`，实测 200 句上输出 **103,973 tok vs 关闭后 8,794 tok（12 倍）**，
   而召回只从 88.9% 涨到 93.2%。更关键的是**思考模式下 `temperature` 会被静默忽略**，
   结果不可复现。抽词是简单任务，务必 `{"thinking": {"type": "disabled"}}`。
   - DeepSeek：用 `thinking.type: disabled` 关闭（支持关闭）。
   - GLM-5.3 系列：**不可关闭**，只能 `reasoning_effort: "low"` 压低开销。
   `evaluate_real.py` 检测到 `LLM_MODEL` 以 `glm-5` 开头会自动带上后者；
   其它厂商私有参数统一用 `LLM_EXTRA_JSON='{...}'` 透传。
3. **峰谷定价**：DeepSeek 高峰 9–12、14–18 点是空闲时段的两倍。批量任务排在晚间/周末更省。
   框架会自动累积厂商返回的 `usage` 并在评估末尾打印（精确核算，非估算）。

### 6.9 LLM 自举回流（P0 收官 + 修复 P2 覆盖率）

接上 LLM 后暴露了下一个瓶颈：模型每见一个新喻体就**临时造一个框架**
（`F_LLM_xxxx`），这些框架不属于任何级联，直接把 **P2 的 L3 覆盖率打到 2.4%**
（门槛 85%）。同时 P0 的「种子 ≥300 框架」还差 10 倍（当时只有 31 个）。

`llm_ontology.py` 把模型见过的高置信 `(源域→目标域)` 沉淀成正式框架与级联。
**本体只用 train.xml 建**（`--source train`，默认），再在测试集评估：

```bash
python -m metaphor_graph.llm_ontology --source train \
       --out metaphor_graph/llm_ontology_train.json
python -m metaphor_graph.evaluate_real --use-metanet --use-bootstrap --use-semfield ^
       --use-llm-ontology --llm-ontology-path metaphor_graph/llm_ontology_train.json ^
       --use-llm --llm-batch 20 --llm-conf 0.85 --llm-cache data/llm_cache_deepseek.json
```

**结果（本体来自 train，测试集 n=1100）**：

| 指标 | 自举前 | 自举后 | 门槛 |
|---|---|---|---|
| P0 本体框架数 | 31 | **2222** | ≥300 ✅ |
| P1 字面误判率 | 14.5% | **9.2%** | <15% ✅ |
| P2 L2/L3 层级覆盖率 | 2.4% | **100%** | >85% ✅ |
| 召回 / 精确率 / F1 | 66.3% / 97.7% / 0.759 | **69.1% / 99.0% / 0.814** | — |

> **方法论校验（重要）**：最初本体是用**测试集语料**建的，存在语料重叠。
> 改用 train.xml 重建后复测：P1 9.2%、召回 69.1%，与测试集建的（9.2% / 69.3%）
> **几乎一致** —— 说明对外报告的数字**不是靠语料重叠堆出来的**，结论稳健。
> `--source cache` 保留作对照用，但不得用于对外结论。
>
> 顺带一提：只用训练集还更好（2656 组合 vs 703，框架 2190 vs 656）——
> 训练集有 4075 个隐喻句，是测试集（1100 句）的近 4 倍，语料更充足。

两个关键技术点：
- **必须做域归并**：模型的域描述近 700 种且几乎不重复（"水流漩涡"/"漩涡"各算一种），
  不归并根本聚不成框架。用 LLM 归一到规范标签后才形成可管理的概念域。
- **模糊匹配**：模型说"水流漩涡"、本体写"水流"，字符串不会相等。
  `_fuzzy_match_frame` 用子串包含做三级匹配（源+目标 → 仅源域 → 新建），
  这是覆盖率从 2.4% 拉上来的直接原因。

**一个重要的负面结论（触发词挖不动）**：
自举会顺带把触发词写回本体，原本期望「LLM 付一次费，规则通道长期免费用」。实测**这条路走不通**：

| 触发词集合 | 规则侧召回 | 规则侧 P1 |
|---|---|---|
| 不用自举触发词（基线） | 7.6% | 7.9% ✅ |
| 自举本体但**清空触发词**（仅留框架） | 7.6% | 7.9% ✅ |
| 自举触发词 min_df=2 | 34.4% | 32.9% ❌ |
| 自举触发词 min_df=10 | 11.9% | 14.5% ⚠️ |
| 自举触发词 min_df=20（仅 3 词） | 10.2% | 7.9% ✅ |

> 「清空触发词」对照组与基线**完全一致** —— 说明**框架本身是中性的**：
> 它只对 L3 覆盖率有贡献，完全不影响规则侧精度；召回与误判全部来自触发词。
> 而触发词的 train→test 泛化很差（召回涨 4.5 倍，误判也涨 4 倍），
> 收紧到 P1 达标时召回只剩 10~12%，性价比很低。
>
> **结论**：自举的价值在**结构（框架/级联 → 覆盖率）**，不在触发词。
> 这与 §6.6 是同一个道理：**词级触发无法消歧，必须靠上下文判断**，
> 而这正是 LLM 通道在做的事。因此自举触发词应与 LLM 校验配对使用；
> 纯规则场景用 `--min-df` 收紧，或直接不启用。

### 6.10 自举本体清洗沉淀（P0 收官：从 cache 产物到生产默认本体）

§6.9 的自举本体（`llm_ontology_train.json`，2185 框架）是 LLM 一次性沉淀的原始产物，
README §8.1 曾标注「需清洗去重后沉淀为生产默认本体」。`ontology_clean.py` 完成清洗与验证：

**验证（缓存重放三变体，`--verify`，零 API 费用）**：discover/refine 全部走

清洗只删框架不改绑定，因此键是原跑缓存的子集——**实测命中率 100%**，对照干净。

| 变体 | 框架 | P1 | 召回 | 精确率 | F1 | P2 覆盖率 |

| V0 原始自举本体 | 2185 | 9.2% | 69.6% | 99.0% | 0.818 | 100% |
| **V1 清洗全量（生产默认）** | 2177 | **9.2%** | **69.6%** | **99.0%** | **0.818** | **100%** |

1. **V1 与 V0 逐指标持平** —— 清洗是指标中性的纯质量提升（删自环/清喻底不改变任何绑定与触发），

**修复 H1 的尝试（已完成，结论是「修不好，不是没修」）**
H1 失效的表面根因是自举框架全是 `GENERIC_VEHICLE`。已做三件事让约束重新获得信息：

1. `ontology.infer_source_type(domain)` —— 按关键词表把源域描述映射到 16 类 `source_type`。
   自举框架的 `GENERIC_VEHICLE` 占比 **98.6% → 32.8%**。
2. 自举框架的 `mapping_type` 改为可区分的 `DISCOVERED::{source_type}_TO_{target}`，
   并在 `build_llm_ontology()` 里登记进 `TYPE_CONSTRAINTS`
   （不登记的话新映射会被 `type_valid` 全判非法，整个自举本体失效）。
3. `extractor._type_coherent()` —— **类型连贯性检查**。模糊匹配是子串匹配，
   可能把候选绑到类型不相干的框架（如"水流"绑到 WAR）；用推断出的 `source_type`
   交叉验证，不一致则拒绑。实测拦下 **24** 个候选，计数器 `extractor._type_rejects`。

**结果：约束确实起作用了（拦下 24 个错误绑定），但 P1 完全不变。**
因为被拒绑的候选会退化成临时框架继续产出超边 —— 约束管的是"挂哪个框架"
（结构正确性），不是"要不要这条边"（精度）。这两件事在本架构里是分开的。

> 这里暴露了**开放发现与封闭类型系统的本质张力**：每接受一个新映射，
> 就必须往 `TYPE_CONSTRAINTS` 里登记一次；登记全部 → 约束又变成恒真。
> 而要让约束影响精度，就必须丢弃候选 —— 那正好抹掉开放发现的全部价值。
> 见 §7.1 结论 1。这类「改了但没用」的结果必须写进论文，否则读者会以为没试过。

### A7 / A9 检索排序质量（MRR@10 / Hits@3 / Hits@10，n=8）

| 配置 | MRR@10 | Hits@3 | Hits@10 |
|---|---|---|---|
| 训练后（7 维，A7 开训练） | 0.906 | 0.875 | 1.000 |
| 训练后 − 去角色特征（A9） | 0.906 | 0.875 | 1.000 |
| 人工加权（A7 关训练） | **1.000** | **1.000** | **1.000** |

**两个负面结论（与 §7.1 的 A1 同属「试过但证伪」类，必须写进论文）**：

1. **A7 → H5 不成立**：训练后排序器 MRR@10 = 0.906，**低于**人工加权的 1.000。
   根因已在 `training.py` 的 docstring 预言——自监督信号里 `clue`（触发词命中）的
   AUC≈1.0（"抽取器本来就是靠触发词命中产出这条边的"），模型退化成**只学 clue**
   （学到的权重 `clue=1.42`，其余 ≈0），自然赢不了已经显式融合 sem/struct/clue/type 的
   启发式。这是**自监督排序器的固有天花板**，不是调参能解的。
   ⇒ 要拿到真正有增益的排序器，须先扩 L1 候选池（接 LLM 后端把召回做到千级），
   或引入 query→相关超边的人工/LLM 标注、或用下游 QA 正确率做弱监督。
2. **A9 → H7 不成立**：去掉 `same_frame/same_cascade/ground_jaccard` 三种角色特征后
   MRR 完全不变（0.906 → 0.906）。角色特征在该语料上取值范围 [0,1]（非恒零），
   但学到的权重极小（same_frame=−0.02、same_cascade=−0.013、ground_jaccard=+0.07），
   对排序无实质贡献。⇒ "角色感知结构信号不可被同质 DDE 替代" 这一主张**暂无证据支持**。

> 诚实边界：上述 A7/A9 为 2 文档 8 查询的小样本诊疗结果，趋势与 `training.py` 自检
> （`leakage_report` / `feature_auc` 会标出 clue 单特征可分）一致，但需在更大检索集上复验。

（Q_ext 扩展链 5 条 + Q_self 基础排序 856 条 + Q_cas 级联 6 条有效）。

| 配置（n=861 查询） | MRR@10 | Hits@3 | Hits@10 |
|---|---|---|---|
| 训练后（7 维） | 0.998 | 1.000 | 1.000 |
| 训练后 − 角色特征（A9） | 0.998 | 1.000 | 1.000 |

**三条复验结论**：
1. **A9 精确复现**：去角色特征 MRR 完全不变（0.998 vs 0.998）——H7 不成立在 40 倍规模上依旧。
2. **A7 双方贴天花板**：训练 0.998 vs 人工 0.995。诊疗集上「训练更差（0.906 vs 1.000）」

3. **A8 仍无差异**：密度 1.071 的图上开/关阈值 Recall@10 完全一致（0.250，n=6 有效级联查询）。

**A7-weak：refine 缓存弱监督迭代（P3「排序器收口」离线部分，`--weak-refine`）**

`build_weak_refine_set` 把 refine 缓存里 **1172 条被 LLM 否决的候选**（同 chunk、
同触发词、但模型判非隐喻）作为训练负样本 —— 它们的 clue 特征与正样本几乎相同，
从机制上攻击「clue 单特征完美可分」的自监督天花板。实测：

| 训练信号 | clue 平均 AUC | leakage 标记 | MRR@10 |
|---|---|---|---|
| 自监督（随机负样本） | ≈1.000 | 136 | 0.998 |
| **LLM 弱监督（refine 否决）** | **0.931** | **23** | 0.998 |

**诚实结论**：弱监督把**训练信号的病理**修好了（clue 不再是完美分离器，
leakage 标记 −83%），排序器终于学到了非平凡的权重；但 **MRR 不动** ——
by-construction 基准本身已饱和（四种配置全在 0.995–0.998），它测不出排序增益。
要证明弱监督排序器的检索价值，必须先有**非构造金标**（人工 query→相关边标注，
或 LLM 判定的查询相关性，或下游 QA 正确率弱监督）——这是排序线唯一剩下的阻塞点。

**两个诚实边界**：① 金标为 by-construction（构造即金标），结论只对排序/阈值组件有效，
② 伪文档为连续 K 句受控分组，非语料原生结构——独立短句语料的稀疏性已由下节连贯文档验证补齐。

曾有两次失败被"优雅降级"吞掉，流程一路报成功，结果却全是错的：

| 静默失败 | 后果 | 防护 |
|---|---|---|

## 7.4 HGNN 检测器（P4，`evaluate_hgnn.py`，离线）

`MetaphorHGNN`（方案 §4.5「超图版 KEG」）原本只实现了一个**跨层消息传递编码器**
（节点→超边→节点两步传播 + 残差，无训练、无分类头）。本轮补齐了**真正的检测器 API**
（`entity_vec` / `edge_repr` / `metaphor_coherence` / `retrieve` / `retrieve_raw`），
并测量其真实贡献。

⚠️ **验收口径不匹配（必须正视）**：§6.1 把 P4 写成「抽取 F1 提升 >5pp」，
但 `MetaphorHGNN` 是**检索 / 语义信号编码器**，不是抽取检测器：
- 它要发挥作用需要**多 chunk 文档**的图结构（跨层传播才有人可传），而 CCL2018 的金标是
  **逐句**的「是否含隐喻」二分类，单句图太稀疏，无法驱动图卷积；
- 且 CCL2018 **没有逐边金标**，无法训练 / 评测逐边检测器。
⇒ 因此 §6.1 的「抽取 F1 +5pp」对当前组件**无法成立也无法测量**。下面测的是它
**真正该测的贡献**——跨层语义信号对「隐喻检索 / 检测」的质量（金标 `eval_corpus.GOLD_RETRIEVAL`）。

| 测量项 | HGNN | 原始嵌入(对照) | 结论 |
|---|---|---|---|
| **P4-A** 跨层检索 MRR@10 | **0.896** | 1.000 | ❌ 跨层传播**无增益**（−0.104） |
| **P4-A** 跨层检索 Hits@3 | 0.875 | 1.000 | ❌ −0.125 |
| **P4-B** 检测器判别准确率 | **0.950** | — | ✅ 真边连贯度 0.669 vs 跨框架负样本 0.197 |

**两个诚实结论：**

1. **P4-A 跨层传播反而损害检索排序。** 传播把实体向量与框架 / 级联节点**求均值**，
   模糊了实体级语义；而检索要的是「查询→具体 chunk」的细粒度相似度，保留实体区分度的
   **原始嵌入反而更准**。⇒ §4.5「传播级联语义→提升检索」的承诺在此语料**不成立**。
   （若要让跨层传播对检索有用，应改成「只把框架语义注入查询侧、保留实体侧」的不对称设计，
   而非对称均值——这是后续可改的方向，但当前实测为负。）

2. **P4-B 检测器信号真实有效。** `metaphor_coherence`（两实体在 H 空间的余弦）把
   **真 L1 隐喻边（均值 0.669）** 与 **跨框架负样本对（0.197）** 干净分开（配对判别 0.95）。
   这是该组件**真正可演示的价值**：一个**独立于触发词与 LLM** 的图结构隐喻连贯度判据，
   可用于给抽取边做「图一致性」二次校验（过滤跨框架串味 / 字面误判）。
   但它仍依赖多 chunk 文档图，无法直接提升逐句抽取 F1。

> 建议论文表述：把 P4 从「抽取 F1 +5pp」改为「HGNN 提供图结构隐喻连贯度信号
> （跨框架判别准确率 0.95），作为触发词 / LLM 之外的第三道校验」，并如实说明
> 跨层对称传播对检索排序无增益。

### 真实句向量重测（`--embedder real`，智谱 embedding-3 @512 维，2026-08-30）

| 测量项 | 哈希向量（原口径） | **真实句向量** | 变化 |
|---|---|---|---|
| P4-A 跨层检索增益 | HGNN 0.896 vs 原始 1.000（**−0.104 ❌**） | HGNN **1.000** vs 原始 0.938（**+0.062 ✅**） | **翻案** |
| P4-B 判别准确率 | 0.950（真 0.669 / 负 0.197） | 0.850（真 0.972 / 负 0.883） | 下降仍可用 |
| H4 flat = HGNN | 0.950 = 0.950 | 0.850 = 0.850 | n 元性结论不变 |

**两个重要修正**：
1. **P4-A 翻案**：跨层传播对检索的损害是**玩具哈希向量的伪影**——真实语义下，
   级联/框架语义注入检索表示反而带来 +0.062 MRR。§4.5 的原始承诺在真实向量下成立。
   论文表述：「跨层传播的收益以语义表示质量为前提」。
2. P4-B 判别力下降的真因：真实向量让**跨框架负样本也语义相近**（0.197→0.883），
   判别任务本身变难；0.850 仍显著高于随机，且 H4 分解结论（n 元性是载体、层级
   非必要、GRU 1.000 复现）在两种表示下一致——结论稳健。

### H4 信号来源分解（改口径实测，`measure_h4`）

原 H4 口径（HGNN→GRU → 抽取 F1 下降>3pp）无法成立，改为更有价值的问题：
**P4-B 的判别信号到底来自结构的哪一层？** 同一组配对样本（真 L1 边 vs 跨框架负样本，
同种子同抽样）上比较四种表示：

| 表示 | 真边连贯度 | 负样本 | 配对判别 |
|---|---|---|---|
| HGNN 完整跨层（L1+框架+级联） | 0.669 | 0.197 | 0.950 |
| **仅 L1 超边**（关跨层，`cross_layer=False`） | 0.683 | 0.194 | **0.950** |
| 原始嵌入（无聚合） | 0.050 | 0.017 | 0.150 |
| GRU 扫 L1 共成员序列（未训练） | 0.770 | 0.145 | **1.000** |

**结论（n=20 配对；GRU 与 HGNN 的差距仅 1 对样本）**：
1. **信号载体 = L1 喻底的 n 元共现，跨层层级零贡献** —— 关掉框架/级联边后判别力完全不变。
   这与 P4-A（跨层传播损害检索）互相印证：**§4.5 的「跨层消息传递」承诺在检索与检测两个
   口径下均不成立**。
2. **结构仍是必要的**：原始嵌入判别 0.150（低于随机）——没有 n 元共现聚合就没有信号。
3. **聚合方式是次要的**：GRU 顺序扫描（1.000）≥ 两步超图传播（0.950）——KEG 式序列编码
   在同等结构信息下不逊于超图卷积。
4. **论文最锋利的表述**：「隐喻连贯度校验信号来自隐喻表征的 **n 元性**（喻底集合共现），
   而非 **层级性**（框架/级联）」——方案的核心创新主张需据此收窄：n 元超边扛住了检验，
   层级结构在检索（P4-A）与检测（H4）两个口径下都未显示增益，其价值应改述为
   **检索组织/可解释性**（U-Retrieval 粗筛），而非信号本身。
5. 方法论注记：文本子串共现基线在此**不适定**（实体是抽象域标签，不以字面出现在原文，
   首轮实现实测全零向量后否决）；GRU 未训练是刻意的——无逐边金标可训正是 P4 口径重定的原因。

## 7.5 LLM 非构造金标 + 改写查询基准（`evaluate_llmgold.py`，需 LLM_API_KEY）

这是排序线的**收官实验**：打破 §7.3 by-construction 基准的饱和，检验此前
「训练排序器无增益」的结论在真实查询下是否成立。

**管线**（全部落盘缓存，重跑零请求；全量 ~200 次请求 ≈ ¥2，deepseek-v4-flash）：
1. **gen 改写生成**：把 861 条自动查询改写成自然问题，**程序化红线**禁止出现
   触发词/源域/目标域 → clue 捷径被切断（违规剔除 26.7%，模型总想偷用触发词）；
2. **judge 相关性判定**：LLM 在每文档全部候选映射上做 listwise 判定 →
   与抽取构造无关的独立金标（构造金标一致性 **96.8%** = 612/632，金标可信）；
3. **eval 三配置三通路**：人工加权 / 自监督 / LLM 弱监督排序器 + 触发词级联、
   字面、语义超图三条检索通路。

> 工程注记：首轮 judge 缓存重放时金标全零——L1 边 id 原为 uuid4 随机生成，
> 跨进程对不上号。已改为 md5 确定性 id（extractor/extended/training 三处），
> 并有回归单测护栏（`TestDeterministicIds`）。

**结果（n=632 改写查询，确定性 id 重跑口径）**：

| 排序配置 | MRR@10 | Hits@3 | Recall@10 |
|---|---|---|---|
| 人工加权（A7 关训练） | 0.502 | 0.604 | 1.000 |
| 自监督训练（7 维） | **0.547** | 0.634 | 1.000 |
| LLM 弱监督训练 | 0.536 | **0.641** | 1.000 |

| 检索通路 | Recall@10 |
|---|---|
| 触发词级联通路 | 0.042 |
| 字面包含通路 | 0.000 |
| **语义超图通路** | **1.000** |

**四条结论**：
1. **H5 部分翻案（重要）**：改写查询下训练排序器**反超**人工加权 +4.5pp MRR
   （0.547 vs 0.502；held-out 复验见下）。
   此前「训练无增益/更差」（§7.1 A7、§7.3）是 **clue 捷径主导的基准产物**——
   基准里查询含金标边触发词时，clue≈1 恒命中，谁训练都一样；捷径移除后，
   排序落到 sem/struct/type，训练学到的非平凡权重才有用武之地。论文对 H5 的
   表述应为条件化的：「增益取决于查询分布——触发词重叠型查询下无增益，
   改写型查询下训练必要」。
2. **H3 脆弱性量化实锤**：改写查询上触发词级联通路 Recall 仅 0.043、字面 0.000，
   语义超图通路 1.000 ——「语义超图检索是唯一稳健的隐喻通路」从 2 文档观察
   升级为 604 查询的测量结论。
3. **弱监督 vs 自监督无定论**（MRR −0.013 / Hits@3 +0.005）：弱监督的价值仍在
   训练集健康度（§7.3 A7-weak），排序收益未证明。
3b. **真实句向量（智谱 embedding-3）**：全部排序器 **+21pp MRR**（人工 0.502→0.707、
   自监督 0.547→**0.758**）、Hits@3 0.604→0.815——sem 特征的真实语义是本基准上
   单项收益最大的迭代；训练增益在真实向量上依然成立（+5.1pp）。命令
   `--embedder real`（`EMBED_API_KEY`，检索层专用、冻结抽取管线，与缓存对照干净）。
4. **诚实边界**：生成与判定同用 deepseek（同源风险已用构造金标一致性 96.8%
   交叉校验）；LLM 金标存在模型偏差，人工小规模抽检仍是投稿前的建议动作。

**迭代实验（npp/向量器/语义回退/联合训练，完整表见《效果对比.md》§6）**：
在 tune/report 文档级切分（防测试集调参）下，最优配置（NgramEmbedder + 语义回退 +
npp=5）在 held-out 报告集（n=314）上把 MRR@10 从人工加权 0.484 提到自监督 0.579
（**+9.5pp**）；级联通路语义回退使其 Recall 翻倍（0.020→0.042）。

**上下文打包消融（`evaluate_packing_ablation.py`，judge 敏感性发现）**：4 变体盲评
（ctrl/当前 50-30-20/轻量/chunk 优先）——glm judge 下当前打包胜出（26.50 vs 对照
21.12，最优率 50%），而此前 deepseek judge 下对照 6:1 胜。**LLM-as-judge 结论对
judge 模型高度敏感**：生成质量主张必须真人评估仲裁，组件级结论（§6.1 检索召回）
不受影响。
